# 对话文件与 R2 存储

阶段 4 第 1 项提供对话文件管理：上传、进度、取消、下载、删除和跨设备列表。文件管理保存 PNG／JPEG／WebP、TXT／Markdown／代码／CSV 和 PDF 原文件。阶段 4 第 2 项另有聊天中的[图片输入](images.md)，可上传、粘贴、预览并交给视觉模型；阶段 4 第 3 项另有[轻量文本文件输入](documents.md)，第 4 项另有 [PDF 文本输入](pdf.md)；[独立附件复制](attachment-copies.md)已实现，包含文件的备份随后接入。

## 使用与部署

打开已经保存到云端的对话，在右上角选择「管理对话文件」。上传进度表示浏览器已发送的字节，100% 后仍需等待云端保存完成；只有「已保存」文件可下载。关闭窗口会继续当前上传，离开对话或退出应用会取消。整个页面关闭或网络中断可能使上传未完成，不能将进度条视作持久化确认。已保存的文件可由同一空间的其他登录设备读取。

本地 `pnpm dev` 使用 Cloudflare 模拟 R2，数据与 DO 一同保存在 `.wrangler/`。端到端测试使用独立临时目录，不访问真实桶。

生产环境需要在目标账户启用 R2，并创建私有 Standard 桶：

```sh
pnpm exec wrangler r2 bucket create everchat-attachments --storage-class Standard
```

`wrangler.jsonc` 的 `ATTACHMENTS` 绑定指向该桶；若更换名字，修改对应的 `bucket_name`。保留私有访问，不开启 `r2.dev` 或公共域名。读写均经过应用密码鉴权，桶凭据不会发送给浏览器。绑定和流式读写方法依据 [R2 Workers API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)。此检查点没有创建远程桶或部署。

不使用文件功能时，可以移除 `r2_buckets` 绑定后部署：普通聊天继续工作，文件入口隐藏，附件登记／读取明确返回未配置错误。已有清理登记保留，待重新绑定后由 Alarm 继续处理，不因缺少桶而丢弃记录或持续空转。

## 持久化与并发

- `Library` DO 保存元数据、长度、SHA-256、上传状态、租约、每日计数和清理队列；R2 保存原文件。没有将二进制或 base64 放入消息事件、快照、对话备份或浏览器本地缓存。
- 客户端先计算 SHA-256 并登记不可变元数据，再通过同源 PUT 发送原始文件。DO 流式转发到 R2，以固定长度流检查实际字节数、有限文件头检查类型，并将 SHA-256 交给 R2 校验。客户端显示高频进度，服务端只保存登记、认领和完成状态。
- 每次登记使用独立随机 R2 键；相同附件 ID 的相同登记幂等，不同元数据或所属对话冲突则拒绝。已完成上传再次 PUT 返回原结果，不再写 R2；未完成或失败的上传不自动重试，需重新选择文件。
- R2 写入完成后，DO 再核对上传认领、文件和对话未被删除，保存 `ready` 后才返回成功。实例在 R2 写入与 DO 确认之间重置时，文件仍不可读；租约到期清理对象与登记，避免把未知结果认作已保存文件。
- GET／HEAD 只读取当前对话的 `ready` 文件，核对 R2 长度和已保存 SHA-256，并在 R2 读取后再次检查删除状态。响应使用 `no-store`、下载文件名和禁止内容嗅探的头；文件不进入 Service Worker 缓存。校验依据 [R2 校验和 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#checksums)。
- 删除先持久化移除标记，立即撤销新的读取和上传，再由 Library Alarm 删除 R2 对象。对话删除也登记全部文件清理；清理信息不会因 Conversation DO 清空数据库而消失。每批最多 4 项，失败 30 秒后重试。
- 未完成登记的租约为 5 分钟，单次上传超时 60 秒。清理每一行时重新检查状态，先关闭登记，再等待 R2 删除；正在当前实例上传的文件暂缓清理。这样不会误删清理等待期间已完成的另一项上传。删除期间容量仍保留，确认对象清理后才释放。

当前类型检查仅用于文件保存：文件头通过不证明图片／PDF 可以解码，文本头没有 NUL 也不证明整个文件为 UTF-8。图片聊天入口会完整解码和缩放，云端检查允许格式、尺寸、长度和校验和；直接文件上传仍仅检查文件头，不证明完整像素可以解码。文本聊天入口会严格验证完整 UTF-8、控制字符、大小和 CSV 行列；PDF 聊天入口在浏览器 Worker 中提取文字，服务端验证原文件哈希、提取文本和元数据并可靠保存，不独立证明客户端的提取语义。

## 原型资源边界

| 维度 | 限制 |
|---|---|
| 单文件 | 1 字节至 5 MiB |
| 每对话 | 最多 64 个文件、32 MiB |
| 每空间 | 最多 512 个文件、512 MiB |
| 上传尝试 | 每空间 UTC 每日最多 100 次，失败不退还 |

容量统计包括未完成、失败和等待删除的登记，配额预留与上传认领通过 SQL 事务完成。每日计数在发起 R2 写入前保存，重置不能绕过；已完成文件的幂等 PUT 不增加计数。文件名、类型、长度、摘要和 ID 都由服务端校验，超限直接返回明确错误。

这些是 EverChat 的应用限制。2026-10-14 核对的 R2 Standard 免费额度为每月 10 GB-month 存储、100 万次 Class A 和 1,000 万次 Class B；R2 互联网传出流量免费。免费额度不适用于 Infrequent Access，账户其他应用的用量仍需一并监控。[R2 官方定价](https://developers.cloudflare.com/r2/pricing/)

上传尝试上限约束写入频率；鉴权下载仍会产生读取操作，DO 的 RPC、Alarm、SQL 和活跃时长也单独计量。本地功能回归不证明真实账户的免费额度、CPU 余量或账单结果。

## 验证

`tests/attachments.test.ts` 检查元数据和允许类型；`tests/e2e/attachments.spec.ts` 使用原生本地 R2、SQLite、DO Alarm 和浏览器，验证 5 MiB 上限文件的精确字节及 Unicode、校验失败、鉴权及跨域拒绝、跨设备读取、幂等上传、过期回收、配额并发、R2 写入后实例重置、清理与上传交错、删除失败后实例重置及定时重试、未配置存储、上传取消、进度、草稿／URL 保留、移动端长列表和焦点恢复。

完整检查点结果记录在 [功能路线图](serverless-feature-roadmap.md) 中。图片、文本与 PDF 检查点另已覆盖接受后的后台任务、私有预览和引用；独立复制的引用与中断清理已接入，后续继续扩展包含文件的备份语义。
