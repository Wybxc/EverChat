# WebKit 流式结束滚动修复

日期：2026-10-18。

## 原因与对照

长回答生成期间，主对话区和嵌套思考区可以正常跟随底部；结束时，两个视口的 `scrollTop` 变为 0。原先测试中主视口距底部 2,422 px，使用改造前组件同样失败。

结束时 `MarkdownContent` 将 Streamdown 2.7.0 的 `mode` 从 `streaming` 改为 `static`。检查本地依赖实现确认：前者以多个带键的 Block 渲染，后者以单个完整 Markdown 解析树渲染，切换会替换内容节点。仅在对照实验中取消这次模式切换，同一 WebKit 滚动测试即通过；实验改动随后撤销。

WebKit 在这次内容替换时重置祖先视口的滚动位置。`useFollowScroll` 观察到位置减小，将其视为用户向上阅读并停止跟随；即使最终内容高度没有变化，也无法再靠 ResizeObserver 恢复。这是渲染切换与自动跟随交互的问题，不涉及流数据、存储或网络请求。

## 修复

在现有 Markdown 渲染边界内处理 `streaming: true → false`：通过 `getSnapshotBeforeUpdate` 在 React 修改 DOM 前记录非零的祖先滚动位置，`componentDidUpdate` 在同一次提交内恢复仍连接到文档的节点。恢复前读取实际位置，仅在位置发生变化时写入，避免无变化的程序滚动。正文与嵌套思考区均覆盖，在浏览器绘制和后续滚动事件前完成恢复。

保留完整静态 Markdown 渲染。跟随状态与用户向上阅读状态沿用原滚动逻辑；没有添加逐 Token 布局读取、定时轮询、无条件跳到底部或服务端处理。完成、失败和取消导致的渲染切换共用同一路径。

## 验证

- 原先失败的 WebKit 用例通过，并增加生成结束后思考区仍在底部的断言。新增完成／取消回归：生成中向上阅读正文和思考，继续收到内容后保持位置，结束后仍保持相同位置。
- 最终 WebKit 7 项集成回归通过，覆盖上述三个滚动场景、流式公式、四按钮导航、搜索／版本锚点及思考与工具切换。
- Chromium 覆盖三个滚动场景、三项公式测试、三项阅读导航以及四种模型协议的思考与工具展示。补测后恢复逻辑改为先读取实际位置并跳过无变化写入；最终完成时保持阅读位置连续两次通过，底部跟随和取消也分别复测通过。
- 386 项单元测试、类型检查和生产构建通过。

发布沿用 `main` 的 Workers Builds，以构建成功和生产只读检查核对部署，不以推送成功替代部署成功。
