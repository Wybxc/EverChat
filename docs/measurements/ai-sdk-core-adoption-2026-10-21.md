# AI SDK Core 深度集成与 UI 采用范围验证

日期：2026-10-21。对应[深度集成计划](../plans/ai-sdk-core-ui-adoption-plan.md)。状态：Core 与工具容错已接入；用户已确认 UI 选择性采用，撤销全量状态迁移，未部署。平台资源与发布验收仍单独记录。

## 调用边界

安装并精确锁定 `ai@7.0.145`；试接入使用过的 `@ai-sdk/react@4.0.149` 已在范围调整后移除。现有 Provider V4 适配器继续负责四种原生协议。普通回答、摘要与工具模型轮次经统一 Core 流入口；标题与能力探测改用 `generateText`。不提供自动执行的工具 `execute`，不启用 Core 多步循环、请求重试或流内重试。

流入口使用公开的 `experimental_streamTextLowMemory`，它与 `streamText` 共用引擎，只有一个消费者，不保留可供再次读取的完整流。该版本在声明 tools／toolChoice 时仍收集本轮内容，不能宣称工具场景完全没有 Core 聚合开销。没有使用 `_internal` 配置、SDK 内部导入或另一个原始响应 tee；升级此实验 API 必须重做资源与协议验证。

公开 `wrapLanguageModel` 中间件观察同一条原生流。私有 collector 保留原生调用身份、完整结束证明和协议续接资料：Anthropic 分片签名拼接、redacted 内容、Responses 加密资料及全文／摘要处理、Gemini thought signature。Core 负责参数 JSON 与 Schema 解析；DO 保存候选与结果后由 Workflow 推进下一轮。

标题删除了旧 ProviderStream 的字节解码消费，继续保留请求前记账、独立预算、版本竞争和不确定执行后禁止自动重发。辅助响应读取共享有界读取器；标题 256 KiB、探测 64 KiB，均支持取消。探测要求工具而模型只返回文字时，Core 的 `ToolChoiceViolationError` 归为能力不匹配，计费用量仍通过调用结束回调保存。

非官方 Responses 的 `store:false` 请求补充由单一 helper 供流、标题和探测复用。关闭 SDK 全局原始 warning 日志；普通生成仍保留 EverChat 有界、脱敏的公共诊断。

## 工具行为

- 公开网页／引用目标允许 HTTP、HTTPS 与 8192 字符 URL；带密钥的联网服务端点继续固定 HTTPS，禁止自动跟随重定向。保留凭据、本地／内网、非网页协议、自定义端口等目标策略。
- 搜索逐条处理来源，缺少标题时使用域名，无效条目单独过滤，保留有效条目和有界警告。真实空结果可以成功，非空但全部不可用明确失败；根结构损坏、超限和凭据泄漏仍失败。
- DeepSeek 查询在 Core 校验与执行边界均按 128 个 Unicode 字符限制。模型 JSON Schema 与含自定义 Unicode 校验的运行时 Valibot Schema 分开配置；不能把不可转换的 `v.check` 直接交给 JSON Schema 转换。
- 无效 JSON／参数、未知工具在身份明确且原生流完整时形成不可执行候选，保存对应失败结果。合法兄弟调用继续，失败调用不会发出网络请求或占用服务额度。SDK 不伪造被原生身份检查拒绝的调用。
- 单工具 15 秒期限是局部失败；调用者取消、全局期限和存储失败仍停止任务。认证／余额／服务额度失败禁止后续服务请求，模型可以根据已有资料收尾。连续同一失败指纹且没有有效来源进展时关闭工具，没有新增固定轮数上限。
- 仍保留 SSE／异常 EOF、重复／缺失调用身份、finish 后内容、私有资料缺失等完整性边界；不会以“容错”修补截断参数或执行不完整调用。

## 已撤销的 UI 全量迁移试验

本节保留试验结论。下述 UI 契约、校验、存储与重放代码均在用户确认新范围后删除，未进入生产 schema；不再作为后续待实施项。

新增 `shared/conversation/ui-message.ts` 和 `ui-validation.ts`：定义 `UIMessage<PublicMessageMetadata, EverChatDataParts, EverChatTools>`，让 SDK 验证标准 parts；EverChat 约束公开字段、附件引用、单轮工具数量、调用／结果身份和正文／思考合计容量。工具执行失败、参数失败和取消各保留状态；部分参数不作为持久内容。拒绝 provider metadata、私有续接字段、原始附件 URL、系统消息和未注册的 data part。附件 Schema 验证只证明引用形状正确，不能替代服务端授权或验证客户端上传历史的真实性。

当前 `ai@7.0.145` 使用的 Standard Schema 适配以 `value in result` 判断成功，而安装的 Valibot 1.5.0 失败结果可能同时含 `value` 和 `issues`。本地复现中，未知 metadata 字段被剥离后作为有效结果返回。新增适配通过公开 `jsonSchema({}, { validate })` 直接检查 `v.safeParse(...).success`；这里的 Schema 只供 UI 验证，不发给模型。最终错误不携带 SDK 拒绝输入的原始对象。测试覆盖未知 metadata、无效计数、无效附件字段和私有 provider metadata，不能直接换成未验证的 Standard Schema 路径。

新增 `worker/conversation/ui-content.ts`：`message_parts` 保存按序描述、工具结果和附件引用；text／reasoning 的全文只在 `message_text_chunks` 中分块保存。追加只写受影响的尾部，更新工具结果不重写正文；MCP 分页按频道聚合多个有序 part，保留 UTF-16 游标和完整字符。读取会拒绝缺块、孤立文本和重复全文表示。SDK 准备／验证位于同步写入之前，事务仍由拥有消息的 DO 控制。

SDK 的内存应用上限由最初证明中的 64 KiB 调整为 128 KiB：既有 64 KiB 工具输入加上 `tool-input-error` 外壳会略超 64 KiB，不能因此让原本合法的错误记录无法恢复。wire 微批次、提交节奏和业务输入上限未改变。新增边界测试验证完整容量的错误输入能经过 SDK、公开验证与语义重放，超出输入上限仍拒绝。

13 项针对性测试及全套 **521 项单元测试**、构建通过；包括真实 SQLite 写入／回滚后恢复 SDK 的 text／reasoning 活动 ID 并精确追加。新表尚未加入生产 schema，生产仍使用原有消息／wire 格式。以上是阶段 3 的模块实现与本地证据，尚未证明原生四协议到新存储的全链路、前端 Transport、离线旧数据转换或新格式平台资源表现。

## 范围调整与最终边界

用户确认 Core 深度集成、UI 选择性采用。删除试验的 `AbstractChat` 状态引擎、批次确认、活动块重放、新 SDK Chunk wire、有序内容表、整消息投影／验证和专用测试，移除 React SDK。正文／思考直接 type import SDK 公开字段，业务校验继续验证真实的 EverChat 数据，不为调用 validator 先转换一份 UIMessage。

试验暴露了 Responses 摘要被全文替换时与 SDK 追加语义的差异，以及中途检查点不能保存半次 reset／重放的问题。可通过额外适配解决，但这正是放弃全面接管的成本依据，不在生产留下未使用的解决方案。

保留异步背压、事务前 prepare／事务内 apply、回滚重建；它们已有生产恢复回归和相同负载计数证据。生产 SQL／wire／浏览器缓存格式不变，无需数据迁移，不新增在线兼容路径。

后续仍须完成当前范围的最终回归、Cloudflare 平台资源与发布验证，不再要求 Chat/useChat、Transport 或 UI 格式离线迁移。平台实测没有完成的项目不记为通过。
