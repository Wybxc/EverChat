# 文件输入回执有界读取验证

日期：2026-10-25。实现分支 `codex/mcp-discussion-improvements`，尚未发布。

生成加载已验证的文档时，在私有 R2 保存确切的 `documentPrompt` 逻辑输入。每附件及输入哈希复用一份快照；选区或文件名等输入变化产生新快照，普通轮次不重复写全文。SQL 仅存对象索引、SHA-256、长度及 ETag。它证明应用实际组装的文件资料，不证明供应商完整接收或模型理解。

`everchat_run_context_get` 的文档 text 视图按 UTF-8 字节分页，单次最多读取 8,196 字节并返回至完整字符边界；游标仍不透明。按 ETag 读取，来源删除、对象被替换或缺失时返回不可用；不在查询中重 hash、计 Token、重建快照或写 SQL。

快照对象键先登记再写入，附件删除按小批次回收，活动写入期间不抢删。显式复制／ZIP 恢复重映射回执中的附件 ID，并从固定文件及选区重建后核对原输入指纹；这只发生在用户发起的复制／导入中，不用于历史在线回填。新索引表纳入 schema 4 的离线升级与运维传输。

验证结果：

- 全量单测 532 项通过，含重启后读取、Unicode、精确重建、重复版本只写一次、跨对话拒绝、删除和 ETag 替换检测。
- 四协议文件调用及复制、文件重试／版本／摘要共 5 项本地浏览器回归通过。
- PDF 全文选区及超 RPC 大小的原文、复制和 ZIP 恢复共 2 项通过；新增断言核对文档回执的输入指纹以及复制／恢复后的附件 ID。

资源边界：每个不同文件／选区多一份 JSON 转义后的逻辑文本对象；相同输入只增加一次 Class A 写入，读取每页一个 Class B Range GET。首次写入包含额外序列化和哈希，后续复用仍计算输入指纹。原文件、提取全文和快照分别占用存储。尚未获得 Cloudflare Free CPU／内存实测，不能宣称该成本可忽略或已满足免费层要求。

本批只补齐已保存文档的回执；MCP 上传、逻辑文件版本的沿用／替换／并列和受控讨论仍待完成。
