# 更新后空白页排查

日期：2026-10-20，时间均为北京时间。

## 结论与证据

本次可复现的空白页由前端状态同步循环造成。

- 14:15 起检查正式站点：首页、入口 JS、CSS 和私有页面模块返回 200，内容类型正确。GitHub 的 Workers Builds 检查为成功。
- 内置浏览器打开首页后，先出现身份确认界面，随后空白；控制台记录 React #185（Maximum update depth exceeded）。堆栈依次经过 `Autosave.emit`、`Autosave.receive` 和 `ConversationSettingsDialog` 的参数接收 effect。
- 本地登录后，仅放入带废弃 `useSummaries` 字段的新对话缓存即可复现相同堆栈，不依赖 Cloudflare Zero Trust 或真实模型请求。
- 匿名 `/api/session` 会跳转到 Access 登录，这符合私有 API 的访问控制规则。到达对话参数组件说明浏览器已取得通过认证的会话。

Cloudflare 同日确有 [Zero Trust connectivity 事故](https://www.cloudflarestatus.com/incidents/0eqtn0khkz87)：11:20 开始，13:46 公告称登录边缘功能已恢复，14:14 公告称 Access API 已恢复并继续观察。因此早前的连接异常可能受它影响，但不能用这次外部事故解释本地也能复现的 React 崩溃。状态会变化，此处记录的是排查当时的公告。

## 触发过程

参数读取函数只在内存中投影当前字段，保留原始存储。输入包含废弃字段时，投影会产生新对象。

对话参数组件此前分别在自动保存初始化和接收 effect 中投影同一输入，得到对象 A 和 B。接收 B 的同时，另一个 effect 向父组件回传 A；随后父组件传回 A，自动保存组件再把 B 回传。两份引用不断交替，触发 React 的无限更新保护，卸载整棵界面。

现有单元测试验证了投影结果可复用，但没有覆盖 React 中两次独立投影和父子回传的组合。干净浏览器、当前格式的测试数据也不会触发它。

## 修复

- 对同一 `initial` 只计算一次投影，初始化和接收 effect 共用同一引用。
- 自动保存接收已经保存的同一设置引用时保持快照不变，不再次通知订阅者。
- 不清空缓存，不改写旧记录，不增加在线迁移，不修改 Access 策略。

这里修复的是通用状态同步，不新增旧版本判断、旧字段补齐或自动清理。废弃字段仍由现有 `scripts/operations/migrations.ts` 在维护窗口的本地 `convert` 中清理；页面上的既有读取逻辑不承担存储升级。后续若需移除这段既有读取投影，应先覆盖服务端数据库和每个浏览器／PWA 的本机设置缓存，再删去它，不能把清理重新接到页面启动中。

## 验证

- 修复前：新增浏览器回归测试复现 Maximum update depth exceeded，页面空白。
- 修复后：466 项单元测试通过；7 项会话参数和 Access 浏览器测试通过。覆盖旧缓存无写回、编辑、跨设备同步、未保存草稿、离线参数及登录恢复。
- `pnpm build` 通过，包含全项目类型检查、正式前后端和 SW 构建。
- 4 项正式 PWA 更新测试通过，覆盖 Chromium、WebKit，检查旧参数、更新前后草稿及多窗口未保存设置保护。

## 已受影响的 PWA

旧版本已经空白时，设置内的更新入口也无法使用。新版本发布后，可以先重新加载一次以下载更新，然后关闭所有 EverChat 窗口／标签并重新打开，让等待中的 SW 激活。无需清除网站数据或重新安装；这样会保留本机草稿与记录。
