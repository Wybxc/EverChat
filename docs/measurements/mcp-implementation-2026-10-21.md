# MCP 实施与验收（2026-10-21）

实现分支为 `codex/mcp-server`，基于已合并 Base UI 的 main。目标是统一自动化聊天：通过可撤销 Bearer API Key 调用已配置模型，每次保存为正常对话，不增加临时模式或模型 JSON Schema 输出。

## 已实现

- 官方 TypeScript SDK v2 的无状态 Streamable HTTP handler，支持现代及 legacy 协议协商，不新增 MCP 会话 DO。
- 四个核心工具：模型发现、创建／明确续聊、有限等待及结果查询、取消。使用现有 Conversation 后台执行、供应商适配、费用与搜索流程。
- Library 按密钥隔离的请求幂等索引。先查询原请求，再读取当前模型设置；接收时冻结设置，接受后清除暂存提示词／凭据副本，答案仍只存于普通消息与内容分块。
- 长正文和思考独立完整分页，默认每页最多 8,192 UTF-16 单元；默认不返回思考。客户端等待中止不会取消已经接受的后台生成。
- 「设置 → MCP」管理页：桌面表格、手机紧凑列表，显示名称／脱敏 Key／创建日期／最近使用；无 Tracking ID。创建和重命名使用弹窗，删除需要确认。密钥仅创建时显示一次，不进入查询缓存或本地持久存储。
- 每个请求验证密钥，结束等待后再次确认未被撤销。重命名不换密钥；删除后拒绝后续请求。最近使用时间最多每小时持久化一次。
- `/mcp` 使用 Worker 路由，协议结果禁止缓存；网页密钥管理仍走 Access 和原有同源写保护。

## 发布边界

当前未发布生产。Conversation／Library 版本从 2 升至 3，需要先完成[离线维护](../operations/offline-storage-migration.md#mcp-存储版本-3)，再部署业务构建。不能将此分支直接部署到仍为版本 2 的数据库。

已验证的是本地协议、业务与浏览器行为；真实 Cloudflare Workers Free 的 CPU／活跃时长、线上 Access 路径及真实供应商调用尚未单独测量。现有每次工具请求会消耗 Worker 与有限次数 DO RPC；等待采用 1／2／4 秒退避，DO 不持有等待请求，也不轮询全文。

附件输入、显式 messages 历史、工作区管理、标准 Tasks 与 OAuth 只保留为后续扩展，未当作本轮已交付能力。
