# 空闲同步修复与本地复测

日期：2026-11-01。状态：本地实施与验证完成；未迁移生产、未发布，平台资源验收待执行。

对应[修复计划](../plans/durable-object-idle-read-plan.md)。修复前的生产聚合和实验保留在[原记录](sync-idle-reads-2026-11-01.md)，不覆盖原始报告。本轮没有新建 Cloudflare 测试资源、访问生产数据或调用真实模型。

## 实际变更

Library 的十秒完整列表轮询已移除。现有通知连接发送当前 epoch／revision 和低频变更通知，客户端只在水位落后时合并获取列表；重连水位相同则沿用缓存。列表、活动、水位和删除游标作为同一缓存值保存；翻阅后续删除页不再重读列表。

修订号通过七张列表业务表的 trigger 原子更新。标题任务、活动状态、置顶、复制／导入和删除路径均覆盖；重复报告、无变化更新和 lease 续期不推动水位。广播不枚举通知设备数据库，也不随供应商 Token 发送。

Conversation 新增 `messages_pending` 部分索引，恢复查询不再扫描终态历史。前端仅发自动 ping／pong 心跳，不再定时请求数据库状态。可靠 epoch／seq 缓存优先同步增量，首次加载、基线失效或协议缺口才拉全文。

两类连接保留最多五分钟的重新鉴权，到期不能继续收业务数据；后台／断网暂停主动连接，恢复时核对水位。连续失败抖动退避至五分钟，仅收到 ready 不重置失败计数。通知焦点抑制和后台推送继续生效；恢复焦点不重复写已同步的设备设置。

数据库 schema 6 → 7 完全离线转换。备份包含新状态、trigger、活动、标题和预留记录。离线回滚在首次写回前保存新的同步 epoch，断点重试沿用同一补丁和核验目标，原始备份不改写。没有加入在线旧库转换或回填。

## 空闲预算模型的边界

三客户端各保留一个有可靠缓存的终态对话，24 小时每五分钟重验，共 864 个“客户端续期轮次”。不计业务变更、首次加载和异常重连：

- 若同轮的两次 Library 调用共享一次冷构造，按每轮 `116 + 91 + 1 + 3 + 1 = 212` 行计算，约 **183,168 行／日**。
- 若每次 Library 调用均独立冷构造，按 `116 × 2 + 91 + 1 + 3 + 1 = 328` 行计算，约 **283,392 行／日**。

这是合成 SQL 路径模型，两项都不是平台测量或严格上界。不能据较低值宣称计划中 25 万行／日目标已通过；实际休眠、额外请求、KV 读取、初次完整快照和活跃业务另计，CPU 也未由此验收。上线后仍需获授权窗口的同负载平台采样。
