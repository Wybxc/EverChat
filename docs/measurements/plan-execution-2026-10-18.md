## 存储与资源测量

改造前合成 7 个回答版本、约 336 KiB 净文本，就产生约 15.4 MB 事件负载和 18.4 MB SQLite 分配，足以触发旧 16 MiB 准入保护。10 个版本时 SQLite 约 24.9 MB。修复后同类 80,000 个 SSE 帧／10 版本回归，完整规范内容保留，SQLite 小于 2 MiB，公开原始日志、通知历史及终态解析检查点均不存在。

[原生本地工具链测量](storage-state-tools-local.json)使用 120 块、每块 200 码元、25ms 间隔和在线订阅，运行完整模型→搜索／读取→模型流程：

| 指标                         |         结果 |
| ---------------------------- | -----------: |
| 模型／工具请求               |         2／2 |
| Conversation／Library 行写入 |      191／32 |
| 持久化通知行读写／负载       |    0／0 字节 |
| 终态 SQLite 分配             | 311,296 字节 |
| 规范正文                     |  24,329 字节 |
| 终态解析检查点／私有流       |    0／0 字节 |
| 幂等记录                     |     380 字节 |

该测量使用本地 workerd 和模拟供应商，不是生产 CPU／GB-s／账单结果。WebSocket 的帧和字节只统计在线通道，不包含建立基线的 HTTP 传输；不能直接与旧的“WebSocket 带全量快照”测量比较恢复流量。Cloudflare 免费额度仍按整个账户计算。

## 保留边界

原生本地运行时不支持本次探测的 SQLite 页统计，`reusableBytes` 为 `null`，容量保护回退到分配字节。删除日志不等同于物理文件压缩；16–28 MiB 旧对象可继续，仍超过新准入线的旧对象可使用已有复制／备份恢复。自动迁移对象并保持旧 URL、所有隐藏分支长期懒加载、账户级剩余空间聚合均未在本轮引入，消息数与单条正文等边界因此保留。

DeepSeek 的真实密钥权限、可用性、计费和网络耗时未实测；只验证官方接口格式和模拟端到端行为。竞品私有界面访问仍待用户授权，不影响本次沿用现有风格的设计整改。新协议发布后旧已打开页面可能需要更新／刷新；不维护旧通知回放协议。

发布采用 `main` 的 Cloudflare 自动构建，具体提交和构建状态以 Git／Workers Builds 为准，不能把推送成功写成生产验收通过。
