# 回答续写验收记录

日期：2026-10-31。分支：`codex/answer-continuation`。

## 本地结果

- 全量单元测试：559 项通过；包括 12 项续写专用测试。
- 本地 workerd 运维通道集成测试：1 项通过。
- 最终针对性 Chromium 集成复测：12 项通过，覆盖页面续写、旧分支隔离、迟到响应、空输出失败、取消后部分输出、自动压缩、四种协议的联网工具续写，以及四协议 MCP 续写。
- WebKit：2 项续写场景和 1 项滚动场景通过。
- 生产构建 PWA：5 项通过，覆盖 Chromium／WebKit 的跨版本更新、草稿保护，以及 Chromium 的离线对话 URL 恢复。
- 类型检查、生产构建及差异空白检查通过。

最初的广泛浏览器回归为 44／49 项通过；3 项旧断言未考虑已有的上下文来源元数据，另 2 项需要排除测试期间开发热更新的影响。更新断言、停止源码编辑后，上述 5 项全部纳入最终 12 项复测并通过。没有将初次失败记为通过。

## 关键证据

续写请求包含原问题、来源回答全文和字面消息「继续」；下一次普通提问只包含一条拼接后的 assistant 消息。原回答和旧后续分支不变；删除来源版本后，存活续写版本、MCP 输入回执、分享和复制仍能读取完整正文。

单元测试创建 12 次连续长文本续写，验证每段正文只保存一次；读取靠后位置的 128 字符页最多使用 4 次 SQL 查询。该结果证明本地存储和查询形态，不能当作 Cloudflare CPU、延迟或免费层容量测量。

独立执行的用量只入账一次；显示组成版本的累计用量时按执行 ID 去重，未知 token 不变成零。备份／复制带有自包含正文、分段来源，以及必需的来源输入快照；线上存储只保留不可变前缀引用和本次增量。
