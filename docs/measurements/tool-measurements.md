# 有限工具任务资源测量

2026-10-15，在 `e9a174c` 后的工具测量与终态清理检查点运行。默认七场景报告见 [tools-baseline.json](tools-baseline.json)。这是本地原生 Cloudflare 运行时的应用计数，平台 CPU、活跃时长和 Workflow 引擎存储仍需另测。

## 复现

```sh
pnpm measure:tools
pnpm measure:tools --scenario online-openai-responses --size 750 --output /tmp/everchat-tools-large.json
pnpm measure:tools --scenario online-openai-responses --interval 500 --output /tmp/everchat-tools-sustained.json
```

默认监听 5185，使用新建临时数据库、模拟模型 HTTP 响应和生产 Tavily 适配器的模拟 HTTP 响应；结束时停止自己的服务器并删除临时状态。登录前校验本次运行时身份，端口属于其他实例时拒绝登录和修改配置。默认本地密码为 `everchat-local`，可通过 `EVERCHAT_TEST_PASSWORD` 覆盖。配置、正文、密钥及私有续接内容不进入报告。

默认最终回答为 120 个增量、每段 200 个 UTF-16 码元、间隔 25ms，共 24,000 码元。两次工具响应各等待 1.5 秒。`--chunks` 为 1–200，`--size` 为 4–750，二者乘积最多 90,000；`--interval` 为 1–500ms，`--port` 可换端口。`--scenario` 可单独选择报告中的场景。单次模拟模型响应的真实事件数、协议完整事件和 EOF 都保留，因此不同协议并非完全相同的原始字节负载。

四种协议均经过生产请求构造、公开流转换、私有日志和 AI SDK 续接解析；没有改用测试专用工具执行器。正常场景调用搜索和网页读取，轮次上限场景重复调用至已有上限，拒绝场景模拟 HTTP 401。每个场景重复提交同一请求 ID，确认模型和服务尝试数不增加；在线场景逐帧回放并比较最终数据库快照，断开场景在首个预览后关闭唯一订阅。

## 窗口和指标

先完成登录、配置、对话初始化和搜索回填，再开启 Conversation 与 Library 计数。窗口包含订阅建立、消息接受、重复接受、模型轮次之间的操作、Alarm、额度认领、索引更新和一次最终快照读取。结束时要求任务和 Workflow 都终止、私有日志／续接／运行配置归零、搜索 outbox／通知归零，以及两个 DO 都没有待触发 Alarm；随后再观察 300ms。对象实例变化、计数丢失或 Workflow 缓存回放导致回调计数不完整，都会使运行失败，不输出完整基线。

| 指标 | 口径 |
|---|---|
| `report.sql` | 原生 SQLite 游标的实际行计数；随 `one()`、`toArray()` 和迭代消耗采样，不提前读完游标。包含窗口中的业务 API、Alarm 和索引操作；排除 fixture SQL、旧生成诊断表和本测量接口的观察查询 |
| SQL 分组 | 按语句中的表名优先归入私有流、公开流、事件、联网设置／额度、工具状态、搜索及其他。每条语句只归入一组；不是逐表的计费拆分，失败事务内的操作也不能据此推断账单 |
| `streams` | 两种日志实际 INSERT 次数、原始 wire 字节及批次 JSON 字节；JSON 包含 base64 和元数据。脚本检查私有 wire 字节总量等于实际收到的模型字节 |
| `upstream` | 实际模型流及工具 HTTP 尝试数、收到的模型字节和模拟工具响应字节。HTTP 401 的尝试也计入；不是模型 Tokens 或服务 credits |
| `eventPayloadBytes` | 窗口内写入公共事件的 JSON UTF-8 总量，包含多次公开状态快照 |
| `broadcasts` | 经 `getWebSockets()` 成功排入发送队列的帧及字节，按收件端累计；不含首次同步的直接发送、心跳及传输开销。客户端另计实际收到的帧和字节 |
| `alarms` | `setAlarm`／`deleteAlarm` 方法调用数，不是计费请求数 |
| Workflow `steps`／`waits` | 真正执行的步骤名、回调尝试／失败数及序列化结果字节；事件等待单列。只测引用与状态，不测引擎的内部 SQL、索引或保存开销 |
| `databaseBytes` | 结束时 SQLite 分配大小，包含 schema、索引和 fixture 表；Library 在七场景之间保留已完成数据。不是单次消息净占用或账户计费存储 |
| `elapsedMs` | 从启用计数到读取报告的经过时间，含网络／调度／观察等待；不是 CPU 或 DO 活跃 GB-s |

构造 schema、配置写入及初始回填不在窗口中。平台 RPC、Worker／DO 请求计费、Workflow 引擎内部存储和其他应用共享额度不由这些计数覆盖。计数自身也有代理和字节统计开销，不能拿开启计数时的 CPU 代表产品 CPU。[普通聊天报告](stream-measurements.md)从认领开始，窗口不同，不能直接用两份写入数字相除声称放大倍数。

一分钟负载首次运行时，回答已完成，但 Library 在最后一轮模型期间自然休眠，内存计数丢失，脚本拒绝了不完整报告。本地计量现每秒只读观察 Library，保持计数窗口可观察；这些诊断查询不计业务 SQL。这会影响对象驻留，**本地基线不测自然休眠或活跃 GB-s**。真实平台验证必须关闭此诊断入口和计数，不沿用这种观察频率。

## 默认负载结果

SQL 写入均为原生游标行数，两对象分开。Workflow 步骤不包含事件等待。

| 场景 | 模型／工具尝试 | Conversation 写入 | Library 写入 | Workflow 步骤／等待 | 私有／公开 wire 字节 |
|---|---:|---:|---:|---:|---:|
| OpenAI Chat 在线 | 2／2 | 156 | 26 | 6／2 | 31,949／31,521 |
| OpenAI Responses 在线 | 2／2 | 160 | 26 | 6／2 | 113,514／31,439 |
| Anthropic 在线 | 2／2 | 156 | 26 | 6／2 | 36,869／31,427 |
| Gemini 在线 | 2／2 | 155 | 22 | 6／2 | 34,971／31,374 |
| OpenAI Chat 断开唯一订阅 | 2／2 | 156 | 26 | 6／2 | 31,949／31,521 |
| 服务 HTTP 401 | 1／1 | 97 | 23 | 3／1 | 839／353 |
| 轮次上限 | 4／6 | 289 | 38 | 14／4 | 3,207／1,184 |

七场景全部通过终态和清理检查。正常往返的步骤结果合计 408 字节、两次事件结果合计 254 字节；轮次上限分别为 1,005／508 字节。这支持“Workflow 只保存小引用与状态”的实现判断，不代表引擎总存储。Responses 模拟协议包含最终完整正文事件，私有流明显大于公开流，真实平台 CPU 验证应覆盖这种路径。

补充负载也已在本地完成：

| Responses 负载 | Conversation／Library 写入行 | 私有／公开 wire 字节 | 报告 |
|---|---:|---:|---|
| 120 段 × 750 码元，90,000 码元 | 174／26 | 377,514／97,439 | [大正文](tools-large.json) |
| 120 段 × 200 码元，500ms 间隔 | 446／26 | 113,514／31,439 | [一分钟以上](tools-sustained.json) |

两种负载均检查完整正文、相同调用上限、私有清理及无待处理 Alarm。短窗口的默认报告和大正文报告在增加每秒 Library 观察前取得，未发生计数丢失；一分钟报告使用上述诊断观察，不能用于休眠结论。同样大小的短流与长流，其持久化次数会随 1.5 秒保存窗口变化，不能仅按输出字节估算写入压力。

测量发现服务拒绝后的消息和 Workflow 已结束，但终态通知仍等待旧根任务 Alarm。新增 HTTP 401 回归在未修复代码上因残留一条通知失败；修复工具 RPC 的失败出口，在完成消息后重新安排 Alarm。HTTP 401／429 回归现要求通知自动清空，不人工触发 Alarm。默认七场景、四协议小负载七场景、运行时身份校验小负载及自建端口冲突检查均通过；端口冲突检查确认未发送登录或配置请求。另有 283 项单元测试、30 项工具 Workflow／服务原生回归、类型检查及生产构建通过。

## 下一次平台验证负载

先准备独立 API-only 验证 Worker、两个新 SQLite namespace 和单独 Workflow 名称；使用随机本地验证 Secrets，保持外部供应商网络禁用。复用[平台隔离入口](../../scripts/measurements/support/stream-worker.ts)，不能把本脚本直接指向现有实例，也不操作真实聊天配置。模拟负载 `LOCAL_TOOL_WORKLOAD` 已与计数开关分离；平台 CPU 测量必须关闭 `LOCAL_RESOURCE_METRICS` 和 `GENERATION_METRICS`。

1. 四协议各一次默认往返，核对终态、调用数、私有清理和完整公开结果。
2. Responses 的 90,000 码元负载，以及每段 500ms、持续一分钟以上的负载，分别检查原始流大小与长时间活跃开销。
3. 客户端在首个预览后断开，再在终态重连，确认不增加模型／工具尝试；另测两个并发任务共享额度。
4. 四模型／六工具的轮次上限、服务拒绝及取消，确认失败和停止后不启动新步骤，通知和 Alarm 清空。
5. 分别收集 Worker CPU、DO CPU／活跃时长、SQL 行、请求及 Workflow 资源统计；记录时间窗、版本、诊断开关和采样缺失。结束后删除验证 Worker、Workflow 和 namespaces，保存清理结果。

平台入口还需提供关闭计数时的只读终态核对，不能用会触发过期处理的 `tool-runtime` 观察接口替代自然清理。平台轮询频率须单列，避免把本地计量的诊断保活带入资源结论。

上述隔离入口、只读观察接口和执行脚本现已完成，详见[平台验证说明](tool-platform-validation.md)。关闭计数的同一 API-only 入口在本地通过九项功能、90,000 码元和 77.5 秒长流；没有在生成期间轮询 Library。随后在 Workers Free 完成 11 项平台场景，保存真实 Worker／DO／Workflow 样本并清理全部临时资源，见[平台实测](tools-cloudflare-measurements.md)。本地报告仍不作为 CPU 证据；真实供应商质量、长期共享额度、CPU 高样本及 SQL 存储采样缺失继续单列。[实施核对](../architecture/implementation-audit.md)据实际证据推进最终审查。
