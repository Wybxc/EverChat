# 文本文件输入

阶段 4 第 3 项。聊天框的「添加文件」支持 TXT、Markdown、代码和 CSV；第 4 项的 [PDF 文本输入](pdf.md)使用同一预览、引用和预算。可以只发送文件，也可以和文字、图片一起发送；文本资料无需视觉模型，图片仍要求模型支持视觉。

## 解析与预览

只接受 UTF-8（可含 BOM），保留原始换行和代码。单文件不超过 128 KiB、解析后不超过 64,000 个 UTF-16 码元；空白文件、非法 UTF-8、二进制控制字符及超限文件明确拒绝，不静默截断。代码扩展名沿用文件管理的 JS／TS／Python／Rust／Go／C／CSS／JSON／YAML／TOML／Shell 等白名单；不执行代码。

CSV 使用 [Papa Parse](https://www.papaparse.com/docs) 处理逗号分隔、引号、双引号转义及字段内换行。跳过空白记录，包含标题行最多 2,000 行、每行最多 100 列，并要求各行列数一致。关闭自动类型转换，公式和数字均保留为原文。格式错误或超限直接拒绝，不自动改列或执行公式。

文件名称可打开私有文本预览和下载原文件；预览使用转义的纯文本，不渲染 HTML、不运行脚本。弹窗独立滚动，关闭按钮固定显示；关闭弹窗不会提交聊天表单。读取需登录和对话所有权检查，响应 `Cache-Control: no-store`，不进入 Service Worker 缓存。PDF 先由浏览器提取再可靠保存；只上传 PDF 原文件不会自动产生可用于问答的文本。

## 保存、上下文和任务

原文件和标准 UTF-8 解析结果均保存在私有 R2；Library 只保存解析状态、版本、SHA-256、字节／字符数、近似 Token 数及 CSV 行列。消息、任务上下文、离线队列和草稿只保存不可变文件引用，不保存大块正文或公开文件 URL。

上传和解析成功后才加入聊天草稿。新对话获得独立 URL，保留文字及聊天焦点；切换对话或退出登录取消尚未完成的操作并清理登记。解析失败保留聊天草稿，不创建消息和模型任务。已保存引用可刷新恢复、离线排队及跨设备读取。

每条消息最多 4 个文本文件，每次发送的完整上下文最多 8 个、合计 128,000 字符；重复出现按次数计入上下文预算。近似 Token 数包括资料说明、JSON 内容边界和消息封装，沿用普通文字的有界估算与模型窗口规则，不能用于推算账单。历史、分支、重新生成、用户修订、手动和自动摘要均使用相同引用和预算。

接受任务前校验解析状态、来源、完整性、数量和预算。开始供应商调用前从 R2 读取并重新校验解析结果，将文件名、类型和正文以带资料说明的 JSON 文本发给四类协议的文本模型。相同附件在一次请求中只读取一次，正文仍按出现次数进入对应消息。资料说明只是区分文件资料和用户请求，不保证模型不会受到文件中指令的影响。

接受后的任务不依赖浏览器继续在线；页面关闭后 DO 可从已保存引用读取并生成。停止和故障保留现有任务边界，不自动重发模型调用。

## 故障与删除

解析写入前持久化认领与 5 分钟租约。成功缓存幂等复用；格式错误缓存失败状态。R2 写入结果未知时由 Alarm 在租约到期后清理解析对象，保留已完成上传的原文件，之后由用户明确重新解析，不自动调用模型。

删除必须通过消息／活动任务引用检查和使用令牌复核；接受任务与删除交错时重新校验，不接受已删除文件。当前实例解析期间暂缓清理，解析结束后清理原文件和解析对象；实例重置后租约恢复清理。删除重试保留容量预留直到对象清理确认。含附件的复制及 JSON 备份继续明确拒绝，文本导出保留文件名占位，阶段 4 第 5 项扩展附件复制及包含文件的备份。

本地自动化使用模拟供应商和本地 R2／DO，不调用付费模型或部署远程资源；它验证数据路径和故障边界，不证明真实供应商的问答质量、Cloudflare CPU 消耗或免费额度。

## 验证

`pnpm check` 通过：195 项单元、161 项端到端、1 项 PWA，以及应用／Worker／工具类型检查和构建。测试文件的严格 TypeScript 检查通过。14 项文本附件浏览器测试使用真实 Worker／DO／R2 本地运行时及实际供应商 SDK，覆盖四协议、关闭页面、跨设备预览、解析／预算拒绝、分支／摘要、混合附件、未知 R2 写入恢复、删除交错、焦点／草稿、离线排队和移动端；上游响应为模拟数据。
