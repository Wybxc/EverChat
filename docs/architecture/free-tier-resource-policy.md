# 免费层资源政策

更新：2026-10-23。EverChat 不再用固定对话数、消息数或附件累计容量来推算免费额度。此前的数值及背景保留在[限制审查](application-limit-audit.md)，本文记录当前代码的边界。

## 已取消的应用配额

- 每空间 128 个对话、每对话 1,000 条消息；创建、修订、摘要、复制和恢复使用同一规则。
- 每对话 SQLite 准入 28 MiB、写入 30 MiB、终态 32 MiB；不再有由此推算的总计约 4 GiB 预算。
- Library 数据库达到 256 MiB 后拒绝更新搜索索引。
- 摘要数量、20,000 字符长度及强制 2,048 输出 Token 上限；摘要仍须完整生成才用于后续上下文，显式输出预算仍会生效。
- 工具任务、复制任务和恢复任务的累计 1,000 条限制；每轮工具调用数、内容部分数和 Responses 思考片段数的固定上限。
- 附件的每日上传次数、空间及对话累计数量与容量；消息和上下文的图片、文档数量上限。
- 图片强制缩至 1536px／1 MiB，以及原图 24 MP 的解码上限。现在仅检查文件头，不解码整张位图，也不转码，保存原图。
- 普通文本 128 KiB／64K 字符、CSV 2,000 行／100 列的配额。
- 供应商 50 个、每供应商 1,000 个模型、模型发现 10 页与总计 8 MiB 的配额。
- 预设 200 个、总文本 512 KiB 的配额。
- 备份的 1,000 条消息限制，以及根据旧附件配额推导的 ZIP 大小／条目数限制。
- 联网结果最多 5 个来源、正文合计 12K 字符的截断。合法结果全文保留；无法保存的大结果明确失败。
- 上下文估算的固定 10% 安全余量、未配置输出上限时的默认预留，以及每张图片 4,096 Token 占位。未知窗口不再按 32K 回退值截掉历史；已知模型窗口和用户显式预算继续生效。界面说明估算仅含文本及文档。
- 联网每日预算输入框的 1,000 天花板；用户已配置的每日费用控制继续生效，不自动清除。

## 仍保留的技术边界

| 边界             | 当前行为及原因                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 平台存储         | 以实际 Cloudflare 存储结果为准，真实存储不足净化为 507 错误。不预先为对话分配容量。                                                                                                                                                                                                                                                                                                                                            |
| 单行存储         | SQL 载荷预算 1,900,000 字节，为平台 2 MB 单字符串／整行上限预留记录字段与编码空间。适用于本次任务的上下文与配置、规范消息文本、预设、会话设置和私有工具续接等。不是每个对话的总量配额。                                                                                                                                                                                                                                        |
| 单个供应商       | 含模型配置的一条供应商记录继续校验序列化字节大小，不能用取消模型数量校验绕过数据库行限制。                                                                                                                                                                                                                                                                                                                                     |
| 原文件上传       | 100,000,000 字节，按 Workers Free 单次请求的 100 MB 边界。原文件流式写入 R2，不在普通 HTTP Worker 中完整解析。                                                                                                                                                                                                                                                                                                                 |
| 整包解析工作集   | JSON 清单／配置、模型目录单页和联网响应采用 16 MiB 的单次内存保护；纯文本／PDF 派生文本保留原有 32 MiB 提取工作集边界（不再与原文件或其他文件共用累计容量），模型请求另有序列化保护。**这是应用的工作集保护值，不是 Cloudflare 的官方请求限制。** UTF-8 解码、UTF-16 文本、解析对象、签名校验和请求序列化可能同时持有多个副本；128 MB isolate 无法安全地直接解析 100 MB JSON。取消数量和累计配额不等于承诺任意大小的单次操作。 |
| 模型图片输入     | 不限制图片数量；编码为 Base64 后的合计字节受上述模型请求工作集保护，避免完整加载多张大原图后耗尽内存。原文件保存和发送给模型是两个边界。                                                                                                                                                                                                                                                                                       |
| ZIP 格式         | 当前 fflate 使用普通 ZIP，最大 32 位大小／偏移及 16 位条目计数，尚未支持 ZIP64。这与已取消的数据库总计 4 GiB 预算无关；浏览器实际可用内存也会限制大文件导入／导出。                                                                                                                                                                                                                                                            |
| 流处理           | 单事件／未完成尾部有界，微批次、提交、确认窗口与慢订阅背压继续生效；不限制完整原始响应累计大小。                                                                                                                                                                                                                                                                                                                               |
| 时长             | 普通生成 14 分钟、watchdog 15 分钟，工具任务 10 分钟；模型发现每页 20 秒、总计 45 秒，保留取消与重复游标检测。                                                                                                                                                                                                                                                                                                                 |
| 并发与租约       | 同一对话生成互斥；最多同时 2 项复制和 2 项恢复，保留租约、幂等和失败清理。历史使用次数不再阻止新任务。                                                                                                                                                                                                                                                                                                                         |
| 完整性与访问控制 | 保留鉴权、HTTPS、URL 安全、文件哈希、UTF-8 与媒体类型、父链、工具身份／结果匹配等校验。                                                                                                                                                                                                                                                                                                                                        |

16 MiB 工作集是当前整包处理架构的保护，并不保证任意形状 JSON 或并发请求都不会触发平台内存错误。继续放大单次解析需要按记录流式导入、逐段文档读取和供应商请求流式编码；不能只提高常量。分页批大小、缓存淘汰、标题长度和能力探测的小预算仍承担各自的调度或任务策略职责。

## 免费层与费用

Cloudflare 的账户用量由账户内所有资源共同消耗。应用取消配额后仍受免费层每日请求、SQL 行读写、CPU、内存和实际存储限制，不能以对话数量精确推算。外部模型、联网服务与 R2 另外计费；本次修改不增加账单硬停或费用保证。

核对日期：2026-10-23。依据：[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)、[Durable Objects 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)、[DO 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)。单次整包解析预算和数据库记录余量是 EverChat 自身的技术保护，未将它们表述为平台固定配额。

## 存储与迁移

本次不修改数据格式，不扫描历史、不做在线迁移。旧上传计数表不再读取或写入；已有数据不受影响，后续如需删除废弃表，通过离线运维完成。客户端基线分页、状态同步、内容分块、生成检查点和批量持久化继续保留。

## 验证

2026-10-23：510 项单元测试、运维集成测试、类型检查及生产构建通过。相关浏览器回归覆盖超过旧对话／消息／附件配额后继续操作、原图保留、较大原文件保存与解析保护、旧上传计数不再阻塞、预设管理、上下文与工具流程；附件删除失败后的重启及重试清理也已单独复测通过。全部使用本地隔离数据，未修改生产数据。
