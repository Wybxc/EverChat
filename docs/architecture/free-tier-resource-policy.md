# 免费层资源政策

日期：2026-10-18。目标：在 Workers Free 下放宽日常聊天限制，同时约束单次任务的内存、SQL 行、存储和执行时间。审查基线见[应用限制审查](application-limit-audit.md)；本文件记录现行实现，不以“正式版”作为取消资源保护的理由。

## 平台依据

- Workers 不强制限制响应体大小，但 isolate 内存为 128 MB；Free HTTP Worker CPU 为 10ms。[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/)
- DO SQL 字符串、BLOB 及整行最多 2 MB；Free 单对象最多 1 GB，账户合计 5 GB；DO Alarm 墙钟时间最多 15 分钟。[DO 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)
- DO Free 每日 500 万行读取、10 万行写入，另有请求和计算额度；批量持久化、日志清理和重用已有结果仍有必要。[DO 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)
- 对象 RPC 的序列化参数／返回值上限为 32 MiB，原生 Request／Response 的流式正文另行传输；大目录和会话响应直接返回 Response，也能减少普通 Worker 的解码和重新序列化。[Workers RPC](https://developers.cloudflare.com/workers/runtime-apis/rpc/)

以下是应用保护预算，不能等同于平台硬限制、账户剩余额度或账单上限。外部模型、联网服务以及 R2 的用量分别计算。

## 本次放宽

| 项目                             | 审查基线            | 调整后                                                                        |
| -------------------------------- | ------------------- | ----------------------------------------------------------------------------- |
| 普通回答原始流                   | 每次 4 MiB          | 取消固定总量上限；数据库占用和总时长继续保护                                  |
| 工具每轮原始流                   | 2 MiB               | 8 MiB；私有续接仍限 1 MiB，防止签名、加密推理或 SDK 回放无限膨胀              |
| 输入                             | 16,000 码元         | 单条正文与思考共用 768 KiB 序列化文本预算；同时验证模型上下文                 |
| 回答、思考、修订、备份           | 各 100,000 码元     | 共用上述字节预算，不再按统一字符数截断                                        |
| 全局／会话／模型／预设系统提示词 | 20,000 码元         | 64,000 码元，所有编辑器、API 与备份一致                                       |
| 显式输出 Tokens                  | 最多 100,000        | 与模型元数据共用最多 10,000,000；已知模型的真实最大输出继续校验，默认仍不设置 |
| 单供应商模型数                   | 200                 | 1,000；保留单配置接近 2 MB 的整行校验                                         |
| 目录分页                         | 5 页、到 200 项停止 | 最多 10 页；重复游标、超量、超页明确报错，不返回伪装完整的部分结果            |
| 提示词预设                       | 50 项               | 200 项，总文本仍为 512 KiB                                                    |
| 未删除历史摘要                   | 20 条               | 100 条，仍计入对话消息与历史总预算                                            |
| 工具任务历史                     | 256 条              | 1,000 条，避免先于消息容量阻断长期使用                                        |
| SSE 事件                         | 256 Ki 码元         | 1 Mi 码元；未完成尾部序列化内容另限 1 MiB                                     |
| 恢复事件                         | 约 1 MB             | 最多 1,900,000 字节（含会话参数），为 2 MB SQL 行留出余量                     |

“序列化文本预算”统计 JSON 字符串内部的 UTF-8 字节，包含引号、反斜杠、控制字符及孤立代理项的转义。768 KiB 大约容纳 786,432 个 ASCII 字符或 262,144 个常见汉字，正文与思考共享额度；不能按 Tokens 或汉字数精确换算。超限保留可保存前缀并标记失败，不伪装成完整回答。输入／编辑在写入前拒绝超限，保留草稿和已有版本。

模型目录每页最多 2 MiB，累计最多 8 MiB；每页最多 20 秒、总计 45 秒，浏览器等待 60 秒。大目录读取、解析和响应构造移到 Library DO，普通 Worker 直接转发原生 Response，避免放宽数量后增加免费 HTTP CPU 路径的 JSON 压力。获取失败或与手工保留模型合并后超量时，现有列表不变，不再使用 `.slice(0, 200)`。

会话初始化中的启用模型列表同样在 Library DO 内构造原生 Response，HTTP Worker 只完成认证和转发；模型名称、能力元数据与独立提示词不再在两层之间重复编码。API 密钥仍只存在供应商设置接口，不进入会话响应。

流保存频率保持约 1.5 秒／32 KiB，预览约 100ms／8 KiB；不因放宽回答增加每 Token SQL 写入。服务端整理普通流时逐条遍历日志游标，不把所有原始提交先复制成数组。单个微批次、提交、确认窗口和慢订阅背压继续有界。

Responses API 常见的顺序思考增量只追加当前片段，不再每个 Token 拼接并编码整段思考；片段替换和乱序仍使用重建路径。字节统计按增量累计，并处理被增量拆开的 UTF-16 代理对。

## 保留的边界

| 项目           | 保留值及原因                                                                                                           |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 对话容量       | 128 个对话、每个最多 1,000 条记录；当前历史、分支和快照仍全量读取，先分页再放宽                                        |
| 历史与数据库   | 接受任务前历史最多 4 MiB、数据库分配最多 16 MiB；写入到 30 MiB 停止，终态最多 32 MiB，预留保存失败前缀和终态的空间     |
| 单次任务上下文 | 上下文与供应商配置 JSON 合计最多 1,900,000 字节，为同一 `runs` 行的其他列与编码预留余量；窗口足够仍不能越过 SQL 行边界 |
| 搜索           | Library 数据库分配 256 MiB 保护；它不是索引独占配额，后续需要拆分或重建策略                                            |
| 供应商数量     | 最多 50 个；含密钥与系统提示的配置总请求保持 12 MiB，模型配置有单行保护                                                |
| 文件           | 单文件 5 MiB、每对话 64 个／32 MiB、每空间 512 个／512 MiB；每日写入尝试、图片解码、PDF 提取和文档上下文预算保持原值   |
| 备份           | JSON 清单 12 MiB、消息最多 1,000、ZIP 解压与条目检查、复制及恢复并发和租约保持原值                                     |
| 时间及外部请求 | 普通生成 14 分钟、watchdog 15 分钟；工具任务 10 分钟、有限轮数与服务额度；不增加供应商自动重试                         |

128 × 32 MiB 约为 4.295 GB，仍需给 Library、索引、任务元数据及账户其他部署留空间；这不是预先分配，也不是账户级总量控制。暂时不同时放大对话数量和每对话数据库预算。附件保留与副本会占用独立 R2 资源，不能用 SQLite 的 5 GB 预算为它兜底。

## 后续继续放宽的前提

2026-10-18 的容量报错定位及分阶段方案见[对话存储容量改进计划](../plans/conversation-storage-capacity-plan.md)。该方案尚未实施，下面及上表仍描述当前运行时边界。

1. 历史和分支按需读取、快照分页后，再放宽对话与消息数量；按实际字节和平台剩余额度管理长期存储。
2. 大消息、事件及私有续接分块存储后，再提高正文、输入及工具续接预算；必须同时验证搜索、编辑、复制和备份恢复。
3. 配置模型逐条存储、列表虚拟化或分页后，再提高模型目录规模；仍保留取消、游标循环与响应体保护。
4. 附件支持页范围、文本片段与可选图片质量，并有部署侧监控后，再放宽附件预算；不把免费层超额风险变为隐藏的失败。

## 验证记录

2026-10-18 本地验证：

- `pnpm test`：367 项通过，覆盖组合文本和转义字节边界、Unicode 前缀与检查点恢复、跨页模型发现、超量与循环游标、超大响应取消、上下文与恢复事件的 SQL 行预算。
- `pnpm typecheck`、`pnpm build`、改动文件的 Prettier 检查和 `git diff --check` 通过；生产构建包含 8 项必需预缓存，约 931 KiB。
- Chromium：50 项相关回归通过，涵盖普通聊天、预览／持久化、断线恢复、慢订阅、故障保存、会话参数、预设、供应商与原生工具 Workflow。最终会话响应改动后，另行通过 2 项长流与大型模型会话测试。
- WebKit：13 项相关场景通过，包含 320 项模型的移动端列表操作、获取并合并 350 个模型、会话配置及供应商设置。现有设置长场景首次在刷新后定位按钮时超时，单独重试 11.8 秒通过；本轮未修改该交互。
- 新增原生集成场景使用约 5 MiB 协议流、各 110,000 汉字的思考和回答、120,000 汉字的编辑，完成保存、导出及恢复；另验证 1,000 个启用模型的会话响应完整且不包含密钥。
- 本地 Node 顺序解析 60,000 个 Responses 思考增量，约 5.1 MB 协议数据，得到 240,000 汉字，约耗时 53ms。此项只记录本地性能，不能作为 Cloudflare CPU 结果。

发布沿用 `main` 的 Cloudflare 自动构建，状态以本次提交的 Workers Builds 检查为准。本地模拟不等同于账户剩余容量、线上免费层极限或真实模型计费测量。
