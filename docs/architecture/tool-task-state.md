# 有限联网工具的逐轮持久化状态

阶段 5 的状态基础。SQLite 日志已接入[生产 Conversation Alarm、Workflow 与过程展示](tool-workflow.md)，并在真实本地 Cloudflare 运行时验证重启、恢复与回滚。[联网服务](../features/web-tool-service.md)提供 Tavily 搜索／读取、共享每日请求上限、网页配置及默认关闭的会话开关；整体验证与边界见[路线图](../plans/serverless-feature-roadmap.md#阶段-5联网搜索与网页读取)。协议资料见[工具协议基础](tool-protocol.md)。

## 状态与事务

`ToolTaskJournal` 保存一个根任务、逐轮模型步骤、只读工具调用及完成通知。根任务绑定请求摘要、供应商协议／端点／模型、启用工具、初始上下文估算和输入预算；请求 ID、首步 ID、消息 ID 及预算相同的重复接受返回已有状态，冲突请求拒绝。同一对话最多一个活跃工具任务。

| 表                       | 内容                                                        |
| ------------------------ | ----------------------------------------------------------- |
| `web_tool_tasks`         | 根任务、固定预算、期限、认领次数、累计文字量及终态          |
| `web_tool_models`        | 每轮独立的流运行 ID、消息引用、阶段、私有续接资料及结果摘要 |
| `web_tool_calls`         | 调用 ID、参数、认领状态及对应结果／错误                     |
| `web_tool_notifications` | 按根任务和轮次去重的完成通知引用、有效期和重试时间          |

模型认领先落盘，再允许调用上游。重复认领不会增加请求计数；工具也使用相同的独立认领边界。每轮保存完整、已验证的供应商结果后才能登记工具调用；全部工具结果保存并重新验证对应关系后，才允许创建下一模型步骤。失败结果使用协议原生错误结果续接，不能覆盖已有结果，也不能借另一调用的 ID 提交结果。

所有变更由调用方包在存储事务中，与公共消息、任务接受及 Alarm 变更共同提交。日志本身不发送网络请求、不运行模型、不创建 Workflow，也不设置实际 Alarm；`nextAlarm()` 只返回需要调度的下一时间。SQLite 与原生 DO 测试验证了接受及下一轮登记发生异常时完整回滚；实际网络、派发及通知由 [Conversation 执行器](tool-workflow.md)协调。

## 恢复与停止

实例重启后，未认领的模型步骤及已保存的工具轮次仍可继续调度。已经认领但失去连接的模型步骤明确失败，要求用户主动重新生成；已经认领却未保存结果的工具调用保存中断错误，不自动重复请求。状态日志不把检查点视为恢复同一次供应商 Token 连接的能力。

取消、失败或超时会阻止下一轮认领，并清理全部私有续接。已完成的工具结果保留，未执行的调用记录取消或失败。停止后到达的有效模型／工具结果不会重新激活根任务。最终回答清理私有载荷后仍保留 SHA-256 摘要，可识别重复完成回调，拒绝用不同结果覆盖同一步。

每个已完成模型轮次生成一条小通知引用，状态仍以 DO 日志为准。通知失败按 5、10、20、30 秒退避，之后最多每 30 秒重试；有效期至任务截止后 1 分钟。确认通知后删除该记录。终态任务没有待确认通知时，日志不要求周期性 Alarm。Workflow 创建、事件投递、确认及重入已经接入 Conversation。

## 私有资料与预算

每轮私有续接独立保存，包含工具继续调用所需的签名、加密推理项目及供应商内容顺序。日志不保存供应商密钥或系统提示词，执行器从已接受任务的固定配置取值。内部 `model()`／`exchanges()` 读取不能直接暴露为公共 RPC。用于编排的 `state()` 只返回状态、步骤／消息引用和调用 ID，`publicCalls()` 只返回可展示参数与结果，`publicTask()` 聚合全部轮次的公开过程；供应商私有资料不进入这些结构。终态删除通过 `erase()` 与消息擦除事务共同执行，活跃任务拒绝擦除。

| 预算               | 上限                              |
| ------------------ | --------------------------------- |
| 整个任务期限       | 10 分钟                           |
| 模型认领           | 最多 4 次：3 次工具交换及最终回答 |
| 工具认领           | 最多 6 次，每轮最多 2 个          |
| 正文／思考总量     | 各 100,000 字符，跨轮累计         |
| 私有续接           | 每轮 1 MiB；终态清理              |
| 单次工具结果       | 64 KiB，来源正文总计 12,000 字符  |
| 每个对话的任务账本 | 256 个根任务，保留终态幂等依据    |

下一轮模型请求前，使用初始上下文、2,048 个工具定义预留 Token、历史私有内容及工具结果估算输入量；超出已固定的输入预算就拒绝登记下一步。它是模型无关的近似保护，不是供应商 Token 计数或账单。第四次模型返回更多工具调用时明确失败，不执行这些调用；错误调用记录仍可展示。

## 验证

新增 23 项 SQLite 单元测试，全部 247 项单元测试通过。四类供应商均用实际 SDK 解析模拟 SSE，并验证私有资料经过 SQLite 后仍可构造续接。覆盖幂等、请求冲突、对应关系、上下文／轮数／累计文字预算、重启恢复、取消、超时、迟到结果、通知退避、事务回滚及容量。

新增 5 项原生 DO 场景与现有 7 项 Alarm、11 项流式浏览器回归共 23 项通过。验证并发认领、真实实例重置、600 KB 分片签名、公共快照边界、终态清理、下一步事务回滚及重复最终回调。应用／Worker／工具类型检查、新增测试和 fixture 的独立严格类型检查、生产构建、差异检查通过。

只使用隔离的本地运行时、SQLite 和模拟响应，没有实际模型、搜索／网页请求、部署或远程资源操作。上述测试不证明 Workflow 编排、工具 UI、实际服务质量或 Workers Free 的生产资源消耗；这些验收继续推进。
