# 应用限制审查

日期：2026-10-18。代码基线：`3dc5b97`。

本次检查运行时代码、前端输入约束、共享校验、备份恢复及相关文档。下文的“当前”数值指上述审查基线；实施时按用户补充的 Workers Free 约束调整，最新规则与验证见[免费层资源政策](free-tier-resource-policy.md)。本审查保留原值供对照。本文中的字符限制大多使用 JavaScript `string.length`，实际单位是 UTF-16 码元，不能等同于汉字数或 Tokens。

## 1. 结论

现有代码仍把个人原型的资源预算作为固定产品上限。4 MiB 响应只是其中一项；正文长度、输入长度、消息与对话数量、模型列表、摘要、附件和备份都存在类似限制。

正式使用应取消无业务必要的固定数量配额，按模型的实际能力处理上下文与显式输出设置。技术保护应针对单次内存占用、未完成解析缓冲、数据库单行、事务和异常连接，不再用正常使用次数或完整响应的原始协议大小代替。

“可以退役”不等于可以立即删掉所有校验。当前全文存储和快照结构仍依赖这些边界；其中一些项目必须在分页、分块或资源控制到位后一起调整。

## 2. 平台边界与应用配额

2026-10-18 核对 Cloudflare 官方文档：

- Workers 不强制限制响应体大小；128 MB isolate 内存和 CPU 限制仍存在。**4 MiB 原始响应不是平台要求。**[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/#request-and-response-limits)
- DO SQLite 单字符串、BLOB 或整行上限为 2 MB；因此移除正文字符限制时，还要处理消息、事件、搜索字段及配置等大行。[DO SQL 限制](https://developers.cloudflare.com/durable-objects/platform/limits/#sql-storage-limits)
- Workers Free 的 DO SQLite 存储为账户合计 5 GB；该文档的存储超限说明另列 Free 单对象 1 GB。应用的每对话 32 MiB、空间 128 个对话均不是这些平台上限。[DO 存储限制](https://developers.cloudflare.com/durable-objects/platform/limits/#what-happens-when-a-durable-object-exceeds-its-storage-limit)、[DO 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/#sqlite-storage-backend)
- DO Alarm 单次处理的墙钟时间上限为 15 分钟。当前普通生成由 Alarm 启动，14 分钟保护有架构依据，不能直接改为无限等待。[调用时长](https://developers.cloudflare.com/durable-objects/platform/limits/#wall-time-limits-by-invocation-type)

这些平台信息不代表已测得当前账户剩余额度。应用预算也不等于账户费用硬上限。

### 3.1 模型列表存在静默截断

这是独立于聊天输出、应尽早修复的一项体验问题：

1. [供应商获取](../../worker/providers/models.ts)最多取 5 页，发现 200 个模型后停止。
2. [前端合并](../../src/features/providers/ProviderEditor.tsx)再次 `.slice(0, 200)`，提示仍显示“已获取 N 个模型”。
3. [保存校验](../../shared/providers/settings.ts)限定每供应商 200 个模型、总计 50 个供应商；[备份校验](../../shared/backup/backup.ts)重复相同规则。

建议取消固定模型／供应商数量限制，支持完整分页、重复游标检测、取消和明确的部分结果状态。当前单个供应商含全部模型序列化在一条 SQLite 记录中，已有接近 2 MB 的整行保护；需要把大模型列表拆成独立记录，不能只去掉数组长度限制后继续无限扩大一行。用户设置的名称、启用状态和覆盖参数都应保留。

### 3.2 提示词及摘要长度应统一按预算处理

- 全局、会话、模型和预设系统提示词均限制 20,000 码元，前端 `maxLength`、共享 schema 和备份都有约束；建议改用实际模型上下文和记录字节限制。
- 摘要正文最多 20,000 码元，生成时另固定最多 2,048 输出 Tokens。后者是摘要任务策略，不是普通回答的默认上限；建议允许按摘要需求和模型窗口调整，避免用一个固定值覆盖所有长历史场景。
- Responses 思考状态最多 64 个片段；工具私有续接最多 64 个内容部分。这些数量缺少统一业务依据，应以状态实际字节、模型内容顺序和分块能力管理。
- 思考片段 ID 的 200 字符边界属于标识校验，不能和完整回答体积混为一谈。可以按协议需求调整，但仍需长度和格式保护，并替换“原型限制”的模糊错误提示。

## 7. 建议实施顺序及验收

1. **统一正常聊天的输入／输出规则。** 先处理消息与事件单行存储、长内容分页和共享 schema，再退役 4 MiB／2 MiB 原始流、100,000 码元、16,000 输入及固定 100,000 输出 Tokens；客户端解析、服务端最终整理、工具续接、编辑、备份恢复必须一致。
2. **去掉模型目录静默截断。** 完整分页、可取消、循环游标保护、模型逐条存储和列表按需渲染；同步调整保存与备份结构。
3. **支持长期对话。** 改造全量历史读取、分支查找、快照和搜索后，移除 128／1,000／20／256 等固定累计数量限制以及 4／16／30／32 MiB 原型保留预算。
4. **整理附件与备份。** 取消隐藏上传次数和保留数量配额，支持文本／PDF 片段、图片质量选择及分块备份；技术上的传输、解析与解压保护保持明确。
5. **清理产品文案和现行说明。** 所有运行时“原型限制”提示改成具体原因；更新 README 和现行功能说明。测量报告和路线图中的历史原型记录保留日期与原有口径，不伪装成重新验证过的正式容量。

验收应包含：原始流大于旧阈值但正文合理；长思考；超过旧字符界限的回答与修订；模型目录超过 200 个并跨多页；超过旧数量的对话／版本／摘要／工具历史；跨设备和断线恢复；新数据的导出、复制、导入与搜索；慢订阅背压及故障保存。另测异常流、超大单事件、数据库大行、任务超时和非法备份，证明移除使用配额后技术保护仍有效。

原始审查只包含静态检查与官方限制核对。后续实现及验证独立记录在[免费层资源政策](free-tier-resource-policy.md)，不把本报告中的建议视为已经完成。
