# EverChat 前端界面优化方案

状态：实施中。日期：2026-10-15。现状基线：`a7a28c2`。

目标是让阅读、输入和切换对话成为界面的主体，减少常驻操作与重复信息，同时保留 EverChat 已有功能、主题和使用习惯。实施顺序为：可视区域与焦点 → 导航和输入框 → 消息阅读 → 设置 → 整体验收。

## 2. 产品目标与现有风格

使用者是反复阅读、输入、检索和整理私人 AI 对话的个人用户，使用环境包括桌面浏览器、手机和 PWA。主任务是选择模型、发送消息、阅读回答并继续对话。

当前风格来自 [主界面](../src/App.tsx)、[样式](../src/style.css)、[主题管理](../src/theme.ts)：中性色背景、DaisyUI 主题、系统中文字体、Lucide 线性图标、圆角输入框和用户消息、开放排版的助手回答。主色用于发送和当前选择。优化继续沿用这些特征。

已经具备且应保留的基础：

- 根布局使用动态视口高度，消息区独立滚动，输入区考虑底部安全区域。
- 设置使用固定头部、Tab、可滚动内容和保存状态区，关闭按钮不随内容滚走。
- 正文与思考均使用 Streamdown；思考默认展开，正文和思考区分别具有跟随滚动逻辑。
- 对话 URL、草稿隔离、前进后退、搜索定位、离线恢复、自动保存及私有附件已经可用。
- 用户主动开启新对话后聚焦输入框；搜索、确认操作等具有各自的焦点规则。

界面精简不改变这些数据和行为语义。已有功能清单和验收基线见 [实施与验收核对](implementation-audit.md)。原型阶段可以直接调整前端组件结构，无须保留旧布局或提供兼容层。

## 3. 现状检查与优先问题

本次在独立的本地模拟服务中检查了 1280×720、390×844 和 320×568 CSS 视口，查看了浅色、深色、空对话、供应商设置、失败回答及带 60 段正文／思考的已完成回答。使用长模型显示名并开启思维强度，刻意覆盖布局边界；未调用真实 AI 供应商。

以下数字是特定场景的 DOM 几何测量，不代表所有设备和设置。浏览器视口调整不能替代手机软键盘、触摸手势和真实 PWA 验证。

| 优先级 | 问题与证据 | 用户影响 | 优化方向 |
|---|---|---|---|
| P0 | 320×568、长模型名、思维强度开启、生成中：输入表单约 294px 高，消息滚动容器约 182px 高 | 输入工具占据大部分可用空间 | 固定发送位置，合并附件入口，模型和思维强度改为紧凑选择入口 |
| P0 | 同一窄屏场景中，顶栏标题区域被多个常驻按钮挤压，模型副标题出现逐字换行 | 标题难以辨认，并溢出顶栏原有高度 | 顶栏限制常驻操作数量，移除重复模型副标题，标题单行截断 |
| P1 | 顶栏与侧栏底部均能打开空间设置；模型名称同时出现在顶栏与输入框 | 视觉与导航重复 | 全局设置统一从侧栏底部进入；当前发送模型只在输入框中展示 |
| P1 | 助手回答底部常驻复制到新对话、复制、引用、分支、重新生成、编辑、删除七个操作 | 操作栏和正文争夺注意力，手机上多次换行 | 按使用频率安排直接操作与更多菜单 |
| P1 | `border-base-content/50` 广泛用于大区块、输入框和消息；生成信息也具有完整折叠卡片外框 | 页面分隔与内容具有接近的视觉强度 | 区分装饰分隔与必要控件边界，减少包围结构 |
| P1 | 每个供应商模型行常驻 ID 和显示名输入框，模型列表最多可达 200 项 | 浏览启用状态时需要穿过大量表单 | 默认显示紧凑模型行，展开后编辑详情 |
| P1 | 输入框显式移除 outline，外层表单未设置 focus-within 替代样式；移动侧栏仅通过 transform 收起 | 存在焦点不可见、焦点进入屏外侧栏的源码风险，尚未完整键盘验证 | 补齐可见焦点、关闭侧栏的不可交互状态和焦点回收 |
| P2 | 新对话大标题和三张带边框推荐卡，在少量任务入口上使用了较大空间 | 短屏初始界面偏重，输入框与主任务距离较远 | 降低标题层级，将推荐问题改成轻量入口 |

现有测试检查了页面横向溢出、390px 布局和设置关闭按钮，但“页面宽度没有超限”不足以发现标题挤压和阅读区域不足。新增验收需要检查关键元素的几何关系和可操作性。

## 4. 页面结构与操作分层

### 4.1 导航

桌面继续采用侧栏加主区。侧栏保留新对话、搜索、对话／归档和设置；压缩品牌区与新对话之间的空白。列表继续保留当前选择、置顶和待发送状态，不新增常驻说明文字。

顶栏结构调整为：

```text
桌面：              对话标题                 同步状态  搜索  会话参数  更多
手机：侧栏入口      对话标题                            搜索          更多
```

桌面右侧最多三个直接操作；手机最多两个，加左侧侧栏按钮。标题占据剩余宽度且单行截断。完整标题通过可访问名称和菜单中的重命名入口读取，不能仅依赖鼠标悬停。

“更多”使用一个带分组分隔的菜单，避免多层级子菜单：

| 分组 | 操作 |
|---|---|
| 会话 | 会话参数（手机）、对话文件、压缩历史 |
| 整理 | 重命名、置顶／取消置顶、归档／取消归档、复制对话 |
| 导出与恢复 | Markdown、纯文本、HTML、下载备份、导入备份 |
| 危险操作 | 删除对话，继续使用确认流程 |

菜单中的可用状态延续当前规则。新对话时不展示没有目标的整理操作；导入备份仍可使用。手机设置入口位于侧栏底部，保持与桌面相同的信息结构。

菜单需支持键盘、Escape 关闭和焦点返回，超出可视高度时内部滚动。基于现有 Popover／原生 dialog 实现，避免被消息区或设置内容的 overflow 裁切。

### 4.2 输入框

保留底部输入位置，发送和停止固定在同一个位置，工具变多时不能把按钮挤到下一行的左侧。

```text
消息输入……
附件  当前模型 ▾  思维强度 ▾  联网                  发送／停止
上下文摘要（按需展示详情）；异常提示紧邻输入区
```

- 文件和图片合并为一个附件入口，菜单中分别选择；保留图片粘贴与已有能力限制。
- 删除装饰性的 Sparkles 图标。模型名称截断展示，打开选择器后显示完整模型名、供应商和当前选择。
- 思维强度仍位于聊天框；窄屏可使用图标加当前值提示的按钮打开选择项，保留清晰的可访问名称。仅支持的模型显示该控件。
- 联网显示当前启用状态，详细配置按需打开；关闭状态不占用整段说明文字。
- 桌面有空间时使用文字标签；窄屏保留识别所需的图标和短名称。不能通过只隐藏标签而让用户猜测功能。
- 上下文常态显示一个紧凑摘要，明细进入弹出层或受限高度区域。即将省略历史、自动压缩调用、超预算等会影响本次发送的信息仍直接展示。
- 附件预览成为独立且有高度上限的区域，不能随附件增加无限推高整个输入框；删除和上传取消始终可达。

保持 Enter 发送、Shift+Enter 换行及中文输入法组合输入规则。无模型时只突出“配置模型”入口；保留草稿，发送不可用的原因应可感知。

### 4.3 消息与过程内容

用户消息继续右对齐，助手回答继续开放排版。保留历史消息中的实际模型名，它与输入框中“下一次使用的模型”具有不同含义。

| 内容 | 默认展示 | 按需展开／操作 |
|---|---|---|
| 用户消息 | 正文、附件、复制、引用、更多 | 编辑为新版本、复制到新对话、删除 |
| 助手回答 | 模型名、正文、复制、重新生成、更多 | 引用、编辑、复制到新对话、继续分支、删除、生成信息 |
| 当前分支 | 必要时展示紧凑状态文字 | 其他分支的“继续此分支”保留在更多中；状态不伪装成低对比度禁用按钮 |
| 思考内容 | 保留当前默认展开策略和流式 Markdown | 用户手动折叠；搜索命中可展开，不因生成完成自动收起 |
| 联网过程 | 紧凑过程标题、当前状态；失败原因始终可见 | 各轮调用和来源详情；不随每个流片段重置展开状态 |
| 历史摘要 | 覆盖范围、使用状态和生成状态 | 摘要正文、重新生成、删除及生成信息 |

消息常用操作保持稳定位置，避免生成结束后突然出现多行工具。鼠标环境可以弱化非当前消息的操作，但键盘 focus-within 和触摸环境中必须可发现，不能仅依赖 hover。

生成信息改为轻量入口，展开后的数据继续保留供应商用量与估算的区别。思考和工具区减少重复边框，依靠标题、间距和次级背景区分。长思考区保留独立滚动，并用可视高度约束替代所有屏幕固定 320px 的上限。

## 5. 可视区域与响应式规则

### 5.1 高度与滚动归属

根布局继续使用 CSS Grid／Flex 和动态视口高度。各级可收缩容器明确设置最小高度与最小宽度，使内容真正能够让出空间。主区只由消息容器承担纵向阅读滚动，顶栏和输入区处于普通布局的固定槽位，避免覆盖消息。

| 区域 | 滚动职责 |
|---|---|
| 侧栏 | 对话列表独立滚动，新对话和设置入口保持可达 |
| 消息区 | 正文主滚动容器，继续使用现有跟随滚动逻辑 |
| 代码、表格和超宽公式 | 内容内部横向滚动，不撑宽页面 |
| 长思考、附件预览 | 必要时内部滚动，限制高度并保留操作入口 |
| 设置窗口 | 头部、分类和保存状态保持可达，主体内容滚动 |
| 弹出菜单 | 按可用高度限制菜单并内部滚动，不截断最后一项 |

新增、折叠或展开输入控件时，已经处于底部的阅读区继续跟随；用户正在看旧消息或搜索结果时不强制滚回。思考区内外的跟随状态分别管理。

### 5.2 尺寸目标

以下为实施目标，需要通过运行页面验收，不是本轮已实现的结果：

| 场景 | 目标 |
|---|---|
| 320×568，空草稿、无附件、默认上下文详情关闭、长模型名、支持思维强度 | 输入表单高度不超过 160px，消息滚动区至少 300px；发送和停止均处于固定位置 |
| 常规手机 | 顶栏约 56px；输入工具最多一行，模型与思维强度选择项在浮层中完整展示 |
| 桌面 | 顶栏约 56–64px，保持正文与输入框对齐；沿用约 48rem 内容宽度作为起点 |
| 多行草稿、较多附件 | 输入文本和预览分别达到上限后内部滚动，不无限压缩消息区 |
| 低高度、横屏或键盘出现 | 保留输入、发送／停止和主要导航；先缩减次要状态与预览高度，再调整输入区域 |

320px 的目标适用于无错误提示的基准状态；重要错误与费用提示不得为了达标而被隐藏。正文阅读保留自然行距，不靠全面缩小字体获得更多空间。

### 5.3 断点、软键盘与安全区域

以现有 1024px 侧栏断点为起点，根据“标题、必要控件能否同时放下”决定重排。介于手机与桌面的尺寸不能继续复制完整桌面工具栏。

输入区、侧栏、顶栏及全屏设置均检查上下左右安全区域，保留现有 `viewport-fit=cover`。动态视口单位不保证所有浏览器中的软键盘都自动避让，必须单独验证。

先用 CSS 完成布局；只有在实际浏览器证据表明键盘覆盖未解决时，才加入局部、可清理的 VisualViewport 适配。不得在 React 每次渲染或每个流片段中测量全部页面。

移动侧栏关闭时，屏外内容不能进入 Tab 顺序。打开时提供清晰的模态语义、Escape／关闭操作及焦点约束，关闭后返回原入口；桌面常驻侧栏保持正常导航。

## 6. 设置与供应商模型列表

保留“通用／供应商／对话／预设／联网”五个分类和自动保存语义。窗口骨架继续沿用已经有效的固定头部和内容滚动结构；小屏采用接近全屏的布局，降低左右内边距。

Tab 不允许压缩成半个字；空间不足时横向滚动，当前分类和键盘焦点应能滚入可见范围。不新增一套移动专用分类。

### 6.1 供应商

桌面继续主从布局，左侧供应商列表，右侧当前供应商详情。窄屏改为列表与详情切换，详情内提供返回供应商列表的入口，避免完整列表堆在编辑表单上方。

基本信息按名称、API 类型、端点、密钥组织；有空间时适当并列短字段。API 密钥默认隐藏、主动查看、切换供应商／关闭设置后隐藏的行为保持不变。

模型列表改为：

```text
启用复选框  模型显示名            编辑／展开
            模型 ID
```

展开后编辑 ID、显示名、系统提示词继承及能力覆盖。取消启用不删除模型；获取列表不覆盖用户显示名和已有启用选择。添加模型使用独立的紧凑区域。

保留所有能力配置，但默认列表不展开每个模型的表单。先增加列表内筛选和延迟挂载编辑详情；只有实测 200 项仍存在明显卡顿时才考虑虚拟化，避免过早引入新的焦点与动态高度问题。

### 6.2 会话参数与自动保存

会话参数按提示词、生成参数、联网、上下文分组；不常修改的上下文高级参数采用渐进展开。思维强度继续放在输入框。

保存状态统一使用“保存中／已保存／未保存”，保留当前编辑，失败展示具体原因和重试。全局、预设、联网等编辑器的状态位置尽量一致，不修改其各自保存接口或防丢语义。

切换分类和窗口之间应保留未完成编辑；由会话参数跳到预设或联网设置后，返回来源位置。删除供应商和模型需补齐确认或明确撤销机制，不能把即时自动保存的删除伪装成仍可取消的本地修改。

## 7. 视觉、文案和可访问性

### 7.1 视觉规则

- 大面积使用主题的基础色；强调色集中用于主要动作和当前选择，不另建固定十六进制配色。
- 当前侧栏选择保留清晰的前景／背景配对；图标、置顶和状态标签也须检查，不能重现此前选中标签对比度不足的问题。
- 使用一套间距层级，以 4、8、12、16、24、32px 为起点；聊天界面不采用营销页式的大段垂直留白。
- 系统字体继续作为界面字体，代码使用等宽字体。正文约 15–16px，手机输入至少 16px；必要说明和标签一般不小于 12px，取消顶栏 10px 模型副标题。
- 区分装饰分隔、控件边界和焦点边界。前者可以减淡或移除，后两者必须清晰；不得把全部边框统一改淡。
- 优先使用现有 DaisyUI 圆角变量和组件状态；输入框、气泡保留已有较柔和的轮廓，菜单和表单采用更紧凑层级。
- 动效仅用于状态和展开反馈，遵循减少动态效果偏好；不添加消息逐项入场、背景漂浮、外部装饰图片或新字体下载。

### 7.2 文案保留规则

默认保留导航、字段名、操作名、必要状态和可采取行动的错误。删除重复品牌名、重复标题、无助于决策的说明及装饰性文案。无模型的新对话突出配置入口，已有模型则直接开始输入；推荐问题改为少量轻量按钮，短屏可进一步弱化。

影响用户决定的信息必须保留：额外模型／搜索调用费用、删除后果、上下文省略、未保存、离线待发送、上传失败和输出中断。展开技术明细与删除必要提示不是同一件事。

### 7.3 验收标准

以 WCAG 2.2 AA 为基础：普通文字对比度至少 4.5:1，大号文字至少 3:1；必要的控件识别与状态图形按非文本对比度至少 3:1 检查。装饰分隔不机械套用控件要求，禁用控件的例外也不能用于掩盖仍需阅读的重要状态。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

触摸主要操作采用至少 44×44 CSS px 的项目目标，图标本身可以更小。这高于 WCAG 2.2 AA 的 24×24 最小目标尺寸基准及其例外条件，不能把 44px 错写成 AA 的统一强制要求。[目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)

输入框通过表单 focus-within 提供可见焦点；菜单、Tab 和折叠内容支持键盘。作者创建的浮层不能完全遮住当前键盘焦点，项目进一步要求主要输入与发送保持完整可见。[焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)

主动新建对话、引用和编辑后保留合理的输入焦点；后台同步、流式更新或自动保存不抢焦点。移动端初次加载和仅关闭设置不主动唤起键盘；关闭窗口优先返回实际触发元素，元素失效时才选择合理替代。
