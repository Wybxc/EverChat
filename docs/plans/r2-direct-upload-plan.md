# R2 预签名 PUT 直传

日期：2026-10-23。状态：实施中。

## 目标

网页原文件由浏览器直接上传私有 R2，去掉客户端慢上传期间的 Worker／Library DO 转发和等待。签发、上传与使用文件仍沿用现有附件身份、取消、进度、文档解析和正常对话；不为上传引入临时对象到正式对象的复制。

本轮实施网页直传与可供 MCP 复用的批量签发／接收能力；MCP 附件工具另按其专项计划实施，不把整套 MCP 附件功能隐含纳入本次发布。

## 链路与校验

1. 受 Access 保护的 API 接收一批附件元数据，在 Library 中登记唯一对象键，并签发短期 R2 S3 PUT URL。采用 `aws4fetch` 的 SigV4，不手写签名。
2. 浏览器以 File／Blob 直传 R2，保留 XHR 进度和取消；不发送网站 Cookie、Access JWT 或其他长期凭据。签名固定对象键、PUT、Content-Type 和 `If-None-Match: *`。浏览器自行生成 Content-Length，应用不尝试设置禁用请求头。
3. 聊天准入、文档解析和附件管理页的自动接收动作检查对象存在、大小与类型；异步检查后重新核对对话／附件未删除。不下载全文验证 SHA-256，不复制对象。聊天和解析无需客户端先调用确认接口；网页上传完成后自动调用同一轻量接收 API，以立即提供预览与保存状态，无用户确认操作。
4. R2 条件写入拒绝同一对象的覆盖；412 表示对象已存在，必须经业务接收检查才能使用。网络响应丢失也先尝试接收，避免盲目重新上传。失败文件和未完成登记沿用清理机制，已有文件不因上传 URL 到期被删除。

客户端 SHA-256 继续作为 PDF 来源绑定、消息引用与备份中的内容指纹，不将其描述为直传阶段服务端验证过的摘要。备份导入、对象复制、文档解析及生成时已有的内容校验不属于上传中转，按其用途保留。原文件读取不再依赖 S3 PUT 不保证提供的 `checksums.sha256`。

## 状态与清理

复用 attachments 表的 token 保存直传 URL 的固定过期时间，lease 表示清理的最早时间；普通内部复制／恢复仍使用已有上传租约。ready 文件保留签名过期信息，删除不能立即删除对象并让尚有效的 URL 重建同名对象。未完成及已删除直传文件在 URL 到期及在途宽限期后回收；不续签旧登记，不重用对象键。删除与接收竞争时删除获胜，迟到上传不能重新激活附件。当前签名 5 分钟、在途清理宽限 15 分钟；这不是 R2 对任意慢上传的终止保证，极端迟到的孤立对象需由离线运维核对并回收，不能宣称绝对不会产生孤立对象。

不改变数据库 schema，不在请求中迁移历史数据，也不增加旧客户端上传协议的兼容分支。旧客户端需要应用更新；内部备份／复制上传仍是独立业务路径。

## 配置和开发

- 生产配置 R2 账户、bucket 与专用 S3 访问凭据；长期 Secret 只存 Worker secrets，绑定本桶。签名配置缺失时明确报告不可用，不能悄悄回退大文件中转。
- bucket 保持私有，CORS 只允许实际网站来源、PUT 与必要签名头；允许读取 ETag，缓存预检。不修改 Access 保护范围。
- 本地开发使用独立的 S3 模拟入口和本地 R2 binding；测试凭据与信任适配均不进入生产入口。模拟入口验证签名、过期和条件写入，不能只返回成功。
- 原文件目前仍按共享附件政策大小检查；R2 原生最大对象、浏览器内存及模型输入工作集是不同边界，本次不继续放大单文件政策。

## 验收与发布

覆盖真实浏览器直传、批量签发、Unicode、取消／响应丢失、签名头篡改、过期、412、大小不符、跨对话／匿名访问、删除竞争、历史附件读取，以及图片／文本／CSV／PDF、复制和备份恢复。不消耗真实模型请求。

执行格式、类型、单测、运维集成、构建及定向浏览器回归；生产签名与 CORS 就绪后用纯测试对象验证真实 R2。提交推送、创建 PR，必需检查通过后合并。记录发布与平台验证结果，不以本地模拟推断具体 CPU 或免费额度节省。
