# EverChat 紧凑布局优化方案

状态：A–E 已完成；真实移动设备验收未测。日期：2026-10-15。源码基线：`bab9dc4`。这是[首轮前端优化](frontend-refinement-plan.md)之后的第二阶段方案。

后续组件库、配色和页面骨架已由[shadcn/ui 迁移方案](shadcn-ui-migration-plan.md)接替。本篇保留当时的 DaisyUI 实施记录；紧凑原则与尺寸单位规则继续适用。

2026-10-18：按钮密度以[消息原位编辑与控件密度](message-editing-density-plan.md)为准：桌面次级操作最小 32px，触屏或窄屏最小 44px。下文全部控件维持 44px 的旧规则仅作为历史记录。

本轮把空间更多地交给消息和可编辑内容：减少重复边框，缩短容器之间的空白，用行布局取代小卡片，并把低频配置收进可辨认的折叠入口。沿用现有 DaisyUI 主题、系统字体、Lucide 图标和开放式助手回答，不新增“紧凑模式”开关。

第 2–8 节保留本轮设计、源码基线与验收目标，实施与实测结果另记于第 9 节。文中 150px／342px 是首轮验收记录；源码几何推算与浏览器实测分别标明。尺寸单位与换算口径见第 3.3 节；用于比较的 px 数值不代表实现统一使用 px。

## 1. 设计规则

继续采用首轮已读取的 Impeccable、Web Interface Guidelines、Minimalist 规则和本地 DaisyUI skill；来源及取舍见[原方案的设计依据](frontend-refinement-plan.md#1-设计依据与取舍)。本轮进一步收敛为五条规则：

1. **一个区域只保留必要的边界。** 列表行已有分隔时取消外框；外层输入区域已有边界时内部工具不再各画一圈。浮层、输入控件和焦点仍须容易辨认。
2. **压缩容器，保持内容可读。** 先减少外边距、内边距、重复标题与头像占位；正文采用 0.9375rem（默认根字号下为 15px），保留现有行高和代码阅读能力。主要按钮与折叠标题常态最小高度 2.75rem，并满足至少 44 CSS px 的操作区域。
3. **常用任务直接可达，低频字段按需展开。** 启用模型、选择模型、输入、发送和停止保持直接操作；模型能力覆盖、采样和上下文细项可以折叠。
4. **折叠标题显示必要状态。** 如“模型能力 · 自动”“生成参数 · 2 项覆盖”“上下文 · 自动压缩开”，让用户在展开前知道配置是否偏离默认值。标题不增加解释段落。
5. **不通过隐藏异常获得空间。** 未保存、失败、上下文省略、超预算及额外调用费用等信息保持可见；同一错误只呈现一份完整说明。

常规结构依靠对齐、字重和小间距形成层次。背景色与分隔线按需二选一，避免对每层容器同时添加背景、圆角、边框和阴影。颜色继续取 DaisyUI 语义色，不通过持续降低文字透明度制造层级。

## 3. 边框与间距规范

### 3.1 边界归属

| 区域             | 保留                                                                             | 移除／合并                                           |
| ---------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------- |
| 页面骨架         | 顶栏与消息区之间最多一条分隔；侧栏与主区按背景和实际主题效果决定是否需要一条分隔 | 同一接缝上的双边框、额外阴影                         |
| 消息输入框       | 一层外框与可见的 `focus-within` 焦点                                             | 输入文本、模型、思维强度等内部区域的重复框线         |
| 普通表单         | 每个输入／选择控件自身的可辨认边界；密钥输入与查看按钮共用一个控件外框           | 包围字段组的卡片框、每个标签下的装饰线               |
| 供应商列表       | 当前选中背景、明确的焦点；必要状态文字／图标                                     | 列表外框和无作用的空卡片                             |
| 模型列表         | 相邻行之间的一条轻分隔；编辑行的轻背景                                           | 列表外框、编辑器自己的顶边框及内层卡片               |
| 思考／工具／摘要 | 可展开标题、展开状态和必要状态文字；展开正文可用浅层背景区分                     | 每块独立卡片边框、嵌套卡片、额外的“过程”总折叠容器   |
| Markdown 内容    | 代码块的一层边界或背景、表格的必要单元格线、引用线                               | 若渲染器外壳已提供同一边界，取消项目附加的第二层边框 |
| 菜单／弹窗       | 清楚的浮层表面、必要边界、焦点                                                   | 内部每个小分组的包围框；分组按标题或一条分隔处理     |

Markdown 的重复边框必须先检查 Streamdown 实际 DOM，确认由哪一层负责再改；不能全局移除 `pre`、表格或图表的所有边界，也不覆盖第三方所有后代元素。

### 3.2 间距基准

使用 0.25、0.5、0.75、1、1.5rem 的少量间距值，默认根字号下分别对应 4、8、12、16、24px。优先使用现有 Tailwind 间距类，避免外层 `space-y`、子层 `margin` 和内容 `padding` 在同一接缝叠加。每个接缝由一层容器负责。

| 用途              | 建议实现值（括号内为默认根字号下的尺寸）                                                  |
| ----------------- | ----------------------------------------------------------------------------------------- |
| 图标与短标签      | 0.25–0.375rem（4–6px）                                                                    |
| 标签与输入控件    | 0.25rem（4px）                                                                            |
| 同组字段之间      | 0.5–0.75rem（8–12px）                                                                     |
| 设置任务组之间    | 1rem（16px）                                                                              |
| 模型行内部        | 水平 0.5rem、垂直 0–0.25rem；整行由内容决定高度，操作区域符合第 3.3 节                    |
| 消息动作与正文    | 0.25rem（4px）；动作本身保留可操作高度                                                    |
| Markdown 段落之间 | 从 1rem 调整为 0.75rem（16px → 12px）；标题、列表、引用单独检查，避免统一覆盖导致结构消失 |

桌面与手机共用布局规则，只调整确有必要的列数和边距。不全局修改 DaisyUI 的尺寸变量，不用整体 `scale` 压缩页面。

### 3.3 尺寸单位选择

本项目的单位决策是：**字体、间距与常规控件尺寸以 rem 为主；局部文字比例用 em；细边界和 DOM 测量用 CSS px；空间分配交给弹性布局；视口高度用 dvh。** 选择依据是用户字体偏好、内容可读性与容器约束，紧凑布局优先通过减少重复占位获得空间。

单位按用途选择。根字号沿用浏览器默认值，必要时显式设为 `100%`，不固定为 `16px`，也不通过 `62.5%` 方便换算。文中的 px 设计尺寸以根字号 16px 为换算基准；用户改变字体偏好后，rem 对应的尺寸应随之变化。字号优先相对用户默认字体设置，依据 [MDN font-size](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-size)。

| 用途                 | 采用单位／机制                           | EverChat 中的约定                                                                                                                             |
| -------------------- | ---------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 字号                 | `rem`，局部比例用 `em`／继承用 `inherit` | 正文 0.9375rem，普通输入 1rem，现有显式 13px 字号转换为 0.8125rem；标题和次级字号沿用 Tailwind rem 字阶，避免嵌套 em 字号逐层放大或缩小       |
| 行高                 | 无单位数值                               | 正文保留 1.9、代码保留 1.7；不以固定 px／rem 行高约束可放大的文字                                                                             |
| margin、padding、gap | `rem`                                    | 优先 `p-2`、`gap-3` 等现有间距类，只有间距刻度未覆盖时再用 rem 自定义值；`px-4` 中的 `px` 表示水平 padding，实际为 1rem                       |
| 控件与导航尺寸       | `rem` 最小尺寸＋内容撑开                 | 主要操作区常态最小 2.75rem；以 `max(2.75rem, 44px)` 保证项目的触控尺寸底线，标签换行时允许继续增高                                            |
| 图标与圆角           | `rem`／主题变量；随文字的图标用 `em`     | 独立图标用 rem 宽高，行内图标可用 1em；圆角沿用 DaisyUI 变量，不把 SVG 的 viewBox／描边数值机械转换为 rem                                     |
| 细边框与焦点         | CSS `px`                                 | 分隔线 1px、焦点线 2px；无需随着根字号加粗。CSS px 不等于设备物理像素                                                                         |
| 容器与列宽           | `%`、`fr`、`auto` 配合 rem 上限          | 正文保持最大 48rem、可用宽度内自适应；Grid／Flex 分配剩余空间，长文本列允许收缩并局部滚动。聊天含中文、代码和表格，暂不以 ch 统一限制正文宽度 |
| 页面与浮层高度       | `dvh` 配合 `rem`、`min()`／`max()`       | 根布局沿用 100dvh；思考、输入和浮层采用如 `min(10rem, 24dvh)` 的上限，安全区域继续使用 `env()`                                                |
| 响应式断点           | `rem`                                    | 沿用 Tailwind 的断点体系；自定义 CSS 的同一断点也统一单位，例如 640px 对应 40rem，不混用两套口径                                              |
| DOM 测量与滚动       | 浏览器返回的 CSS px                      | `scrollHeight`、滚动偏移和元素几何值按原单位计算；回写测量高度可用 px，不按固定 16 除算成 rem                                                 |

这里的单位分工是结合 EverChat 的设计选择。[MDN 长度单位](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length)说明字体、视口等相对单位的参照；[MDN line-height](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/line-height)建议使用无单位行高；[Tailwind 响应式文档](https://tailwindcss.com/docs/responsive-design#using-custom-breakpoints)要求新增断点与默认断点保持相同单位。

断点的换算也以浏览器初始字号为前提：默认 16px 时，`sm`／`md`／`lg` 分别为 40／48／64rem，对应 640／768／1024 CSS px。CSS 媒体查询与 JavaScript `matchMedia` 使用相同表达式。媒体查询中的 rem 基于浏览器初始字号及用户偏好，不随页面声明的 `html { font-size: … }` 重新换算；因此仅修改根字号无法验证字体偏好对断点的影响，依据 [W3C Media Queries 的单位规则](https://www.w3.org/TR/mediaqueries-5/#units)。设置内部短字段并排优先使用容器查询，根据剩余空间重排。

实施时同时清理现有例外：正文／用户消息的固定 15px 字号、代码与表格的固定 13px 字号，以及输入框自动增高中的硬编码 160px 上限。字号改为等值 rem，默认视觉尺寸保持；输入内容高度仍按 [DOM 测量](https://developer.mozilla.org/en-US/docs/Web/API/Element/scrollHeight)写入 px，由 CSS 的 rem／dvh 上限限制最终高度，避免 JS 与 CSS 分别维护一套上限。检查嵌套 `code` 的相对字号，避免重复缩小。

有文字的按钮、选择器、折叠标题和状态栏使用最小高度与 padding，避免固定高度裁切放大后的文字。输入框按内容增长，安全区域以 `max(既定 rem 间距, env(...))` 合并。视口单位用于布局边界，不用于正文和控件字号；不能仅更换为 rem 就认定缩放与可访问性已通过。

实现中保留 DaisyUI 主题尺寸变量和 Tailwind 现有刻度，避免为相同尺寸再建一套 token。Lucide 独立图标由 rem 宽高控制，SVG 坐标与描边仍按图标库约定。自动增高输入框除内容与宽度变化外，也须在实际字体尺寸变化后重新测量；DOM 测量结果不缓存为固定设计尺寸。

## 4. 聊天主区

### 4.1 扁平消息结构

```text
小图标  历史模型名                      必要生成状态
▾ 思考过程
  流式 Markdown……
▸ 联网工具 · 2 次调用 · 已完成
回答正文使用整行宽度……
复制  重新生成  更多        当前分支（存在时）
```

头像不再形成贯穿整条回答的左侧空列。标题中的小图标仅作身份辅助，不增加标题高度；模型名仍表示该条回答实际使用的模型。保留约 48rem 的桌面内容宽度，不随屏幕无限拉宽正文。

消息列表水平内边距改为手机 16px、桌面 24px，并与输入区域尽量对齐。相邻消息依靠角色、气泡和 20–24px 间距区分，不给每条回答增加分隔线。

常用动作继续位于正文下方，减少上边距和按钮之间的空白；保留复制、重新生成／引用和更多的当前分工。不把动作移到仅 hover 可见的位置，也不将按钮覆盖在正文或代码上。

### 4.2 思考、工具和摘要

思考与工具采用两个同级折叠入口；没有相关内容就不渲染入口。取消重复卡片外观，展开内容底部留 8px。工具调用用紧凑列表呈现，来源标题直接作为链接，摘录继续按需查看。

思考默认展开，流式 Markdown 和完成后的展开状态保持现有行为。不能为了紧凑而在出现正文、生成完成或追加片段时自动收起思考。长思考仍有受视口约束的内部滚动，不通过截断文本代替折叠。

已完成摘要首次加载时默认折叠，标题保留覆盖条数、是否用于当前分支和生成状态；正在生成的摘要保持原有展开行为，生成完成不重置展开状态。重新生成、删除和生成信息收进摘要自己的“更多”，避免已折叠的摘要下仍常驻第二排按钮。失败原因在折叠状态下也可见。

同一工具调用的完整错误只在过程区外展示一次；展开后仍能辨认是哪次调用失败，并可定位到该行。不同调用的不同错误不能合并丢失。

### 4.3 输入与导航

- 空草稿输入从一行起步，最小高度 44px；多行内容自动增高，到现有视口上限后内部滚动。中文输入法、换行、粘贴和草稿恢复均参与尺寸更新。
- 表单内边距为 6–8px，文本区与工具栏间距 4px。保留附件、模型、思维强度、联网和固定右侧的发送／停止，不再增加一行常驻操作。
- 上下文仍为紧凑摘要加明细浮层；320px 下不强行塞进已满的工具栏。异常、历史省略和额外摘要调用提示继续直接展示。
- 桌面顶栏常态从 4rem 收至 3.5rem（64px → 56px），手机维持 3.5rem；安全区域另计，文字放大时允许按内容增高。标题仍单行，按钮仍可完整点击。
- 侧栏品牌／关闭入口共用一个紧凑顶部区域；搜索与新对话之间留 8px，分类上下留 4–8px。对话行维持 44px、取消行间额外间隔；底部设置入口收至 44–48px。
- 附件预览保留高度上限。多附件的“一行摘要＋展开列表”列为后续 P2：单个附件直接展示，多项只折叠超出部分；上传进度、失败、取消和移除入口必须可达。

## 5. 设置与模型管理

### 5.1 设置骨架

继续保留通用／供应商／对话／预设／联网五个 Tab、固定关闭按钮与自动保存。标题行用 44px 控件加上下各 6–8px 内边距；Tab 不另加大块上下空白。主体内边距手机 12px、桌面 16px，字段标签与输入间留 4px。

保存状态区在普通状态下只保留一行；有重试、恢复等操作时由控件所需高度决定。状态区与内容间最多一条分隔，不能因压缩而滚出屏幕或遮挡最后一个字段。各 Tab 的保存状态仍按原来的数据保存归属展示，避免无依据地报告“全部已保存”。

桌面优先并排语义相关的短字段；小屏退回单列。提示词编辑是该页面的主任务时保留足够的编辑高度，例如预设页不默认折叠整个编辑器。只有少量控件的通用页不增加折叠层级。

### 5.2 供应商与模型

```text
供应商列表        当前供应商                         删除
                  名称              API 类型
                  API 端点
                  API 密钥                         查看

                  模型  已启用 3 / 8                 获取

                  ☑ DeepSeek Flash                 编辑
```

- 连接配置保持直接可见。名称与 API 类型在足够宽的内容容器中并排，端点和密钥各占整行；根据实际剩余宽度决定列数，不只依赖整个屏幕宽度。
- 供应商列表去外框；保留选中背景、默认供应商和密钥状态。模型列表去外框，仅保留行分隔。获取、筛选与计数形成一个紧凑工具区，窄屏允许必要换行。
- 模型显示名与 ID 相同时只显示一行；不同时保留第二行 ID。复选框与编辑入口互不触发，不能用点击整行同时切换启用状态和展开编辑器。
- 仍只展开一个模型编辑器。ID 与显示名直接展示，“使用统一系统提示词”保持直接操作；选择专属提示词后立即显示编辑区域。
- 模型能力改为轻量折叠组，默认关闭，标题显示“自动”“自定义 N 项”或必要的“未识别”状态；展开后保留全部窗口、输出能力、图片、工具、结构化输出与思维强度配置及来源。
- “添加模型”默认只展示入口，展开后出现 ID、显示名和添加按钮并聚焦 ID。收起保留本次输入，取消才清空；不通过折叠触发添加或保存空模型。
- API 密钥查看、自动保存失败恢复、获取模型、确认删除和最多 200 个模型的能力保持不变。折叠不会改变模型启用状态，也不引入列表虚拟化。
- 供应商与联网服务共用 `ApiKeyInput`：密钥框内放置显隐按钮，使用相同高度、边框、占位文字与加载状态。已保存的联网密钥仍只在用户主动查看时读取，离开面板后隐藏，不写入本地缓存。

### 5.3 会话参数按任务折叠

| 分组     | 默认状态                                       | 折叠标题与展开内容                                                                                                       |
| -------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 预设     | 展开                                           | 标题显示默认预设／会话快照；展开后选择预设或编辑会话提示词，提供预设管理入口                                             |
| 生成参数 | 折叠                                           | 标题显示默认或覆盖项数；展开后配置支持的 Temperature、Top P                                                              |
| 联网工具 | 关闭时折叠，已开启或从聊天框联网入口进入时展开 | 标题显示关闭／已启用项目；展开后显示开关及服务配置入口；启用后的费用提示在收起时仍可见                                   |
| 上下文   | 折叠                                           | 标题显示摘要与自动压缩状态；展开后显示输出预算、输入预算、条数、压缩阈值与摘要模型；开启自动压缩的费用提示在收起时仍可见 |

移除“上下文”内部原有的第二个“预算与条数”折叠层，由外层任务组统一控制。各组允许同时展开，避免编辑一个区域时另一处突然消失。思维强度仍在聊天框中配置。

输出预算只在上下文管理中配置，仍限制实际请求的最大输出 Tokens，输入估算也预留对应容量。可选择默认、不设置或自定义；默认显示已有配置的数值，没有数值时显示“不设置”。不再在全局对话设置或生成参数中重复提供输出上限控件。

### 5.4 默认预设与新对话入口

原全局系统提示词在预设管理中显示为“默认预设”，沿用原存储字段，不复制历史数据。默认预设可编辑内容、不可重命名或删除；模型的专属提示词和已有会话覆盖继续生效。自定义预设应用到会话时保留文本快照，后续编辑或删除预设不改写历史会话。

新对话顶栏提供紧凑的预设选择与管理入口，与会话参数共用同一份自动保存状态。手机上选择控件字号至少为 `1rem`，避免 iOS 聚焦缩放；创建会话后隐藏该快捷入口，已存在会话从会话参数管理预设。预设管理重开时恢复上次选择与未保存草稿。

### 5.5 长用户消息

用户文本超过当前字号下十行时默认折叠，气泡内显示“展开消息／收起消息”。按实际行高与容器宽度测量，窗口缩放后重新判断；短消息不增加控件。只限制展示高度，完整文本仍保留在消息、复制、搜索和分享中。搜索命中隐藏的文字时先展开，再定位到命中处；原位置编辑继续使用完整文本。

## 6. 折叠行为契约

| 情况                             | 行为                                                                               |
| -------------------------------- | ---------------------------------------------------------------------------------- |
| 流式片段更新／后台同步／自动保存 | 不改变用户展开状态，不重新挂载正在编辑的控件                                       |
| 思考生成完成                     | 保持用户当前选择，不自动折叠                                                       |
| 搜索命中折叠内容                 | 展开包含命中的必要区域后定位；关闭搜索后不强制收回                                 |
| 校验错误位于关闭分组             | 展开对应分组并显示字段错误；输入过程不抢焦点，用户提交／主动定位时才移动焦点       |
| 用户收起含焦点的区域             | 焦点返回该区域标题，避免落入隐藏内容；输入草稿保留                                 |
| 切换供应商／会话                 | 展开状态按对应对象隔离；不把前一个模型的能力编辑状态带到新对象                     |
| 切换 Tab 后返回                  | 当前设置窗口内保留该对象的展开状态和草稿；关闭后重开按默认策略初始化               |
| 离开／返回消息视口               | 同一会话中的思考、工具和摘要展开状态保留至离开该会话，不因流式重排或组件重挂载复位 |
| 展开内容改变消息高度             | 底部跟随者继续跟随；正在阅读旧消息时维持阅读锚点，不跳到最新消息                   |

优先使用语义化 `details/summary` 或现有展开按钮，明确可访问名称和展开状态；不使用纯 CSS 复选框模拟交互。普通设置只有一级折叠，模型行／能力组与工具／来源摘录最多两级。不得把“更多”菜单再套成多级折叠菜单。

展开状态只属于前端视图，不写入服务器设置，不新增后台任务、轮询或模型调用。不使用展开动画逐帧测量高度；自动增高输入框和流式跟随沿用局部测量机制。

## 9. 实施与验收记录

### A：边界、间距与单位

根字号为 `100%`，正文、代码、表格和独立图标改用等值 rem；行高采用无单位数值。CSS 与 JavaScript 的相同断点统一为 rem，连接配置依据容器宽度重排。输入框测量值继续使用浏览器返回的 CSS px，由 CSS 的 rem／dvh 上限约束；草稿、宽度或实际字体尺寸变化后重新测量，使用动画帧调度避免 ResizeObserver 循环。

通过实际 Streamdown DOM 确认边框归属：代码块原有外壳、内层内容和项目 `pre` 三重边界，Mermaid 原有两层边界；现保留各自一层外壳，表格和引用边界继续保留。覆盖限定在 `.markdown` 与渲染器的具体节点。轻量折叠组使用 DaisyUI `collapse` 和 `@utility`，避免组件层规则被库的工具层覆盖；取消内容高度过渡，展开后即可正确定位焦点。

### B：消息、输入与导航

助手图标并入模型标题，正文使用整行宽度；消息、气泡、操作区、顶栏及侧栏收紧间距。输入框从一行开始，主要操作保持可达，安全区域继续参与布局。以下均为默认根字号、CSS px，使用隔离的本地模拟数据测量：

### C：思考、工具与摘要

新增轻量 `Disclosure`，展开状态保存在当前会话／设置窗口的视图作用域内。思考默认展开，生成完成、离线重连和分支切换保留用户选择；搜索命中时展开必要的所有祖先分组。摘要完成后首次加载默认关闭，生成中默认打开，状态变化不重置用户选择；操作收进摘要“更多”。

工具调用、来源摘录按需展开。完整错误保持在折叠区外，并通过“查看调用”展开、滚动及聚焦到对应失败行；同一错误不再同时出现在回答的通用失败区，标题仍标明生成失败。收起含焦点的分组时返回标题，避免焦点留在隐藏字段。

### D：紧凑设置

供应商列表去外框，模型列表保留行间分隔；相同 ID 与显示名只显示一行。名称／API 类型在足够宽的内容容器内并排，模型仍只挂载一个编辑器，能力字段默认关闭，校验失败强制展开。添加模型默认折叠，展开聚焦 ID；收起及切换 Tab 保留草稿，取消清空，组合输入中的 Enter 不触发添加。

会话设置按提示词、生成、联网、上下文独立折叠；保留自动保存、恢复与重试。关闭分组的错误、启用功能的费用仍可见。联网入口及从服务配置返回时展开联网分组。修复嵌套删除确认框的关闭事件冒泡，避免误重置外层设置编辑状态。五个 Tab、密钥查看和 200 模型管理能力保留。

### E：验证范围与限制

新增回归覆盖折叠状态、能力校验、添加模型草稿／焦点／组合输入、费用和错误可见性、失败工具调用定位、字体改变后的草稿测高、正文宽度与渲染器单层边界。已有流式、搜索、模型、摘要、设置、附件与 PWA 回归继续保留；旧入口测试改为通过新的折叠／菜单入口操作。

完成 8 个视口 × 浅／深色矩阵：320×568、360×640、390×844、768×1024、1024×768、1280×720、1440×900、844×390。集中人工检查桌面阅读、窄屏输入、供应商列表／详情与失败工具；截图使用独立模拟数据，密钥保持遮罩。

根字号 20px／24px 下，已有多行草稿随字体变化重新增高；通过浏览器默认字体偏好 20px／24px 后重新加载，另验证 CSS 与 `matchMedia` 的 64rem 断点一致。200% 根文字尺寸与 320 CSS px 重排通过；320px 对应 1280px 布局在 400% 缩放下的宽度，但本轮没有据此宣称真实浏览器页面缩放或真机已通过。

浅／深主题的合成色抽样达到普通文字 ≥4.5:1、输入边界与焦点 ≥3:1。回归发现 DaisyUI 深色主题默认 primary／primary-content 组合不足 4.5:1，现通过 `daisyui/theme` 将深色 primary 明度调为 54%，其余颜色继续继承主题；选中对话、发送、占位文字与设置状态均复测通过。
