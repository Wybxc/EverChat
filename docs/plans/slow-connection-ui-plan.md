# EverChat 慢连接下的界面加载优化方案

状态：首轮界面优化已完成并通过验收。日期：2026-10-16。代码基线：`ffeebc7`。

目标：Cloudflare 请求缓慢时，页面仍保留稳定的导航、输入区域和设置结构；远程数据只影响依赖它的区域与操作。沿用 shadcn/ui、现有语义主题及紧凑布局，不增加新的显示模式或解释段落。

本篇保留修改顺序和验收标准，第 7 节记录实际实现与验证。首轮保留现有 HTTP 接口、Access 验证和流式协议。

## 1. 已确认的原因

| 位置                                                 | 优化前行为                                                                                     | 影响                                                         |
| ---------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `src/app/App.tsx`、`useSession.ts`、`AccessGate.tsx` | `session` 初始为空，等待 `/api/session` 后才显示主界面；等待期间只显示品牌、主题入口和 Spinner | 侧栏、输入区及主要导航一起消失                               |
| `src/app/useSession.ts`                              | 启动请求失败后，仅在 `navigator.onLine === false` 时恢复缓存会话                               | 浏览器仍联网但服务响应慢时，不能沿用已有的离线恢复分支       |
| `src/app/SettingsPanel.tsx`                          | 供应商配置返回前，不挂载 `SettingsForm`；Tab 和所有内容均在表单内部                            | 本地主题、预设、联网配置也被供应商请求阻塞                   |
| `src/app/App.tsx`                                    | 对话加载、发送、附件处理、分支等待等状态合并为 `busy`，多个操作共用                            | 单项任务扩大为多个按钮不可用；禁用按钮统一半透明，辨认更困难 |
| `src/main.tsx`、`index.html`                         | 空的根节点等待 JS 和 IndexedDB 初始化，之后才挂载 React                                        | 首次资源加载或本地存储迟缓时没有启动界面                     |

已有可复用的基础：会话列表和对话快照具有本地缓存；预设、联网配置具有独立查询；API 有 20 秒超时；会话同步会保留已缓存消息。应在这些机制上拆开渲染依赖，避免重复实现缓存或请求框架。

以上是源码诊断。尚未通过生产环境的网络录制区分静态资源、Access 和业务请求的耗时，不能把所有等待都归因于某个 Cloudflare 产品。

## 2. 加载期间的统一规则

1. **保留结构。** 导航、设置 Tab、关闭按钮和输入区域保持位置；数据未到时在原位置放骨架，不用一个居中的 Spinner 替换整个区域。
2. **局部等待。** 主题切换、关闭浮层、已加载内容的复制和本地搜索，不等待不相关的远程请求。
3. **区分首次读取与后台更新。** 没有数据才显示骨架；已有数据时保留内容，只在现有状态位置提示更新或失败。
4. **未知不等于空。** 模型尚未读取时显示“读取模型”占位；成功返回空列表后才显示“配置模型”。预设、文件列表同理。
5. **保留用户正在做的事。** 请求返回、重试和自动保存不重置草稿、选中的 Tab、表单字段、展开项、滚动位置和焦点。
6. **反馈保持简短。** 状态使用“连接中”“读取中”“未保存”“重试”等必要文字；不增加多层进度条、重复通知或长期全屏遮罩。

加载提示使用稳定高度的占位与现有语义色。按钮需要等待时仍应容易辨认；只在对应按钮中展示忙碌指示，不降低整个工具栏的透明度。占位动画遵循减少动态效果的设置。

## 3. 身份、数据与操作分别判断

不要再用 `session !== null` 同时表达“可以显示页面”“身份有效”“配置已读取”和“可以发送”。保留现有认证状态，另外由各查询与操作维护自己的状态，不新增一个覆盖所有功能的全局 loading。

| 场景                               | 显示内容                                         | 可以操作                                                   | 需要等待                           |
| ---------------------------------- | ------------------------------------------------ | ---------------------------------------------------------- | ---------------------------------- |
| 首次访问，身份正在确认             | 不含私密数据的界面框架、模型与消息占位、必要状态 | 主题、通用设置、关闭浮层、侧栏展开收起                     | 私密数据展示、云端操作及消息编辑   |
| 身份已确认，某对话没有缓存         | 导航和输入框，消息区域骨架                       | 切换对话、编辑当前草稿、打开设置                           | 依赖历史或分支状态的发送与修改     |
| 身份已确认，有已缓存内容，正在更新 | 当前列表、消息和草稿，局部更新状态               | 阅读、复制、本地搜索、编辑草稿；其他操作按实际前置条件判断 | 仍需要确认的历史、分支或服务端状态 |
| 设置首次读取                       | 固定的 Tab、关闭按钮、立即可用的通用设置         | 切换 Tab、主题、关闭设置                                   | 对应远程表单的编辑与保存           |
| 后台更新失败                       | 保留现有内容，在对应区域提供重试                 | 与失败请求无关的本地操作                                   | 依赖该请求结果的操作               |
| 现有离线模式                       | 按当前规则展示本设备已保存内容与草稿             | 阅读、本地搜索、编辑草稿、现有离线队列操作                 | 网络投递、同步与上传               |
| 明确要求重新认证或拒绝访问         | 相同布局的无私密内容框架、认证恢复入口           | 主题、重新登录或切换账号                                   | 私密内容展示与云端操作             |

慢请求、请求失败和浏览器离线是不同状态。不能因为超时就伪造离线状态，也不能依据缓存中的 `authenticated` 授权网络请求。

继续保留已实现的身份边界：冷启动身份未确认时不提前展示历史、草稿、模型或密钥；确认当前身份并核对缓存所属身份后才恢复数据与队列。账号切换、退出清理、跨标签页锁定和认证恢复 URL 的规则不变。供应商密钥不加入持久缓存。

## 4. 实施顺序

### P0：先让界面结构不消失

**页面框架：** 从 `App.tsx` 提取侧栏与主区域的布局结构，供已登录页面和 `AccessGate` 的加载状态复用。框架接收内容插槽，认证未完成时只传入无私密数据的占位；不复制两套完整聊天界面。身份确认、失败和恢复只更新对应区域，维持尺寸与导航位置。

冷启动的输入区域使用不可编辑的占位，避免看似可以发送。真实输入框仅在允许恢复当前身份数据后挂载。认证失效时卸载私密内容和真实输入框，保留外层结构。

**设置布局：** 把窗口外框、Tab 状态、通用设置与关闭行为移到 `SettingsForm` 外面。供应商和默认对话设置共用现有供应商查询及自动保存实例；预设、联网 Tab 分别使用已有的独立查询，互不等待。

- 默认打开“通用”时不必先请求供应商配置；访问供应商或对话 Tab 时按需读取。
- 快速切换 Tab 不重复创建保存实例，不丢失尚未保存的供应商编辑。
- 查询失败只替换对应内容区，Tab、主题和关闭按钮仍可用。
- 自动保存状态只出现在对应表单；未加载时不显示“已保存”。
- 退出操作立即锁定网络与本地状态，不因供应商查询或保存请求迟缓而无限等待；沿用现有退出清理规则。

主要修改：`src/app/App.tsx`、`AccessGate.tsx`、`SettingsPanel.tsx`，必要时新增一个布局组件。完成此阶段即可解决最明显的“整块控件消失”。

### P1：拆细操作可用条件，保留已加载内容

梳理 `busy` 的调用位置，为发送、附件、分支修改、摘要和其他管理操作分别判断前置条件。优先使用邻近组件的派生变量，不搭建通用权限引擎。

- 对话首次读取期间允许输入并保存草稿；历史未确认时暂缓发送，不依据未读取的历史或错误分支发起生成。
- 发送中的状态只阻止重复发送及存在冲突的操作；复制、主题、导航不跟着禁用。
- 附件处理只限制相关附件操作及依赖这些附件的发送，不冻结其他设置。
- 停止生成的可用条件独立判断，不因无关读取或后台刷新而禁用。
- 已缓存消息和列表在重新连接、后台读取和失败时保留；确认为删除、身份变更等终态时按原规则处理。
- 初次缺少数据时显示对应区域的骨架；后台更新不重新挂载消息、输入框或编辑表单。

复用 `useLibraryIndex`、`useConversation` 现有缓存与同步机制。模型与附件能力未知时保留工具栏占位，避免把“正在读取”误显示为“未配置”或“不支持”。

### P1：处理慢请求、重试与焦点

- 同一身份复核进行中，焦点和联网事件复用该请求；保留身份版本及存储 epoch 检查，防止迟到响应恢复已退出的会话。
- React Query 请求接入其取消信号；快速切换 Tab 或对话时，过期响应不能覆盖当前选择与草稿。
- 继续使用现有超时与重连退避。普通错误留在对应区域，认证错误仍统一进入认证恢复流程；避免手动重试与自动重连并行重复执行。
- 设置保存失败保留本次编辑并提供重试；后台刷新不能覆盖未保存字段。
- 加载结束不抢焦点。用户在等待期间已经选择其他控件时，不自动跳回聊天框；保留新建对话、关闭弹窗等明确操作的焦点规则。

主要修改：`useSession.ts`、相关查询函数、`useConversation.ts`、`App.tsx` 及相应表单；只有确有需要时才调整 `platform/api.ts`。

### P2：补齐 React 挂载前的启动反馈

- `index.html` 的根节点提供轻量静态启动占位，覆盖 JS 尚未下载的时间；不绘制貌似可操作的假按钮。
- JS 就绪后可先显示无私密数据的启动框架，再等待 `hydrateStorage()` 完成。
- 身份与缓存归属比对、草稿恢复、队列恢复和存储写入仍等待必要的本地初始化，不能为了提早渲染产生竞态。
- 若测量显示 IndexedDB 全量读取确实明显阻塞，再拆分必要启动数据与按需读取的数据；不在本轮直接重写存储结构。

主要修改：`index.html`、`src/main.tsx`；按测量结果决定是否进一步调整 `platform/storage.ts`。

### P2：按测量结果缩短真正的网络等待

先记录静态入口资源、`/api/session`、对话快照、WebSocket ready 以及各设置请求的时间，再判断进一步的优化对象。

当前 `/api/session` 将身份验证与 Library DO 的模型、默认设置读取放在同一次响应中。首轮先解除界面渲染对该请求的整体依赖。如果测量显示配置读取显著拖慢身份确认，再拆分轻量身份接口与登录后的配置查询，并统计新增请求与首个可用操作的耗时变化。

静态资源方面按实际初始依赖检查分包与缓存。Markdown、代码、数学及图表继续按需加载；不能把 PWA 预缓存总量当成首次页面必需下载量。认证接口、密钥及 Access 路径继续排除离线响应缓存。

此阶段单独依据测量推进，不作为前面界面修复的前提。原型阶段直接调整类型与调用方，不引入旧协议兼容层。

## 5. 验收方式

使用 Playwright 拦截请求并主动控制返回时机，先断言“请求尚未完成时”的界面，再释放响应验证恢复行为。覆盖以下场景，避免仅在请求结束后截图：

| 场景                           | 核心断言                                                           |
| ------------------------------ | ------------------------------------------------------------------ |
| `/api/session` 持续挂起        | 框架和通用设置可见；无私密数据、无实际消息输入框、无提前投递       |
| `/api/session` 返回 401／403   | 认证入口可用，私密内容不恢复，URL 与已有草稿按原规则保留           |
| 身份返回与缓存属于不同账号     | 不显示旧账号数据、不投递旧队列，完成原有清理流程                   |
| 供应商请求持续挂起或失败       | 所有 Tab 与关闭按钮可用；主题、预设及联网服务不被该请求阻塞        |
| 表单保存缓慢，同时切换 Tab     | 编辑值与自动保存实例保留，不重复保存、不被刷新覆盖                 |
| 未缓存对话加载缓慢             | 消息区域骨架，输入草稿可编辑，依赖历史的操作不会提前执行           |
| 已缓存对话刷新缓慢或失败       | 消息和输入框不消失，复制与本地搜索可用，不重置滚动和焦点           |
| 先开 A 再开 B，A 最后返回      | B 保持选中，A 的响应不覆盖 B 的消息或草稿                          |
| 断网、恢复网络及跨标签页退出   | 现有离线阅读与队列规则不回退；退出后缓存和迟到响应不能恢复私密界面 |
| IndexedDB 延迟、入口资源慢加载 | 有启动反馈；实际应用恢复后不重复写入、发送或覆盖数据               |

视觉验收覆盖桌面与移动端、浅色与深色：加载与完成前后的侧栏、Tab、输入区域位置保持稳定；关闭按钮始终可达；骨架与禁用操作可辨认。检查键盘导航，加载区域用 `aria-busy` 或简短状态标识，避免每次后台刷新反复播报。

验证入口：现有 `tests/e2e/platform/access.spec.ts`、`settings/tabs.spec.ts` 以及聊天、PWA 和焦点相关测试。只增加状态隔离、迟到响应和操作可用性的行为回归，不为占位条数量等实现细节编写测试。

实施后运行相关端到端测试及 `pnpm typecheck`、`pnpm test`、`pnpm build`、格式与 diff 检查；完成一轮浏览器视觉验证。记录真实结果后再更新本文状态。

## 6. 提交拆分

1. 稳定页面框架与设置 Tab，加入延迟响应下的可见性回归。
2. 拆分操作禁用条件，修复缓存、重试和焦点行为，补齐对应回归。
3. 完善启动占位与必要的初始化调整，验证 PWA 和退出边界。

网络耗时优化以测量结果另行提交。前三步的完成标准是：请求未结束时也能看到并使用不依赖该请求的功能，失败只影响对应区域。

## 7. 首轮实现与验收记录

### 已实现

| 范围           | 实现结果                                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 页面框架       | `AppFrame`、侧栏通用入口及 `SettingsDialog` 供主界面和身份等待界面复用。首次身份确认时显示无私密数据的骨架；深浅色均可辨认。                                                   |
| 设置解耦       | Tab、关闭按钮和通用设置始终挂载；供应商／对话 Tab 按需读取供应商配置，预设和联网配置分别读取。失败只在对应内容区重试。                                                         |
| 自动保存与编辑 | `SettingsAutosave` 由弹窗外的 `SettingsPanel` 持有；慢速保存期间切换 Tab、关闭再打开不会丢失编辑或重复创建保存实例。模型能力展开状态在同一窗口内保留，密钥仍按原规则隐藏。     |
| 操作可用条件   | 分开判断历史确认、消息修改、附件处理及生成前置条件；读取历史时可编辑草稿，发送等待可靠历史。停止生成不等待无关请求。                                                           |
| 已加载内容     | 对话刷新失败保留消息、复制和草稿，提供局部重试；列表和预设区分首次未知、成功空结果与后台刷新，已缓存空列表也不会反复变成骨架。                                                 |
| 请求与焦点     | 身份复核复用同一进行中请求；退出、离线和过期对话请求主动取消，并继续检查身份版本与存储 epoch。迟到响应不覆盖当前对话，数据返回不抢走用户已选择的焦点。                         |
| 启动阶段       | HTML 静态占位覆盖脚本下载等待；React 先展示通用框架，再等待本地存储初始化。此间打开的设置窗口和 Tab 会延续到正式界面；私密数据、队列及真实输入框继续等待必要初始化和身份验证。 |

本轮没有修改后端接口、DO 执行器、流式协议及持久化频率。未新增第三方依赖。

### 后续网络性能调查

本地受控延迟证明了界面与请求依赖已拆开，不能据此推断线上网络耗时降低的比例。对话加载测试附带本地 API Resource Timing 记录；生产环境尚未录制静态资源、Access、`/api/session`、快照与 WebSocket ready 的完整耗时。

因此，本轮不拆分 `/api/session`，不重写 IndexedDB，也不依据 PWA 总预缓存量调整分包。第 4 节最后一项仍作为有线上测量依据后的独立优化，不属于本轮界面修复的未完成事项。
