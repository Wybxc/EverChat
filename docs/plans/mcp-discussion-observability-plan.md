## 目标与实施顺序

让调用方在一次正常模型调用前后，能够回答：本次提交了什么、哪些资料未提交、任务有没有进展、回答是否完整、费用依据是什么，以及怎样重建这条讨论分支。

保留现有精确 `modelRef`、显式 `continuation`、`requestId` 幂等、普通对话保存和可撤销 API Key。所有改进继续使用现有 Core 适配器、Conversation DO、Library、R2 和请求账本；不引入新的 Agent 执行平台、临时调用模式或模型 JSON Schema 输出。工具结果的结构化 schema 是 MCP 接口契约，与要求模型输出 JSON 是两件事。

## A1：记录服务端实际提交的上下文

### 三个证据层次

1. **已选择**：任务准入时选择的消息、摘要和文件，尚不代表已发出供应商请求。自动压缩尚未完成时标为 `pending`，不能把压缩前的估算当作最终输入。
2. **已提交**：资料读取／校验、有效系统提示词和工具组装完成，经过供应商适配器后已尝试发送请求。记录 `submittedAt`；请求发出不证明供应商接收完整或模型理解了资料。
3. **供应商回报**：响应 ID、模型 ID、输入用量及结束原因等实际可得证据。没有回报时返回未知，不根据 HTTP 200 或模型自述声称“全部读懂”。

统一称为“服务端输入回执”，避免“模型看到的一切”这样的无法证明的承诺。供应商的隐藏提示、内部裁剪和注意力分配不可观测。

### 回执内容与接口

`everchat_chat`／`everchat_run_get` 默认增加小型 `context` 摘要：`receiptRef`、证据阶段、所选／省略／摘要覆盖的条数、文件选区情况和 Token 估算。新增只读 `everchat_run_context_get`，用 `runRef`、步骤位置和游标按需读取清单或逻辑文本。

清单按供应商输入顺序记录：

- 消息来源引用、角色、源正文哈希、实际输入文本哈希／长度、是否为本次提问、保留或未包含的原因。
- 未包含原因区分 `context_budget`、`recent_messages`、`summary_covered`、`explicit_exclusion`、`superseded_file`；失败／删除消息属于不可用资料，不假装发生了文本截断。正文不被静默切半。
- 摘要 ID、摘要内容哈希、覆盖消息边界与来源引用；原文被摘要代替和原文被直接省略必须分别显示。
- 本次有效系统提示词的来源、版本／哈希、长度，启用工具及定义版本、模型、实际输出预算及其他生效参数；不把仅用于预算的预留写成供应商输出限制。
- 文件原始版本、实际使用的提取版本与选区、实际注入字符数／哈希；“已上传”“已解析”“已校验并组装进该步骤”分别报告。PDF 原始字节被保存不代表原始 PDF 被发送；当前路径一般发送提取文本。

文本详情必须读取**当时版本**，不能重新运行当前版本的上下文选择器，不能用当前配置或当前同名文件替代。按稳定引用重建时重新核对哈希；材料已删除则保留回执元数据并返回 `content_unavailable`，不猜测、不回填旧正文。

系统提示词全文属于相对现有“目录不返回系统提示词”的权限扩展：默认回执提供来源与指纹；如需读取服务端预设／模型的有效系统提示词，密钥管理明确授权该 Key 读取自己请求所使用的有效提示词。未授权的遮盖项必须标为 `redacted`，不能把遮盖后的结果称为完整明文请求。调用方自己提交的提示和经授权的历史／文件可按需完整读取；任何模式均不返回供应商密钥、鉴权头或供应商私有加密续接资料。

### 保存什么

在上下文选择器旁产生带来源的计划，在 `openProviderStream` 的实际消息组装处完成回执，最终发送边界补充提交事实。普通回答一条逻辑输入记录；联网工具按现有模型步骤 ID 分别记录新增工具结果与续接引用，首步之外采用增量，不为每轮复制整份历史。

- SQL 保存任务关联、顺序、来源、哈希、统计和阶段；长清单分行／分页，遵守单行边界。
- 正文优先引用已有不可变消息、摘要、附件和工具记录。只有无法从这些记录重建、又需要保留的应用生成文本，才按步骤一次性固化到现有内容存储或私有 R2，并纳入删除和备份规则。
- 不永久保留完整 HTTP 请求体、base64 图片、凭据和原始 SSE，不重新引入持久化同步事件。必要的请求载荷指纹在既有序列化边界计算，额外 CPU 需实测；不能为取得回执再发送一次请求。
- 回执失败的强一致边界放在外部调用前：无法可靠保存必需输入依据时拒绝发起付费调用。请求发出后状态更新失败，按既有未知结果／恢复流程对账，不重放模型调用；不能标为“未调用”。

SDK 的消息结构、中间件和当前自定义 fetch 边界可复用。先验证锁定的 `experimental_streamTextLowMemory` 路径是否支持需要的请求元数据，不能仅因为标准 `streamText` 文档有选项就全局打开请求体保留或回退到高内存收集。

### Token 数的语义

回执的 `estimatedInputTokens` 使用现有 `approximate-v1`，包含其覆盖的系统、历史、文件、工具与封装估算，并标记方法和未覆盖项。首步应映射当前 `ContextEstimate.totalTokens`，不能误用其中仅表示本次提问／附件分量的 `inputTokens`。供应商实际报告的 `usage.inputTokens` 单独列出，两者不能混为精确回执。

Gemini 等计数接口可作为后续显式的按需预检，不默认每次调用增加一个远程计数往返；即便预检可得，也仍与生成后的账单用量分别标记。

## A2：长任务阶段与可见进展

保持现有六种顶层状态，新增 `progress`，表达 EverChat 可观测到的阶段：

| 阶段               | 依据与边界                                                                     |
| ------------------ | ------------------------------------------------------------------------------ |
| `queued`           | 已接受，执行器尚未认领；不编造队列位置                                         |
| `preparing`        | 自动摘要、资料读取／校验和输入准备；附 dependency 类型                         |
| `waiting_provider` | 已开始模型请求，尚无可显示的正文／思考／工具输出；不能区分供应商内部排队和计算 |
| `generating`       | 已观察到语义输出；只返回供应商公开返回的内容                                   |
| `waiting_tools`    | 现有工具步骤已认领或等待结果；返回轮次及脱敏工具状态                           |
| `finalizing`       | 最后检查点／结果正在可靠保存；不能提前报告完成                                 |

返回 `acceptedAt`、`phaseStartedAt`、`providerRequestedAt`、`firstContentAt`、`lastProgressAt`、`lastContentAt`、`observedAt`、`elapsedMs`、`phaseElapsedMs` 和 `revision`。未发生的时间为 `null`。`lastProgressAt` 只因阶段推进或新增语义内容／工具结果更新，查询、网络 keepalive 和重复 checkpoint 不算业务进展；`observedAt` 才表示本次查到了服务端。

运行中开放当前持久化的正文／可选思考分页，附 `durable`／`persistedAt` 说明，预期可能落后约一个现有提交间隔（当前缓冲器以约 1.5 秒及字节阈值提交，并非端到端时延保证）。不为了 MCP 每轮轮询强刷缓冲器，不返回依赖单一实例内存、重连后可能消失的尾部。

`progress` 的通道长度可说明“正在输出思考，正文尚为空”；思考文本仍按 `includeReasoning` 显式读取。长期无进展只返回 `stale` 及依据时间，不直接改成失败、自动取消或另起付费请求。复用已有任务期限与失联恢复规则。

查询维持 0–20 秒短等待及现有退避；增加 `pollAfterMs` 提示。阶段变更低频落盘，输出进展附带既有 checkpoint 提交，不加 SQL 心跳、Cron 或每个 Token 的 RPC。重启后无法确认的瞬时细节返回未知。

## A3：区分分页、未生成完与被截断

| 信号                                 | 含义                                       | 下一步                                         |
| ------------------------------------ | ------------------------------------------ | ---------------------------------------------- |
| `output.hasMore: true`               | 当前已保存内容还有下一页                   | 原 `runRef` 继续读游标，不调用模型             |
| `output.hasMore: false` 且仍在运行   | 当前追上持久化尾部，未来可能追加           | 等待后从同一尾部继续读                         |
| 终态且 `completion.truncated: true`  | 供应商明确以长度原因结束                   | 读取完已有页后，由调用方决定新建生成请求       |
| `interrupted`／`failed`／`cancelled` | 断流、执行失败或主动停止，可能保留部分内容 | 按错误和已有 continuation 决定；不冒充长度截断 |

每次页面都返回 `resumeCursor`，即使暂时没有下一页；`nextCursor`／`hasMore` 仍表示当前可读页面。增加 `contentFinal` 说明这一通道是否还可能追加。游标绑定 Key 授权后的任务、消息、通道和实际偏移；校验其未越过当前持久化边界，保留 Unicode 代理对保护。移除固定累计偏移上限，保留有界单页读取。

终态新增 `completion`：`state`（`complete`／`incomplete`／`unknown`）、`truncated: boolean | null`、脱敏的标准／原始结束原因、`requiresNewGeneration`。待生成完成前 `completion` 为 `null`；长度结束为 `truncated: true`；正常 stop 为 false；没有充分证据的断流／未知结束原因不猜 true 或 false。

明确区分请求配置的输出预算、供应商原生长度结束和应用容量错误。仅有标准 `length` 时原因写 `provider_length_limit`，不能断言是哪一项窗口或输出配置耗尽；供应商更具体的结束原因可作为补充。推理 Token 也可能占输出预算，不能仅按可见正文字数归因。

长度结束不会自动生成下一段。沿用原 `runRef` 只读取；用新的 `requestId` 和明确 `continuation` 才发起新调用。终态、完整性和分页是三个独立维度，帮助工具应给出两种后续操作的并列示例。

## A4：可信的用量与费用

所有已声明 Token 维度使用 `number | null`；缺失不补零。有依据的真实零保留为零。每个字段附 `source`：`provider_reported`、`derived` 或 `unknown`；派生值列出规则和依赖字段，不用本地 Token 估算填充实际账单字段。

先用合成 Gemini 流复现“只有 total”“缺 input/output”“显式零与非零 total”“含 thoughts／tools”“SDK 规范化补零”的差别，再核对原生流、适配器、公共事件、检查点与 MCP 序列化。当前代码已有 raw usage 防补零逻辑，仍不能由此证明该次返回的零来自哪个环节。真实供应商若明确报告不一致数字，保留原值并给 `inconsistent_usage`，不静默改成未知或猜测纠正值。

最终化与数据完整性分开：任务结束只表示 `finalized: true`，`completeness` 可以仍为 `partial`／`unknown`。多工具轮次按请求账本汇总；某一维度有轮次缺失时，该维度总量为 null，可另报 `knownSubtotal`、已报告／预期轮次数，不能把已知部分合计当完整总量。缓存、思考与文本的包含关系沿用现有协议规则，避免重复相加。

费用复用现有 `UsageLedger`、价格快照及定点金额：返回币种、十进制金额字符串、价格来源／生效时间、`priced`／`partial`／`unpriced` 状态及汇总范围。默认范围为本回答的模型步骤，自动标题、摘要、搜索等费用另列关联项及是否计入；不把账户总量暴露给单个 Key，不合并不同币种，不把价格估算称为供应商最终账单。账本尚未同步时明确 `pending_accounting`，查询不触发补算写入。

## B：结构化读取与按轮次导出

增加三个只读工具，输出都继续提供可校验的 `structuredContent`，帮助工具同步更新：

| 工具                           | 主要参数和结果                                                                                                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `everchat_conversations_list`  | 分页发现当前 Key 获授权的正常对话，含标题、更新时间和可选分支索引；不含正文和全空间搜索                                                    |
| `everchat_conversation_read`   | `conversationRef`、明确分支 head、消息／正文游标；返回有序消息、轮次、模型、时间、父消息、revision、附件版本、摘要边界、结束状态与回执引用 |
| `everchat_conversation_export` | 固定分支 head、轮次范围、是否含公开思考／工具和格式；首期支持 Markdown、结构化读取供调用端生成 JSON，无需再提供整库备份工具                |

分支由明确消息 head 确定，不能默认导出“界面此刻选中的分支”。一次读取固定 head 和内容 revision；默认终态记录稳定，活跃回答若显式包含，则固定已持久化水位并标为 partial。游标包含快照版本，后续删除或数据变化不能悄悄跳页：返回明确 `snapshot_changed`／`content_unavailable`，调用方重新读取。

完整表示**允许逐页取得整条指定分支**，不是一次把全历史送进宿主上下文。轮次以用户提问和对应回答定义，保留孤立提问、失败回答及摘要标记；兄弟回答属于其他分支，不拼成同一轮。大消息支持正文子游标，不能因单条消息超过页预算而读不到后续。Markdown 使用围栏／引用并转义文件名与元数据，不预渲染或执行材料中的 HTML、Typst 和代码。

短导出直接返回文本页；大导出首期由调用端逐页写本地，避免服务端全量拼接及临时导出对象。文件只导出版本／哈希／选择范围和引用，不默认附带 base64、临时 PUT URL 或公开原文件下载链接。读取／导出不调用模型，不生成自动摘要或标题。

### 授权语义

读任务的权限不能自动等于读全空间。为这些新工具明确保存 `keyId → conversationId` 的授权关系；MCP 创建的新对话授予创建 Key 读取该正常对话的指定分支，包含之后在网页追加到该已授权对话的记录，这一范围需在 Key／帮助说明中写明。其他 Key 或网页单独创建的对话默认不可见；不因为复制一个 conversationId、messageRef 或 URL 获得访问权。

存量授权只在离线迁移中从可证明的 MCP 创建来源建立；存在歧义的对话不猜归属，需由网页所有者明确授权。撤销 Key 后，新查询及分页立即失败，正在返回的大页前后均复核；已下载资料无法远程撤回。仅授权分支时不得读取被排除兄弟分支或来源引用背后的未授权正文。

## C：附件版本及沿用／替换

落实既有“批量签发 → R2 PUT → 调用聊天”三步，聊天自动接受所选文件，不增加确认工具或第四步。复用已上线的网页签名器、HEAD 接收、防覆盖、私有读取与延迟清理，不复制另一套 MCP 上传存储。

1. `.typ` 作为严格 UTF-8 文本资料接入文件类型映射、选择器及辅助程序；不编译 Typst、不读取 include 路径、不自动上传引用图片或论文。PDF 仍由调用端提取全文／页码，不增加 OCR、知识库或 Workers 内 PDF.js。
2. `documentRef` 表示调用方明确关联的逻辑文件，`versionRef`／`attachmentRef` 表示不可变版本，附 `supersedes`、版本说明、创建时间、原文件 SHA-256、提取文本 SHA-256、解析器版本和选区指纹。同名不同文件不自动合并，不以名称决定“最新版”。
3. 调用参数明确 `reuse`（沿用指定版本）、`replace`（用指定新版本替换某个逻辑文件的活动版本）或 `include_both`（有意对照两版）；不允许未固定版本的 `latest`。新上传在原对象之外分配独立键，不能覆盖或回写旧引用。
4. `replace` 只改变本次及其后续分支的材料绑定，不改变旧消息、旧回执、兄弟分支或先前已接受的任务。实际组装上下文时排除同一逻辑文件的旧**材料块**，防止历史附件与新版一起发送却声称已替换；回执列出排除的版本。旧回答中对旧稿的讨论仍可能存在，不声称“替换文件”会消除模型在历史文字中看到的旧结论。
5. 历史被预算省略或被摘要覆盖时，不因此悄悄丢失已经显式激活的文件。当前分支的材料绑定与历史消息后缀选择分别管理，再统一计入预算；材料本身装不下时明确拒绝或要求页码／选区，不静默裁切。摘要标注所依据的文件版本；换版后默认不再注入仍包含被替换文件结论的旧摘要，重新估算，是否重新压缩由调用方显式决定并返回成本提示。
6. 不对所有内容做全局哈希去重或跨 Key 共享对象。复制讨论时复用既有受控附件复制服务或明确重新上传，保留当前按对话删除／备份语义。源版本、选区、替换关系及实际输入指纹进入请求幂等依据；重试不能重新解析成新的文件版本。

哈希必须注明证据：直传登记中的原文件哈希由调用端声明，HEAD 只确认存在／大小／类型；生成加载图片和文档时已有的哈希校验才可标为 verified。文本提取已校验不等于服务端独立证明 PDF 语义提取无遗漏。回执通过“发送的是全文还是哪些页／片段、实际字符数与哈希”回答送达问题，不以一个模糊的 `fileComplete: true` 覆盖所有阶段。

## D：独立提案与审查

不增加一个自动互相调用的 Agent 团队。扩展 `everchat_chat` 的显式上下文来源选择：新讨论可指定 `discussion.mode`、授权的背景消息／文件版本引用，审查另带 `targets`；仍需调用方提交 prompt、选择模型，并保存为普通对话。已有 `continuation` 的语义保持为从明确回答续聊，不能同时混用“从零独立提案”的模式。

| 模式          | 输入组织                                                                                                         | 必须返回的依据                                                            |
| ------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `independent` | 从白名单背景材料创建新的正常讨论；不继承来源对话完整父链、已有答案、思考或含答案的摘要；材料作为有来源的引用资料 | 选择清单、明确排除的来源和输入回执；原讨论及分支引用仅作出处              |
| `review`      | 新讨论仅加入明确背景和被审查的消息／命题；答案作为被审查资料，不当作系统指令；不默认带入全部先前赞同意见         | 每个 target 的稳定消息引用、正文指纹，以及可选命题 ID、原文范围和逐字引文 |

命题引用先提供 `claimId + messageRef + range + quoteHash` 的确定性机制；服务端验证引用确实匹配当时版本。不额外调用模型自动判断“命题是否正确”或生成审查结论。审查回答是否真正逐条回应仍是模型行为，EverChat 只保证材料选择和引用可查。

上下文排除需检查派生来源：删除某条 assistant 消息但仍带着概括其结论的摘要，不算独立提案。白名单用户文字或文件自身可能包含旧答案，服务端不能证明语义无污染；回执保证选择事实，不保证模型独立性或结论正确。已有来源仍保留，不在原分支中删除／改写后续消息。

新讨论的一次性背景快照可作为可见资料消息／文件保存，引用保留出处及版本；这属于用户明确创建讨论的数据，不是每次请求重复保存全历史。复用普通分支／复制和引用服务，不引入第二套讨论数据库或可循环的跨对话父链。

## 存储、Serverless 成本与迁移

主要复用：MCP 契约和帮助；共享上下文构建；Core 消息与现有 fetch 边界；Conversation 运行／检查点；Library 权限／附件；UsageLedger 及分支／导出纯函数。新增内容按职责分模块，不继续把所有读取与回执逻辑堆入 `durable-object.ts` 或 MCP handler。

额外成本主要是每次逻辑请求／工具步骤的紧凑回执、阶段变更和授权索引。禁止用逐 Token 事件、常驻 MCP 会话、周期状态写入或所有轮次的完整请求副本换取可见性。状态页应合并为一次有界 DO 读取；上下文文本和历史正文按需读取，读取与导出不重算哈希、Token 或费用。页面预算覆盖消息元数据、正文、思考及 MCP 的文本／结构化双重封装，不只限制单个 text 字段；长清单也必须可分页。

Workers Free 的 CPU 和内存约束要求避免大 JSON 二次解析、base64 复制和服务器全文导出；网络等待与 CPU 时间不同，也不能把降低 Worker 转发量等同于零 DO 活跃时长。MCP 当前 2 MiB 控制请求边界、输出单页边界、模型容量及现有序列化／SQL 边界继续保留，清除与它们无关的累计偏移魔数。不为新功能恢复总对话数、总附件量或工具轮次等任意配额。

元数据若需新增表、授权、来源关系或存储版本，通过本地维护窗口备份、离线转换、逐项校验、上线新代码完成；不在访问时回填、不保留旧协议解析分支。旧请求没有可信回执时标为 `unavailable_legacy`，可以读原始聊天，但不能事后声称知道当时确切输入。历史原始用量只保留可证明的值，不在线根据当前模型／价格补造。

删除对话时清理所属回执正文、索引和权限引用，既有签名租约与文件清理仍生效；删除被引用材料时，其他讨论可保留出处、版本与哈希，文本不可用应明确显示。备份／恢复需覆盖新增的来源、回执和版本关系；密钥值、预签名 URL、私有供应商续接不进入导出。

| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 实际上下文 | 四协议模拟供应商抓取最终请求；按顺序与回执核对保留／省略历史、摘要、有效提示、工具和文件文本／图片指纹；自动压缩后核对最终而非预估输入          |

| 分页／截断 | 超过旧累计偏移界限的长回答能读完；运行中尾部游标能等到新增内容；Unicode、正文／思考独立分页；stop、length、断流、过滤、取消和应用失败有不同结论 |
| 用量／费用 | Gemini 仅总量、缺失值、真实零、字段冲突及多轮缺失不混用；已知小计不冒充完整总量；价格来源和调用范围正确；不重复计费／入账                       |
| 记录／导出 | 指定分支按轮次完整读出，长单条消息可跨页；包含模型、时间、附件版本及摘要；并发生成／删除不跳页，不混入兄弟分支                                  |
| 权限       | 跨 Key、网页未授权对话、伪造 ref、系统提示全文权限、撤销与分页竞争均拒绝；错误和帮助不泄漏密钥或签名 URL                                        |
| 讨论组织   | 独立提案的实际请求没有被排除答案／摘要；审查引用匹配指定版本；显式 continuation 与模型选择无回归                                                |
| 存储／资源 | 离线迁移、备份恢复与删除完整；单次状态／回执查询有界；记录新增 SQL／R2 操作、存储放大、峰值内存和平台 CPU，不能只凭本地通过宣称满足免费层       |

格式、类型、单测和运维集成继续作为 PR 必需检查；MCP／附件／浏览器回归独立运行并报告。先用本地模拟供应商完成四协议和故障场景，不消耗真实模型费用；部署后用短请求核对真实 Gemini 的回执、用量与结束原因，另行记录供应商证据及无法确定的字段。各阶段的代码、协议 schema、`everchat_help`、接入文档和验收证据应一起交付。
