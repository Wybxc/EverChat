# 用量、费用估算与供应商统计计划

日期：2026-10-19。状态：已实施并部署，生产离线迁移、私有接口和真实 DeepSeek 用量入账验收通过。Cloudflare 合成资源已测量；DO CPU／活跃时长未取得，保留此测量限制。

## 目标与范围

增加统一的用量统计页，回答三个问题：花费了多少、主要花在哪些供应商和模型上、哪些请求失败或耗时较长。覆盖 EverChat 发出的对话、重新生成、上下文摘要、标题生成、模型能力检测及联网服务请求。费用是根据用量和价格计算的估算，供应商账单为实际结算依据。

参考 CC Switch 的概览、趋势、请求明细及供应商／模型／定价分页；其本地 CLI 日志采集不适合 EverChat，改为在服务端实际调用边界记录。参考依据为[官方用量统计手册](https://github.com/farion1231/cc-switch/blob/main/docs/user-manual/zh/4-proxy/4.4-usage.md)和[统计页代码](https://github.com/farion1231/cc-switch/blob/main/src/components/usage/UsageDashboard.tsx)，本次未运行 CC Switch 实际界面。

不查询整个供应商账户的余额或其他应用消费，不执行用户提供的余额查询脚本，不根据估算费用限制聊天。联网服务费用单列，避免把搜索次数换算成模型 Token。

## 统计与计价口径

### 每次真实请求独立记账

以服务端生成的 `attemptId` 标识一次真实供应商调用，关联任务 ID、模型轮次和会话引用。重新生成、检测及实际重试产生新请求；同一次请求的 Workflow 重放、结果投递重试及客户端重连沿用原 ID。

请求类型分为对话、摘要、标题、能力检测、网页搜索、网页读取。页面同时区分“回答数”和“模型请求数”：一次回答调用模型三轮，计为一个回答、三次模型请求，不能混作三个回答。

| 情况                         | 处理规则                                                         |
| ---------------------------- | ---------------------------------------------------------------- |
| 正常结束并返回最终用量       | 记录供应商报告的用量，按当次价格估算                             |
| 取消、超时、供应商错误       | 保存已知用量及终态；没有最终报告时标为部分／未知，不按零费用处理 |
| 请求已发送但进程中断         | 保留已发生请求的事实，恢复后标为结果未知；不为补统计重新调用模型 |
| 本地验证拒绝，尚未请求供应商 | 不计供应商请求和消费，可保留为普通诊断                           |
| 编辑、切换分支、复制、导入   | 不产生消费记录；真实重新请求才计费                               |
| 删除对话或供应商配置         | 历史统计保留名称快照；会话定位失效不影响金额                     |

“最终用量已报告”仍不等于“账单已确认”。页面分别展示请求状态、用量完整性、定价状态和估算金额；缺少价格或用量的数量必须与合计一起可见。

汇总金额明确标为“可计算部分的估算”，同时显示未定价、部分用量和未知请求数量。补齐价格可以显式计算此前未定价记录，但不能悄悄改写已采用价格的历史金额；人工修正保留原值、修正值和原因。

### 价格属于供应商实例与模型

价格键为 `providerId + modelId + effectiveFrom`。保存供应商名称、协议、模型 ID／显示名及价格版本快照，区分不同供应商提供的同名模型。价格记录不包含 API 密钥、完整请求端点或提示词。

供应商模型配置增加紧凑的价格编辑区：币种、每百万输入／输出 Token 单价、缓存读取／写入单价；联网服务支持按实际服务计费单位配置。空值表示未知，显式填写 0 才表示免费。支持从该供应商其他模型复制价格。

优先使用用户配置。可提供带来源链接、更新时间和适用端点的预置价格，但仅对明确匹配的服务和模型提供建议，代理及自定义端点不能套用官方价格；确认采用后再生效。更新预置目录不覆盖用户设置，也不重算历史记录。

首期支持每百万 Token 和每次调用计价；无法表达的阶梯价格、长上下文溢价、缓存有效期差异或服务套餐标为“不支持此计价规则”，允许逐请求填写修正金额。不能用简单价格公式冒充精确账单。

### 防止重复计算 Token 与金额

输入、输出是合计字段；缓存和思考往往是其中的子集。标准化层先得到互不重叠的计价分量，再分别乘单价。没有独立收费规则的思考 Token 包含在输出中，不再次加价；`totalTokens` 用于展示与校验，不能再加入费用。

例如，输入总量为 1,000，其中缓存读取为 300，输出为 200，其中思考为 50：普通输入按 700、缓存读取按 300、输出按 200 计价；不再为那 50 个思考 Token 重复收费。Anthropic 当前解析器已将缓存读写计入输入总量，不能再直接相加。Gemini 的工具输入、思考及缓存则按协议字段含义分别验证。

若供应商返回互相矛盾或缺失的细项，不用负数截断来伪造完整金额；记录可计算的小计并标注缺口。正常价格、零价格、缓存单价继承与未定价均采用明确规则。

金额使用十进制定点运算，价格保存十进制字符串，金额使用可表达亚分币的整数单位；数据库和 JSON 的精度与范围通过边界测试固定。先按请求计算，再汇总，显示时才舍入。不使用 JavaScript 浮点数反复累加。

CNY、USD 等币种分别汇总。首期不默认换汇；以后若支持统一币种，必须保存用户选择的汇率及日期，并保留原币金额。

## 统计页与交互

设置旁增加“用量统计”入口，打开与设置一致的弹窗；宽屏为紧凑面板，手机保持固定标题、关闭按钮和可滚动内容，不增加常驻聊天栏。

| 区域   | 内容                                                                                     |
| ------ | ---------------------------------------------------------------------------------------- |
| 筛选   | 今日、近 7 日、近 30 日、自定义；供应商、模型、请求类型、状态；默认浏览器时区            |
| 概览   | 分币种费用估算、模型请求数、输入／输出 Token、成功率；可展开缓存、未知费用和部分报告数量 |
| 趋势   | 按日显示费用／Token／请求量，短时间范围可切换小时；沿用同一组筛选                        |
| 供应商 | 名称、请求数、输入／输出、缓存命中率、费用、成功率、首字耗时和总耗时                     |
| 模型   | 以“供应商 · 模型”分组，显示用量、费用及单次平均费用                                      |
| 请求   | 时间、类型、供应商／模型、状态、Token、估算；展开细项并定位相关回答                      |
| 定价   | 按供应商维护价格，显示币种、来源和生效时间；未定价模型便于补齐                           |

首字耗时仅对适用的流式请求统计；平均值只采用有有效测量的数据，并显示样本数。缓存命中率使用兼容口径的缓存读取／输入 Token，不把缓存写入当作命中；协议不可比时分开显示。

请求详情不默认显示正文、密钥或完整供应商错误体；只保留受控错误分类／HTTP 状态。支持导出筛选后的 CSV，防止以 `= + - @` 等开头的名称成为表格公式。

复用 shadcn/ui、现有语义色和密度规范，图表按需加载。首期不加入年度热力图、自动余额查询或排行榜，先保证统计完整和检索可用。

## 服务端与存储

新增独立的 SQLite `UsageStore` DO，按现有个人空间归属。账本与价格表不塞进有搜索容量预算的 Library，也不放回对话正文数据库。新 namespace 仍共享账户免费额度，并非新增免费配额。

建议数据结构：

| 表               | 最小职责                                                                                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------- |
| `usage_attempts` | `attemptId` 唯一键；任务／会话引用、类型、时间、供应商／模型快照、终态、规范用量、完整性、价格版本及估算 |
| `usage_prices`   | 供应商模型计价规则、币种、生效版本、来源和用户覆盖                                                       |
| `usage_rollups`  | 按 UTC 小时、供应商、模型、类型及状态生成可重建的小聚合；金额在聚合内分币种保存                          |

账本只保留计费事实和必要诊断，不存流片段、同步事件、请求／响应正文、工具搜索内容或含密钥配置。小时聚合不与明细再相加；完整小时直接汇总，跨时区或区间的边界小时从时间索引读取明细。采用小时粒度是为了同时支持小时图和非整点时区，避免为小时趋势重扫整日明细。

价格快照在实际调用前确定。调用方将请求身份与待投递摘要写入现有任务状态；结束时与终态同一事务保存最终摘要。低频投递到 UsageStore，接收方以 `attemptId` 和状态版本幂等 upsert，在同一事务中修正聚合差额。确认后清除本地待投递负载，不长期保存两份账本。

不能在每个 Token／检查点上写全局统计。统计投递失败由已有后台维护机制退避重试，不因统计失败重试模型、丢弃回答或阻塞客户端流。断电恢复、乱序投递、终态覆盖初始状态均须测试；不能宣称外部计费与本地数据库拥有跨系统的“恰好一次”。

查询使用时间与供应商／模型索引、游标分页和小时聚合；筛选变化才重新查询，不为统计页建立持续轮询或常驻 WebSocket。明细清理与重建须显式操作，保留聚合覆盖范围和去重边界，不让清理后迟到重试重新计费。

按内聚原则新增 `shared/usage/` 的契约与纯计价逻辑、`worker/usage/` 的存储／投递／查询，以及 `src/features/usage/` 的统计界面。现有生成模块只接入采集边界，运维工具仍归 `scripts/operations/`，不将统计逻辑集中塞进 App 或 Conversation 类。

## 历史数据、免费层与运维

上线日起完整采集，不推算此前未记录的标题、能力检测和失败请求。需要历史补录时，用本地运维工具从消息最终用量生成单独标记的历史估算；默认不混入新账本总计，工具轮次不能从合计伪造拆分。重复导入、备份恢复或复制不能重复补录。

所有已有对象的 schema 变更和历史补录走[离线运维流程](../operations/offline-storage-migration.md)，先备份、预检和 dry-run，再执行及验证；不在请求、构造器或 Alarm 中回填旧数据。新建空对象可以初始化。Cloudflare namespace 的声明变更与存量业务数据迁移分别记录。

2026-10-19 核对：DO Free 每日 100,000 次请求、13,000 GB-s、500 万行读、10 万行写，账户 SQL 存储共 5 GB；超额相关操作失败。统计采用每次调用数量级的写入，不能占用每个流片段数量级的资源。[DO 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)

现有对话预算已占用大部分理论存储空间，新增账本需与[免费层资源政策](../architecture/free-tier-resource-policy.md)及分享快照共同重新核算。先测每千次请求的 SQL 行读写、分配字节、RPC、CPU 和活跃时长，再确定索引与保留方案；不自动删账、不擅自增加每日应用消费限额，也不保证整个 Cloudflare 账户零费用。

## 实施顺序与验收

| 阶段          | 工作                                                             | 完成条件                                                                 |
| ------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1. 口径与采集 | 类型契约、价格与分量规则、请求身份、完整性；接入全部实际调用入口 | 四协议、标题／摘要／检测、联网多轮、失败取消均有正确记录；同一调用不重计 |
| 2. 存储与查询 | UsageStore、幂等投递、聚合、离线运维和索引查询                   | 断线／重放／乱序后合计一致；删除／复制／恢复对话不改变已发生消费         |
| 3. 前端       | 定价、概览、趋势、供应商／模型／请求明细、回答费用与 CSV         | 同名模型分供应商；未知和零值不同；多币种不混加；手机弹窗可操作           |
| 4. 验收与发布 | 模拟供应商、原生 DO 集成、浏览器回归、资源测量                   | 金额可由测试夹具逐项复算；资源报告和运维步骤可复现                       |

关键用例包括缓存／思考不重复计费、价格更新不改历史、辅助请求不漏计、能力检测失败、搜索成功但回答失败、请求取消后部分用量、旧消息只读历史补录、任务重放去重、删除供应商后统计仍可读。验证使用模拟服务；真实计费与生产测量单独记录，不把本地测试当成供应商对账结果。

## 实施记录
