# 模型能力识别与开箱即用改进计划

日期：2026-10-15。目标：减少用户为新模型手动填写能力的次数，未识别能力不再阻断用户主动选择的图片和联网请求。当前原型直接调整现有结构，不做旧格式迁移。

## 目标与验收

1. 配置目录已收录的新模型 ID 后，自动获得可用的能力和窗口信息；支持常见网关前缀、日期版本与微调别名。别名推断明确标注，不能凭系列名称虚构数值限制。
2. 未知图片／工具能力允许用户主动尝试；明确不支持或手动禁用时仍拦截。保留窗口估算与服务端执行预算，未知模型默认不发送未经确认的思考控制参数。
3. 提供模型级“测试能力”：真实发送文本、图片和工具协议请求，核验预期文本、图片内容和工具参数；仅将确认成功的能力写入配置。网络、权限、格式和输出不符保留为“未确认”，不据此关闭能力。
4. 手动配置始终优先，自动补全和测试不改名称、密钥、端点、模型启用状态、提示词或未完成输入。测试结果在连接、有效密钥或模型身份改变后失效，晚到结果不能覆盖新配置。
5. 无后台付费探测。目录在客户端低频加载，公共缓存 7 天，带离线内置快照；服务端不在聊天或流式路径下载完整目录。任务仍固定接受时的能力快照。
6. 单元测试、受影响浏览器回归、类型检查和构建通过；覆盖目录失败、别名边界、未知能力尝试、明确禁用、探测误判、并发编辑、配置刷新及备份恢复。

## 参考与取舍

- [Chatbox 目录](https://github.com/chatboxai/chatbox/blob/main/src/renderer/packages/model-registry/fetch.ts)：借鉴 models.dev、缓存和内置快照。
- [Chatbox 匹配](https://github.com/chatboxai/chatbox/blob/main/src/shared/model-registry/enrich.ts)：借鉴别名识别；EverChat 将推断与精确数据分开，手动值保持最高优先级。
- [Chatbox 测试](https://github.com/chatboxai/chatbox/blob/main/src/renderer/utils/model-tester.ts)：借鉴用户主动测试；EverChat 进一步核验响应内容与工具调用，不把 HTTP 成功等同能力确认。
- [models.dev](https://models.dev)、[数据格式](https://github.com/anomalyco/models.dev)：目录属于外部参考，缺失字段保持未知。只保留能力、限制和匹配所需字段，忽略价格、链接、密钥及其他内容。

## 阶段 A：识别与来源

- 新增经筛选的 models.dev 精简快照和可复现更新脚本。
- 逐字段优先级：手动 → 原生供应商报告 → 已确认测试 → 本地协议修订／已核对条目 → 精确公共目录 → 别名推断 → 未识别。
- 客户端进入供应商设置时后台更新公共目录，新增／获取模型时补全；只把当前配置涉及的元数据保存到云端，跨设备共用。
- 公共目录请求不携带供应商配置或密钥；失败沿用已有缓存和内置快照，不影响编辑和聊天。

## 阶段 B：未知能力的使用

- 能力的值与来源共同决定行为：未识别图片／工具能力可尝试，已明确的 false 阻止使用。
- 前后端共用同一判断，覆盖附件上传、上下文校验、联网开关和任务接受。
- 模型设置显示“未识别，可尝试”；未知窗口仍使用现有规划回退并标明，输出请求仍默认不限。
- 思考控制保持协议约束；默认不为未知模型注入强度参数，供应商主动返回的思考仍可显示。

## 阶段 C：主动验证

- 模型能力折叠区增加“测试能力”按钮及简短结果；按钮说明会发送模型请求。
- 服务端使用已保存供应商凭据，固定小型测试，限制输出、响应大小、时长和请求次数，不运行模型返回的任意工具。
- 图片测试读取图片内的验证码；工具测试要求指定函数和挑战参数；文本测试核验随机挑战值。
- 测试结果独立于手动覆盖，连接／模型身份变化时清除测试证据；手动值继续优先。
- 备份校验并保留公共目录与测试证据，不包含密钥。只在连接身份一致时接受晚到结果。
