# EverChat 对话体验改进计划

状态：阶段 A–F 已完成。日期：2026-10-17。起始代码基线：`267dc54`。

后续调整（2026-10-17）：按[对话列表简化方案第 6 节](pwa-mobile-navigation-theme-plan.md#6-移除对话归档)移除归档入口、状态与搜索范围切换，已有归档对话并入统一列表。下文归档相关内容保留为当时的设计与完成记录，不作为继续保留该功能的要求。

本计划统筹本轮九项需求，并将上一轮的侧边栏生成状态、对话菜单纳入实施顺序。[侧边栏对话操作方案](sidebar-conversation-actions-plan.md)保留其活动索引、任务一致性和任意对话操作的详细设计；跨功能的先后顺序以本篇为准。

界面沿用 shadcn/ui、现有语义主题和紧凑布局。常用操作直接可见，次要信息按需展开；缩减留白和重复边框，不以缩小字号或触摸区域换取空间。尺寸单位遵循[紧凑布局优化方案](frontend-compact-layout-plan.md)。

## 2. F8：重新生成的模型与版本

优先修复行为，再调整入口，避免界面显示已选模型而实际请求仍使用旧模型。

1. 点击普通回答的“重新生成”时，立即读取并固定输入框当前的供应商 ID、模型 ID、显示名和本次生成参数。不能默认回退到旧回答模型。
2. 使用新模型对应的系统提示词规则，包括“模型独立提示词／使用统一提示词”；思维强度按新模型能力校验。历史问题、附件、分支父节点和上下文选择沿用被重新生成消息的正确位置。
3. 新回答是该位置的独立版本。气泡标题来自服务端接受任务时固定的实际模型和显示名；等待期间继续切换模型，不改变已提交版本的标题。旧版本保留原模型、正文、后续分支和生成指标。
4. 生成请求尚未接受时的模型提示也来自本次请求快照，不借用当前选择器或旧气泡标题。相同模型 ID、不同供应商必须能正确区分。
5. 未选择模型、模型已禁用／删除或配置无效时，提供选择或设置入口；不静默换用其他模型。参数变化与离线待发送遵循同一任务配置固定规则。
6. 重新生成不消费或清空输入框中另一条尚未发送的文字、图片、文件和编辑状态。失败后保留可恢复的请求信息，不自动发起可能产生费用的重试。
7. 摘要消息的重新生成继续使用摘要专用配置流程，不能被普通回答的模型规则意外覆盖。

主要修改位置：`src/app/App.tsx` 的 `retry`／请求入队、共享提交类型、服务端接受任务的配置固定，以及 `MessageView` 的标题来源。先明确“输入框发送草稿”和“重生成请求”的不同清理行为，再复用提交能力。

## 3. F2：供应商错误的采集与展示

### 信息层次

失败消息首先显示可理解的短提示，保留已经生成的正文和思考。其下提供“查看详情”“复制诊断信息”，以及适用的“重新生成”或“供应商设置”入口。不要把一大段原始 JSON 默认铺满时间线。

展开区按实际存在的字段展示：

- 错误来源与阶段：供应商连接、响应、流式解析、工具执行等；与 EverChat 自身 API／Access 登录失败区分。
- 供应商名称、协议、实际模型，安全化后的端点，发生时间。
- 上游 HTTP 状态、供应商错误类型／代码、可读消息。
- 允许列表中的请求 ID、`Retry-After`、响应截断标记，便于排查和向供应商反馈。

错误建议依据状态码与供应商代码共同判断。`429` 不能统一解释为“额度耗尽”；可能是速率限制。供应商返回 `401` 不能触发 EverChat 的 Access 退出流程。

### 数据与隐私边界

1. 在 `worker/providers/stream.ts` 读取有限长度的错误响应，再释放响应体。建议首版最多读取 16 KiB、保存脱敏后详情最多 8 KiB，并标记截断；同时限制读取时间。解析已知 JSON 错误字段，兼容纯文本及非标准网关响应，不执行或渲染上游 HTML。
2. 为 HTTP 错误、流内错误和协议解析错误建立一致的结构化失败类型，保留面向用户的短摘要。工具失败保留自身来源，沿用已有去重规则，避免同一错误在工具区和气泡末尾重复展示。
3. 只采集必要字段。端点移除用户信息、查询参数和片段；不转发完整请求、SDK 调试对象或所有响应头。对已知 API 密钥、令牌及常见凭据字段脱敏，错误中的提示词／附件回显不直接保存。
4. 服务端先完成白名单提取与脱敏，再写消息、事件和快照。客户端复制的是同一份安全诊断，不能从另一个入口复制未脱敏内容。
5. 同步更新共享类型、存储、WebSocket／快照、备份与导入校验；备份只包含允许保存的诊断字段。原型阶段直接调整格式，不增加旧错误结构的长期兼容分支。
6. 模型列表获取与能力测试可复用错误规范。首期不增加自动重试、自动上传日志或额外遥测服务。

## 4. F3、F7：菜单分组与回答操作

### 菜单规则

按操作对象和目的分组，用少量分隔线表达边界。短菜单不强行拆组；命令组内统一使用现有 Lucide 图标和对齐宽度，不能在同一组中随机混用有图标和无图标项目。

| 入口           | 建议分组                                                                                                                                 |
| -------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 侧边栏对话菜单 | 整理：置顶、重命名、生成标题；复用：复制链接、复制对话；任务：查看生成位置、停止；归档与删除放在末尾，删除独立成组。无可用项的组不显示。 |
| 顶部对话菜单   | 整理与复用命令、独立的“导出”格式组、归档／删除；与侧边栏同名命令使用相同图标和行为。                                                     |
| 消息更多菜单   | 引用／复制到新对话等复用命令、分支操作、删除；将编辑回答和生成信息的主入口移出。                                                         |
| 参数选择菜单   | 选项使用统一勾选／单选状态列；分组标题是标签，不添加装饰图标。                                                                           |

Markdown／TXT／HTML 等纯格式选项可以统一采用文字选项，但必须与带图标的操作命令分组。危险操作保留文字语义和确认规则，不能仅靠红色图标。分组调整覆盖消息、顶部对话、侧边栏及输入框参数菜单，不重新设计整套组件库。

### 回答第一层操作区

- “编辑回答”提升至复制、重新生成旁的直接操作，保留可访问名称、悬停提示和触摸入口。继续创建手动修改版本，不覆盖旧回答及其后续分支；生成中的回答按现有约束禁止编辑。
- 简略生成信息与回答操作同层，例如 `1.2k Tokens · 8.4 s`，点击打开现有详细生成信息弹窗。桌面优先显示总 Tokens 与云端生成时长；窄屏缩短格式，不重新藏回“更多”。
- 只显示实际已有数据；供应商未返回的用量不显示为零，部分报告需可辨认，估算值使用 `≈`。不根据字符数伪造真实 Token、速度或费用。
- 手动编辑版本不继承成一次新的模型调用，不复用旧生成的统计冒充当前结果；必要时只标记“手动编辑”，原生成信息在原版本中查看。
- 将 `GenerationMetadata` 的详情内容与菜单触发器拆开，使简略信息可直接打开同一弹窗。关闭详情或编辑后恢复到原消息的触发位置，避免跳到输入框。

## 5. F6：输入框下方保持一行

主功能区始终是一行，不以常驻第二行展示上下文估算。附件预览、上传进度、校验错误仍可在各自区域展示，它们不属于这条固定操作栏。

| 空间   | 可见主操作                                         | 收纳方式                                                             |
| ------ | -------------------------------------------------- | -------------------------------------------------------------------- |
| 宽容器 | 附件、模型、思维强度、联网、简略上下文、发送／停止 | 上下文详情通过现有内容的弹出层查看。                                 |
| 窄容器 | 附件、可截断的模型名、更多参数、发送／停止         | 思维强度、联网和上下文详情进入“更多参数”；保留已启用状态的简短提示。 |

按输入框容器宽度和实际内容占用收纳，避免只按屏幕宽度判断。发送／停止始终可见，不水平滚动才能操作；模型名先截断，次要参数再折叠。触摸目标至少 44 CSS px，字号与间距使用适合缩放的单位，在 320 CSS px 宽度及 200% 字号下仍可操作。不能为满足一行而隐藏功能或缩小命中区域。

上下文估算改为本行的简短触发器，点击查看当前已有的明细与预算提示；不增加为刷新该数字而发出的高频服务端请求。收纳前后共用同一设置状态，切换布局不重置模型、思维强度或联网开关。

## 6. F4、F5：全屏搜索与快捷键

### 全屏搜索

侧边栏保留简短“搜索”入口和快捷键提示，移除内嵌的搜索输入与结果。桌面和移动端都打开覆盖可视区域的搜索弹窗；桌面可限制内部结果的阅读宽度，但弹窗本身保持全屏。

1. 顶部固定输入、范围切换与关闭按钮，结果区独立滚动。空查询展示近期对话，不请求空的远端搜索。
2. 保留本地标题匹配和联网的正文／思考匹配，按类别展示；默认搜索未归档对话，可切换归档范围。保留现有防抖、分页、索引更新、失败重试和过期请求隔离，不把所有正文拉到客户端。
3. 离线仍可搜索当前可用的本地标题，正文搜索显示必要的联网状态。身份边界沿用现有缓存与 Access 规则。
4. 支持方向键选择、Enter 打开、Escape 关闭；输入法选词时不误打开结果。结果保留真实对话链接，支持浏览器的新标签页操作。
5. 选择结果才进行 SPA 导航，恢复对应分支、消息定位和高亮；仅打开或关闭搜索不改变当前 URL、输入草稿与阅读位置。
6. 打开后聚焦搜索框，关闭回到触发入口；移动端从侧栏打开时先协调 Sheet 关闭，不叠加两个焦点陷阱。固定关闭按钮不随结果滚走。
7. 继续保留当前对话内查找，与全库搜索使用不同入口、范围和快捷键。

优先复用现有搜索接口、TanStack Query、shadcn 对话框和已安装的 `cmdk`；远程结果的筛选、分页、分支定位由现有搜索逻辑负责，不能被命令组件的本地过滤二次隐藏。

### 快捷键

建立共享命令定义，由菜单、工具提示、帮助弹窗和键盘监听共同使用，记录命令 ID、执行函数、可用条件、快捷键及作用域。不要为每个按钮增加独立全局监听。

| 首期命令     | 建议默认键    | 规则                                                                           |
| ------------ | ------------- | ------------------------------------------------------------------------------ |
| 新建对话     | `Mod+J`       | 调用已有新对话导航；保留原对话草稿，聚焦新输入框，首次发送前不创建云端空对话。 |
| 全局搜索     | `Mod+K`       | 打开全屏搜索；已打开时聚焦搜索框。                                             |
| 当前对话查找 | `Mod+F`       | 保留已有行为，当前无可查找内容时交还浏览器。                                   |
| 聚焦输入框   | `Mod+Shift+L` | 仅在当前界面存在可编辑输入框且没有阻挡弹窗时执行。                             |
| 切换侧边栏   | `Mod+B`       | 桌面折叠／展开，移动端开关 Sheet；富文本编辑等冲突作用域不拦截。               |

`Mod` 在 macOS 显示为 ⌘，其他平台显示为 Ctrl。新建对话固定为 `Mod+J`，全局搜索固定为 `Mod+K`；其余新增按键为候选，实施时检查 Chrome／Safari、macOS／Windows 的冲突后确定。不能抢占新窗口、新标签、关闭、刷新等浏览器基础快捷键。快捷键帮助从现有菜单打开，首期不扩展为完整自定义按键系统。

统一处理输入法、按住重复、`defaultPrevented`、AltGraph、弹窗和文本编辑作用域；编辑控件只放行明确允许的全局命令。只有命令可用且确实执行时才 `preventDefault`。入口显示平台对应提示并设置适用的 `aria-keyshortcuts`，键盘操作与点击共用焦点和草稿保护规则。

## 7. F1：PWA 安装、更新与缓存恢复

### 已有能力的边界

`vite.config.ts` 已配置 `VitePWA`、manifest、`autoUpdate` 和静态预缓存；`src/main.tsx` 在生产环境使用原生 API 注册 `/sw.js`。已有离线导航、数学字体和 PDF 资源回归。本项是完善生命周期和使用体验，不是首次接入 PWA。

当前配置有自动激活策略，但缺少用户可见的更新控制和多标签页协调；不能仅据此认定页面会自动刷新。构建预缓存清单的大小也不等于首次打开页面的必要下载量，应分别测量。

### 计划行为

- 安装：在通用设置中提供入口；支持安装提示事件时按能力显示按钮，已安装时隐藏。不支持该事件的平台提供简短的浏览器安装指引，避免长期展示无法执行的按钮。能力差异参考 [MDN 的 PWA 安装说明](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/How_to/Trigger_install_prompt)。
- 更新：推荐改为等待用户确认激活新版本，提示“更新／稍后”，并在设置中提供当前版本和“检查更新”。统一一套 SW 注册与更新控制器；接入 `onNeedRefresh` 等生命周期或等价的原生事件，具体流程参考 [Vite PWA 的更新提示方案](https://vite-pwa-org.netlify.app/guide/prompt-for-update)。
- 安全刷新：更新前确认草稿、待发送请求与已确认快照已保存；存在上传／解析、结果未知的写请求或尚未保存的设置时延后刷新。密钥输入未保存时提示先保存或放弃，不能为支持刷新而新增客户端明文密钥持久化。云端生成继续由 DO 执行，更新后重新订阅。
- 多标签页：协调版本通知与激活，避免另一个标签点击更新后让本页无提示丢失状态。每个标签在安全条件下刷新，不循环触发更新或重复提示。
- 缓存：仅缓存明确允许的应用静态资源；API、Access 登录／回调、密钥和私有附件响应不进入 SW 缓存。离线壳不代表登录授权，继续沿用身份未确认时的限制及退出锁定。
- 恢复：针对旧 chunk、资源更新中断和注册失败提供重试；必要时提供“修复应用缓存”，只处理本应用的静态缓存和 SW，不以删除聊天 IndexedDB、草稿或 outbox 作为修复手段。
- 性能：先测量预缓存条目、下载与存储占用，再决定哪些可延后缓存。调整后必须保留承诺的离线公式、字体、PDF 和已保存对话重开能力，不能只缩小清单却破坏离线体验。

SW 负责应用资源与生命周期，不承担后台长时间 AI 生成。首期不新增推送通知、后台周期任务或第二套缓存框架。

## 8. F9：可配置模型的 AI 标题

### 配置与触发

聊天设置中新增可折叠的“自动标题”：默认关闭，启用时选择供应商和已启用的文本模型。标题模型独立于聊天模型和摘要模型；可提示使用成本较低的模型，不默认替用户选择会产生费用的供应商。

- 新对话立即使用现有首条提问／附件标题，不等待额外请求。
- 开启自动标题后，在第一条回答成功完成且仍使用临时标题时，为该对话触发一次后台命名。已手动命名的对话不自动改名，不因每条消息、切换分支、刷新、复制或导入重复调用。
- 对话菜单增加“生成标题／重新生成标题”，仅在配置可用时提供；由用户明确发起，可用于旧对话或手动重新命名。每次操作会产生独立模型调用。
- 标题模型不可用时保留原题并提示设置；不回退到当前聊天模型。自动命名失败不影响回答，保留已有标题，允许用户主动重试。

### 执行与一致性

1. 复用 Conversation DO 与 Alarm 的持久任务基础，增加用途明确的辅助任务。固定接受时的标题模型配置、输入范围和任务标识，不新增 Workflow 或常驻服务。
2. 输入只包含有界的首个问题与首个成功回答的必要文字，不发送整个历史、附件二进制或工具原文。使用独立的短输出预算与执行期限；普通聊天默认“不设置输出上限”的规则保持原义。
3. 聊天生成优先。标题任务与主回答的状态、锁、结果和取消目标分开，不能创建虚假的回答气泡，也不能让侧边栏主任务一直显示“生成中”。具体调度需验证不会与现有 Alarm 任务互相覆盖。
4. 增加标题来源与版本：临时标题、手动标题、AI 标题。应用自动结果时校验标题仍为触发时的临时标题及版本，不能覆盖手动命名；用户主动重新生成可以替换已有标题，但不能覆盖请求之后再次修改的标题。
5. 删除后的结果直接丢弃；归档本身不撤销已接受的命名。复制／导入保留标题，不继承活动任务。设置与备份包含标题模型引用，恢复后引用无效时要求重新选择。
6. 任务派发与结果应用保证幂等；遇到上游执行结果未知，不能为了恢复而盲目重发一次可能收费的请求。失败保留原题与必要错误，主动重试创建新任务。
7. 输出清理为非空、单行、最多 80 字的普通标题，去除格式包装；不将模型输出当作 HTML、Markdown 或指令执行。

本项会增加独立的模型费用和有限的 DO 任务操作。记录额外请求、SQL／Alarm 使用量，不能承诺“复用基础设施即零成本”。不顺带增加应用内每日额度或账单限制。
