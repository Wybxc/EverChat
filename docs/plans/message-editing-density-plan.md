# 消息原位编辑与控件密度

日期：2026-10-18。适用当前 shadcn/ui 前端；延续 EverChat 的语义色、轻背景、少边框与必要导航。

## 设计参考

| 规范                                                                                      | 可借鉴的原则                                  | EverChat 的应用                                                         |
| ----------------------------------------------------------------------------------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| [Atlassian Inline edit](https://atlassian.design/patterns/inline-edit/)                   | 同一位置在阅读态与编辑态间切换                | 点击消息下方铅笔，正文原位变为文本框；保留阅读上下文                    |
| [Carbon Button specifications](https://carbondesignsystem.com/components/button/style/)   | 按任务密度分级按钮尺寸，提供 32px 的小尺寸    | 鼠标操作的次级按钮以 2rem／32px 为常态，不把所有大小都撑到 44px         |
| [Fluent 2 Layout](https://fluent2.microsoft.design/layout)                                | 使用一致的间距刻度及相近内容分组              | 同组图标 0.125rem 间距，字段和操作组采用 0.5rem，任务组之间保留更大间距 |
| [WCAG 2.2 AA 2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) | 一般指针目标至少 24×24 CSS px，另有间距等例外 | 本项目桌面常态至少 32px；触屏或窄屏至少 44px，不依赖例外来缩小点击范围  |

以上是原则参考，具体数值属于 EverChat 的设计选择，不导入其他 UI 框架或复制整套视觉风格。原位编辑只沿用交互模式，版本关系继续由现有消息分支机制维护。

## 根因与间距规则

原先全局 `[data-ui-button]` 的 `min-height: max(2.75rem, 44px)` 和图标按钮的同宽规则，覆盖了 shadcn 的 `sm/xs` 等尺寸。消息中的 14px 图标因此放在 44px 容器内，再叠加 4px 外部 gap，看起来比标记的间距更松。

调整常规按钮、Tab 和菜单项的鼠标操作最小高度至 `max(2rem, 32px)`；图标按钮同宽，保留内容撑开的能力。`any-pointer: coarse` 或不超过 40rem 的窄屏恢复 `max(2.75rem, 44px)`。混合触控设备保留触控尺寸，不能只根据屏幕宽度判断输入方式。

消息工具栏同组间隔为 0.125rem，版本数字最小宽度由 2.5rem 降到 2rem。按默认字号计算，四个 44px 按钮加三个 4px 间隔占 188px；四个 32px 按钮加三个 2px 间隔占 134px。压缩容器占位，同时保留清楚的 hover、焦点和禁用状态。

输入框、主输入区、发送按钮、阅读导航及已明确设置的大尺寸控件继续保留原有空间。间距使用 rem，细边界使用 CSS px，正文和输入字体不随工具栏一起缩小；iOS 输入保持至少 16px，页面仍可缩放。相邻点击区域使用实际布局，不用重叠的透明伪元素扩大目标。

## 编辑交互

- 提问和回答均把编辑按钮放在消息下方，菜单只保留次要操作。
- 原位置展示可换行的文本框及「取消编辑」「保存」操作。提问用「保存并重新生成」，回答用「保存新版本」。底部输入区继续保留自己的草稿与附件。
- 提问使用输入区当前选择的模型、思维强度及会话参数重新生成；保留原提问的附件引用。新版本沿用原始父节点，旧后续消息保留在旧分支。
- 回答修改 Markdown 源文本，保存后恢复渲染，不重新请求供应商；沿用现有修订规则，不继承原回答的生成用量。
- Enter 换行，Mod+Enter 保存，Escape 取消；中文输入法组词期间不触发快捷键。不因失焦自动保存或取消。
- 编辑草稿按对话单独缓存。切换分支、切换对话或刷新后可以返回原消息继续修改；取消、成功保存、删除对话或退出登录时清理对应草稿，不占用底部输入区的草稿。
- 进入编辑时将焦点移至原位文本框，暂停滚动跟随；取消后回到原消息编辑按钮，保存后等待新版本进入 DOM 再恢复焦点。
- 服务端保存失败保留文本和幂等请求 ID；用户修改内容后生成新请求 ID。提问沿用离线待发送队列，失败或离线内容不会覆盖底部草稿；重新编辑待发送的修订时回到原消息。
- 正文仍使用共享的 768 KiB 序列化字节预算。文本框按内容增高并受视口上限约束，较长内容在文本框内滚动。

## 验证

覆盖提问与回答原位编辑、取消／保存、键盘操作、失败重试、底部草稿保留、版本和旧分支、跨设备同步、移动端操作可见性、桌面 32px／触屏 44px 目标、字体放大与明暗主题。

- Chromium：28 项相关场景通过，含失败项修复后的定点复测。覆盖 8 个视口的浅／深色布局、200% 字号、32px／44px 点击范围和保存按钮可达性。
- WebKit：5 项通过，覆盖提问／回答原位编辑、版本父链、长 Markdown 切换、草稿与焦点、触屏输入字号。
- 单元测试：367 项通过；删除对话后，原位编辑草稿不能被延迟写入恢复。
- 类型检查、生产构建、Prettier 检查与 `git diff --check` 通过。
- 截图检查：桌面 1280×800 与手机 320×568 的编辑状态。

收紧消息操作行后，长短回答切换更容易触碰滚动下界；锚点逻辑现在只保留必要的额外滚动范围，并在主动导航或切换对话时释放。按下按钮时不移除该范围，避免按钮在按下和点击之间移动。
