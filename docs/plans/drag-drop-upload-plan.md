# 拖拽上传图片与文件

日期：2026-10-18。状态：已实现并通过本地拖放回归。作为第 4 项独立计划，已按用户要求纳入本轮实现与验收目标。

## 目标与范围

在聊天页面将本地图片或文件拖入消息／输入区域，释放后加入当前对话的附件草稿，等待用户发送。复用 `useChatAttachments`、`prepareAttachment` 和 `uploadAttachment` 的现有上传、模型能力校验、容量检查、进度和失败逻辑，不新增后端上传入口或另一套文件限制。

## 交互规则

- 仅在拖入真实本地文件时展示简短的「拖放以添加附件」提示和语义色高亮；拖离、释放、取消或切换对话后清除。用进入深度或等价方式避免经过子元素时闪烁。
- 有文件拖入应用时阻止浏览器将文件当作页面打开；只有聊天的有效接收区域执行上传。设置、搜索、确认弹窗和其他模态界面打开时不向背后的对话添加文件。
- 图片和文档通过同一入口分流。支持一次拖入多个文件，沿用现有数量、大小和格式校验；目录、网页链接、选中文字及不支持的文件不能被误当成附件。
- 文件上传不自动发送消息，不修改已有草稿、模型、分支或原位编辑内容，不主动抢焦点或弹出键盘。切换对话后，迟到的上传结果不能进入新对话。
- 上传中显示现有进度及取消／重试入口；单文件失败保留其他成功结果，错误提示能定位到对应文件。离线或当前状态不允许上传时明确提示，保留已有草稿。
- 保留点击选择文件入口及键盘操作，触屏设备继续使用系统文件选择器；拖拽不是唯一上传方式。

## 实施与验收

1. 梳理现有附件入口，将文件选择与拖放统一调用同一个文件接收函数。
2. 在聊天区域加入有界的拖放状态和反馈，处理模态窗口、嵌套元素、文件类型及浏览器默认导航。
3. 验证图片／文档混合、多文件、格式／容量错误、部分失败、离线、取消、对话切换及迟到响应；确认没有重复上传或自动发送。
4. 回归点击选择、草稿与焦点、浅／深色、窄屏及键盘可达性。使用合成本地文件和模拟服务验证，不向正式对话上传测试文件。

## 实施结果（2026-10-18）

窗口捕获文件拖放并阻止文件导航，只有聊天接收区可添加附件。复用原有图片准备、PDF 提取、上传与文档解析；设置／搜索等模态、侧栏、原位编辑、离线和上传期间不接收背后文件。普通文本／链接拖动保持原生行为，文件夹给出提示。

混合批次逐文件处理，失败只清理该文件并继续后续有效文件；失败提示与目标对话绑定，创建新对话后的路由切换不再清空它。合并草稿时读取最新草稿，保留上传中输入和移除操作；对话切换／退出中止上传，迟到结果不跨对话。新建附件对话不主动聚焦输入框、不自动发消息。

两项 Chromium 回归覆盖图片＋文本混合、嵌套拖入／离开、草稿和焦点、无自动发送、无效＋有效文件部分成功、模态禁止、默认导航和普通文本拖动。既有附件与联网场景继续覆盖参数校验、点击上传和新对话工具设置。触屏保留原文件选择器，本轮不声称已在真实 iOS 上完成文件拖放测试。
