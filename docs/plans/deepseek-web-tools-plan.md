# DeepSeek Search／Fetch 接入计划

日期：2026-10-18。状态：已核对官方文档与现有实现，待实施。本轮不修改运行时代码，也不发起真实计费请求。

## 目标与接入位置

把 DeepSeek 作为「联网」设置中的第二个服务，与 Tavily 并列。继续向模型提供 `web_search` 和 `read_webpage`，沿用 Conversation DO 执行、Workflow 有限编排、工具来源展示及后台续跑。它是独立 HTTP 工具服务，不要求聊天模型也选择 DeepSeek；使用其他供应商的模型仍须支持工具调用。

不把 Search／Fetch 当作 OpenAI Chat 的额外参数，也不新增另一套 Agent 框架。有限轮数、取消、检查点、私有续接和来源引用规则继续使用现有实现。

官方依据：[使用指南](https://api-docs.deepseek.com/zh-cn/guides/search/)、[Search Reference](https://api-docs.deepseek.com/zh-cn/api/search/)、[Fetch Reference](https://api-docs.deepseek.com/zh-cn/api/fetch/)。以下接口事实以查阅日期为准。

## 请求与结果映射

两个请求均由 DO 向固定的 `https://api.deepseek.com` 发送 POST JSON，使用 DeepSeek Bearer 密钥。

| EverChat 工具  | 接口               | 首期请求                                   | 统一结果                                                                      |
| -------------- | ------------------ | ------------------------------------------ | ----------------------------------------------------------------------------- |
| `web_search`   | `/v1/tools/search` | `query`、`count: 5`、`need_content: false` | `results[].title/url`；模型正文优先 `summary`，为空时回退 `snippet`           |
| `read_webpage` | `/v1/tools/fetch`  | `url`                                      | `title/content`，来源 URL 使用本次请求 URL；空标题回退域名，正文保持 Markdown |

Search 默认不索取整篇网页；需要细读时由模型再调用 Fetch。这样减少响应体、SQL、上下文与后续模型输入消耗。暂不保存站点图标、评分等未展示字段，也不下载远程图片。空搜索结果是正常完成；Fetch 没有正文是明确的工具失败。

DeepSeek 查询最多 128 个 Unicode 字符，而现有工具允许 500 个 UTF-16 码元。工具定义和执行前验证都应依据已固定的服务生成约束；DeepSeek 使用 Unicode 码点计数，不能直接以 JS `length` 代替。超长查询要求模型缩短，不静默截掉 `site:`、引号等语法。服务专属校验在额度认领、外部请求之前完成。

首期不传可选的 `ori_question` 和 `localization`，不额外发送完整原问题或客户端 IP。Fetch 接口允许更长 URL 和 HTTP，但首期保留 EverChat 现有公开 HTTPS 校验及 2,048 字符边界；是否放宽 URL 长度作为独立调整，同时检查模型定义、8 KiB 工具参数预算与来源 schema。

## 设置、密钥与任务固定

当前 `shared/web-tools/service.ts`、`worker/web-tools/settings.ts` 及前端均写死 Tavily，设置表只有一行密钥。改为：

- 已知服务枚举 `tavily | deepseek`；每种服务独立保存密钥，空间选择一个当前服务。首期不增加任意自定义 API 地址或自动故障转移。
- 「联网」Tab 增加服务选择，沿用自动保存、显式查看／清除密钥。切换服务保留两边已填配置，绝不把 Tavily 密钥随服务名称改成 DeepSeek 密钥。
- 查询接口返回当前服务、各服务的 `hasApiKey` 和公共用量；显式密钥读取须指定服务。保存只更新指定服务；切换 Tab、关闭设置或退出仍隐藏密钥，迟到响应不得恢复它。
- 搜索密钥独立配置，可以由用户手填与模型相同的 DeepSeek Key；不根据模型名称、兼容协议或任意代理地址自动复用聊天密钥。
- 接受任务时固定服务、密钥及预算；后台执行不读取「当前选择」来改换服务。更换服务不改变已经接受的任务。
- 现有 Tavily 配置原地迁入按服务存储的结构，保留已配置密钥和偏好；更新内部 schema，不维护两套长期兼容格式。

沿用现有 UTC 每日尝试额度，切换服务不清零，认领仍按调用身份幂等。它属于已有的可见费用控制，不另加一个隐藏的应用配额。后续若分服务统计，可增加展示计数，但不能让切换服务绕过已保存的全局额度。用户设置降低预算后继续按现有规则作用于在途任务。

## 错误语义与费用

DeepSeek 的错误码不能直接套用当前 Tavily 的字符串分类。尤其 Fetch 的 403 是网页被安全策略拒绝，不应显示成 API Key 无效。[错误与计费依据](https://api-docs.deepseek.com/zh-cn/guides/search/)

| 情况                      | EverChat 行为                                                    |
| ------------------------- | ---------------------------------------------------------------- |
| 400／413 或本地参数不合法 | 显示查询或参数问题；允许剩余模型轮次修正，不原样重发             |
| 401                       | 明确提示 DeepSeek 密钥无效，结束任务并提供服务设置入口           |
| 402                       | 明确提示 DeepSeek 余额不足，结束任务                             |
| Fetch 403／404            | 报告网页受限／无可用正文，允许模型解释或在剩余预算内选择其他来源 |
| 429                       | 显示服务限速，结束本任务，不进行后台重试风暴                     |
| 408／5xx／本地超时        | 显示服务超时或临时失败；保留已保存内容，不自动重复未知结果的请求 |

公开错误包含服务、HTTP 状态、可安全展示的错误代码及可重试提示。未知上游错误体、凭据和私有续接内容不直接展示；替换依赖错误文案相等判断是否结束任务的逻辑。官方虽建议对临时失败稍后重试，首期仍保持 EverChat 的外部调用自动重试次数为零，用户可以主动重新尝试。

查阅时中文指南列出 Search 和 Fetch 各为 **5 元／1,000 次产生有效结果的成功请求**，各自账号级 **5 QPS**。EverChat 的保守尝试计数包含失败和未知结果，不能当供应商收费次数。针对 Claude Code／Codex 的限时优惠不适用于本项目直接调用，不承诺这部分免费。[官方价格及限速](https://api-docs.deepseek.com/zh-cn/guides/search/)

首期对并发突发以明确的 429 结果收束，不增加隐藏次数配额。若后续需要排队，应按服务账号协调短期请求，而不是为每把 Key 各分配 5 QPS；其他应用也可能共享该账号，EverChat 不能保证掌握全部可用吞吐量。

## 免费层约束

复用现有 15 秒单次取消期限、最多五个来源、合计 12,000 码元、64 KiB 持久化结果、有限模型／工具轮次。先通过摘要搜索降低流量，不随接口最大返回条数放大本地预算。

现有 JSON 原始响应上限为 512 KiB。Fetch 可能返回较长页面；首期必须明确区分「响应超过读取预算」与无正文，不能返回模糊连接失败。用模拟长网页测量后再决定是否单独放宽 Fetch 读取预算，不能无限 `response.json()`。

不在普通 HTTP Worker 中添加浏览器、DOM 解析器或网页代理；固定服务完成抓取，DO 验证、裁剪和归一化结果。每个工具仍只认领一次额度、发起一次请求、保存一次结果；不增加每 Token 写入、常驻轮询或每秒 Alarm。网页文本只作为不可信引用，不能改变工具权限。

## 实施顺序与验收

| 阶段              | 修改位置与结果                                                                                          | 验收门槛                                                                                               |
| ----------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1. 服务设置       | `shared/web-tools/service.ts`、`worker/web-tools/settings.ts`、`routes.ts`、Library RPC、前端设置与缓存 | 切换保留配置；密钥不串用、不落本机缓存；现有 Tavily、每日用量与自动保存不回归                          |
| 2. 适配层         | 将 `worker/web-tools/service.ts` 拆成共享请求／响应保护与 Tavily、DeepSeek 两个适配器                   | Search 摘要与 Fetch Markdown 正确归一化；固定 origin；拒绝重定向；空结果、超量、Unicode 参数及取消正确 |
| 3. 工具协议与编排 | `worker/providers/tool-turn.ts`、Conversation DO、工具错误结构、前端失败展示                            | 查询长度定义与服务验证一致；403／402／429 等语义正确；旧任务固定原服务；不重复执行未知请求             |
| 4. 场景回归       | 单元、原生 workerd、Chromium／WebKit 与文档                                                             | 四种模型协议、后台无客户端、重启、取消、离线队列、服务切换、全局额度并发、复制／备份与私有数据隔离     |
| 5. 真实验证       | 用户明确选用的 DeepSeek 测试 Key 和公开页面，最小 Search＋Fetch 请求                                    | 记录实际响应、耗时与调用数；不读取私人页面，不将密钥或完整响应写入测试报告                             |

推荐先做[对话容量修复](conversation-storage-capacity-plan.md)中的诊断与日志整理，再上线真实联网服务，避免新增工具使用进一步触发现有存储保护。两项的单位测试和适配设计可以独立准备。
