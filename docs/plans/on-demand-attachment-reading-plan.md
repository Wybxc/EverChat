# 文本附件按需读取计划

日期：2026-10-31。状态：已实施，本地验收及生产离线升级校验完成。发布与验收证据见[执行记录](../measurements/on-demand-attachments-2026-10-31.md)。

关联：[MCP 附件](mcp-attachments-plan.md)、[上下文可见性与讨论记录](mcp-discussion-observability-plan.md)、[免费层资源政策](../architecture/free-tier-resource-policy.md)、[离线存储迁移](../operations/offline-storage-migration.md)。

## 目标与范围

让模型在处理长文本附件时，先获得文件清单，再通过工具选择性读取原文。文件不必整体进入模型上下文；读取内容、版本、范围和实际提交情况能够追溯。网页聊天和 MCP 发起的聊天使用同一实现，客户端离线后仍能执行。

核心只提供三个模型工具：`attachment_info`、`attachment_read`、`attachment_search`。所有合法文本使用相同的位置与分页模型，不依赖标题、日期、表格字段或业务记录结构。同时放宽附件格式限制，将 HTML 等文本格式按原始文本接入全文／按需输入，不再依靠一份封闭的扩展名白名单决定是否可读。

本计划不增加 HTML 选择器提取、按业务字段聚合、任意代码／Shell 执行、OCR、向量知识库或新的 Agent 平台。PDF 继续先提取文本；图片输入保持现有路径。工具处理的是已固定的文本版本，不承诺理解未提取的图片、版式或扫描页。

这三个名称属于 **EverChat 调用供应商模型时提供的工具**。MCP 调用者通过现有聊天接口选择附件输入方式；首期不因此新增三个对外 MCP 工具，已有附件元数据／原文读取接口继续服务自动化客户端。

## 从实际 session 抽取的通用模式

用户提供的 DSH 日志包含 11 次 Shell 工具调用，操作顺序可归纳为：

1. **了解规模**：检查大小，判断全文是否适合直接阅读。
2. **局部探查**：读取开头和少量片段，理解内容形态。
3. **跨位置浏览**：查看首尾和分散片段，避免只看到开头。
4. **定向定位**：一次或多次搜索关键词，取得相关位置。
5. **补全原文**：读取命中周边及较长片段，再决定下一步。

日志中的 HTML 正则、年份分组、记录长度筛选是任务专属算法，不提升为通用工具要求。日志也显示了重复全文读取、手写清洗破坏原文、将未知日期归入指定年份，以及抽样后声称读完全文等问题；工具需要提供可靠的位置和证据，不能替模型推断内容含义。

压缩包只包含日志，不包含原始 HTML。提取数量不能独立核验；计划不收录其中的私人正文，也不将该日志或原文件提交到仓库。验收使用合成文本。

## 放宽文本附件格式限制

### 分类依据与格式范围

当前限制涉及 `shared/attachments/files.ts` 的扩展名映射、`shared/attachments/documents.ts` 的媒体类型校验、网页多个文件选择器与上传入口，以及 `scripts/mcp/upload.ts` 的扩展名拒绝逻辑。实施时一并调整，不能只修改文件选择器。

将“原文件的格式”和“模型输入的处理方式”分别记录。文本统一进入通用文本读取管线；保留原文件名、声明 MIME 和格式提示，供展示、下载及模型理解使用。内部可以将普通文本输入归一为 `text/plain`，不必为每个代码语言扩展整个上传／消息 schema；Markdown、CSV 和 PDF 继续保留确有行为差异的元数据。

优先识别已支持的图片和 PDF 专用路径，其余候选文件按文本验证。扩展名和 MIME 只帮助选择处理方式，不代替完整内容校验，也不要求两者总是一致：浏览器常返回空 MIME 或 `application/octet-stream`。

首期明确覆盖以下类别，但这不是新的封闭扩展名白名单：

- HTML／HTM／XHTML、XML、SVG 等标记文本，保留标签、属性和脚本源码。
- JSON／JSONL／NDJSON、YAML、TOML、INI／CONF、日志、SQL 等数据与配置文本。
- 源代码、脚本、CSS、Markdown、reStructuredText、TeX／BibTeX、Typst 和普通文本。
- 无扩展名文件、点文件、未列出的文本扩展名；允许经“作为文本”路径上传并验证，而不是先要求改名为 `.txt`。

`text/*` 以及常见的 JSON／XML 等 `application/*` 文本 MIME 共用分类规则。未知或通用二进制 MIME 可以进入候选文本验证，不能仅凭声明把任意二进制文件标为文本。保留现有严格 UTF-8、控制字符和工作集校验；首期支持 UTF-8／UTF-8 BOM，遇到 UTF-16、GBK 等编码明确要求转换，不用替换字符或启发式猜测静默损坏原文。编码转换如后续支持，应保留原文件并创建有明确编码依据的派生文本版本。

JSON 语法、HTML 完整性或 CSV 列数并不是普通文本可读性的前提。CSV 格式检查可继续提供结构化元数据和诊断，失败只影响该增强信息，不妨碍把合法 UTF-8 原文交给通用文本工具；不为了读取文件而要求内容符合其扩展名对应的业务语法。

### 所有入口使用同一规则

网页附件对话框、聊天框文件选择、拖放、MCP 批量准备／小文件上传以及 `scripts/mcp/upload.ts` 共用分类和归一化模块。移除多处硬编码的扩展名拒绝逻辑；文件选择器保留常用类型便利过滤，同时有选择所有文件的路径，移动端也不能被 `accept` 限死。文件类型不确定时提供“作为文本”入口，由内容校验确认，错误说明具体是编码、二进制内容或资源边界。

确定的归一化媒体类型在签发 PUT 前固定，预签名请求头、登记数据、上传和 HEAD 接收保持一致。原始 MIME 作为描述信息保存，不改变签名后请求头；同一请求的处理方式和原始元数据进入幂等指纹。保存原文不增加渲染依赖或 Worker 上的 DOM／语言解析开销。

### HTML 等格式的展示与模型输入

HTML、SVG、XML 和脚本文件均以转义后的源码预览，模型收到相同文本，不渲染为网页、不执行脚本、不加载外部资源，也不自动去除标签。附件内容继续作为参考资料传递，不能成为系统指令。

附件预览与读取响应使用明确的纯文本类型和禁止 MIME 嗅探的响应头；原文件下载使用附件下载语义，避免用户上传的 HTML／SVG 在 EverChat 同源环境中作为活动文档打开。R2 对象保持私有，既有分享及缓存边界不变。该行为只针对附件，不影响应用自身 HTML 入口或聊天 Markdown 渲染。

## 文件身份、坐标和输入方式

### 不可变文本版本

每次运行固定附件 ID、原文件哈希、文本哈希和索引格式版本。相同文件名不代表相同内容；替换文件仍创建新版本。工具位置、游标、缓存和回执都绑定文本版本。

所有范围使用 **UTF-8 字节偏移，起点包含、终点不包含**。工具结果给出可直接复用的位置句柄；行号、PDF 页码只是映射和展示坐标，不与现有 UTF-16 消息分页偏移混用。

文本保持固定版本中的原样内容，不新增 `trim`、换行标准化、HTML 标签清洗或 Unicode 归一化。普通文本与 PDF 派生文本均以其文本哈希确定读取对象，不能拿原文件哈希替代。编码、BOM 和换行计数规则在实现阶段写入契约并通过往返测试固定。

### 三种输入方式

网页与 MCP 均支持每个文本附件选择 `auto`、`inline`、`on_demand`，默认 `auto`。每次运行的最终决策固定下来，不在工具执行期间因设置变化切换版本或模式。

| 方式        | 行为                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------- |
| `inline`    | 全文或用户明确选区进入初始输入；超预算明确拒绝，不静默截短或换模式                           |
| `on_demand` | 初始输入只有文件清单与读取说明，原文由工具返回                                               |
| `auto`      | 综合已知上下文余量及实测后的软阈值，短文件全文输入，较长文件按需读取；界面和回执显示实际选择 |

`auto` 的切换阈值是体验策略，不是文件容量限制；阶段 A 测量后确定。多文件按整体预算选择，避免每个文件单独看起来能放下、合计却溢出。未知模型窗口不恢复猜测性的硬上限；回执明确估算依据。

模型明确不支持工具时禁用 `on_demand`；`auto` 在全文能容纳时使用全文，不能容纳时提示选区或更换模型。能力未知时允许按现有模型能力策略主动尝试，失败明确报告，不假装文件已传入。按需读取与网页搜索分别启用，关闭联网搜索仍可读取附件，附件工具也不要求联网服务密钥。

文件清单由本次分支、有效材料版本及统一上下文选择生成。同一版本去重；`include_both` 仍保留两个明确版本。模型不能因为知道其他附件 ID 就扩大本次可读范围；提供选区的文件只开放该选区。普通历史附件、摘要来源和固定材料哪些仍可读取，要在清单中明确，不能从全空间枚举。

## 三个工具的契约

以下是拟定语义，实施时使用共享 schema 生成 SDK 和 MCP 文档需要的类型，避免不同协议维护不同参数定义。

### `attachment_info`

按本次清单中的一个或多个附件引用，返回文本版本、名称、媒体类型、字节数、字符数、行数、可用页码映射和文本准备状态。已在初始清单中的基础字段不必再次调用获取；大清单沿用有界分页。

行数和位置索引在文本准备时生成，查询信息不扫描全文。字符数与 Token 估算使用明确的方法标记，不把文件大小换算值当成供应商实际用量。不保证所有文本都有章节目录；不存在的结构返回不支持或未知。

### `attachment_read`

输入指定文本版本，以及下列一种定位方式：

- 一个或多个字节范围／位置句柄；已知行号或页码可先由同一工具映射。
- 前次返回的续读游标。
- 等距抽样：指定片段数和每段期望大小，服务端按可读范围计算互不重复的位置。抽样依据是文本位置，不是业务记录或统计代表性。

允许请求输出预算；实际返回量受本轮剩余上下文、序列化工作集和单次读取预算共同约束。批量范围排序、合并相邻 R2 读取，但返回时保留各请求的来源和边界。不得先加载全文再做 `slice()`。

结果包含实际范围、原样文本、文本哈希、行／页坐标（如可用）、估算 Token、未满足范围、`hasMore`、`nextCursor` 和截短原因。因输出预算切断片段时明确标记，继续读取能无缝覆盖剩余原文。空范围、读到末尾、来源不可用和游标失效是不同状态。

所有读取均处理多字节字符边界；一个极长单行不能绕过工作集边界，也不能因此被当作不可读取的文件。行号定位从稀疏索引附近开始，长行内继续通过字节范围和游标读取。

### `attachment_search`

输入指定一个或多个可读文本版本、带 ID 的字面量模式数组、可选范围、结果形式和输出预算。多个模式一次扫描，分别返回结果，避免为每个关键词重读一遍文件。

首版采用大小写敏感的精确字面量匹配。模式按字节／Unicode 的既定契约匹配并返回原始坐标，不做语义扩展、Unicode 归一化或模型分类。空模式拒绝；重叠匹配是否计数在契约中固定。任意 JavaScript 正则不进入首版，后续确有需求时单独评估线性时间实现及坐标映射。

结果形式包括：

- `snippets`：命中位置及有界前后文，相邻片段合并，保留各模式的命中位置。
- `positions`：只返回定位结果，供后续批量精读。
- `count`：统计指定范围内的精确匹配数量，不返回全文。

严格区分两种分页：

| 状态             | 含义                                         |
| ---------------- | -------------------------------------------- |
| `scanComplete`   | 指定范围是否全部扫描完成                     |
| `hasMoreResults` | 是否还有已经发现、但本页尚未返回的结果       |
| `nextCursor`     | 后续扫描或结果分页的游标，语义由结果状态标明 |
| `matchesFound`   | 已扫描范围内发现的数量；未完成时仅为下界     |
| `totalMatches`   | 仅扫描完成且计数精确时给出，否则为 `null`    |

默认片段搜索可在取得足够结果后返回可续扫的位置；完整计数需要遍历整个指定范围。工具不能因本页没有命中就声称全文没有命中。跨存储块、换行和 UTF-8 分片的匹配不能遗漏或重复。

## 存储与预处理

### R2 与 DO 分工

- **R2**：保存原文件、不可变提取文本及按需读取的稀疏索引。保持文本大对象，使用 Range GET 读取；不为每行创建一个对象。
- **Library DO**：保存已授权附件与版本、文本／索引对象引用、摘要元数据、准备状态及清理租约。索引按需分页读取，不把大索引塞入一行 SQL。
- **Conversation DO**：固定本次清单、模型工具许可、幂等状态、执行进度、规范工具结果及输入回执引用。
- **有界执行器**：执行实际范围读取和字面量扫描，调用纯算法处理单批文本；不在共享 Library DO 中执行长期全文扫描。

索引按可配置的字节间隔记录最近的有效 UTF-8 起点、行号和必要的页码映射。索引步长在阶段 A 根据读放大与索引大小实测确定。索引本身也是有版本、有哈希的派生对象；稀疏定位后最多扫描一个有界局部区间，遇到超长行使用字节游标。

### 一次准备，多次读取

新文本在正常上传处理期间增量验证 UTF-8、计算哈希、计数并生成索引，全部对象可靠保存后原子标为可读。失败、实例重启和删除沿用租约及清理机制，不留下已就绪但索引缺失的引用。

普通文本的按需路径不再依赖整包 `arrayBuffer()`／解码／估算；当前 32 MiB 整包工作集保护不直接成为该路径的新文件容量上限。仍遵循现有单次上传政策。CSV 的可选格式诊断使用增量接口并保留真实工作集保护，CSV 行不被通用文本工具误当作业务记录；诊断失败不阻断原文读取。PDF 继续使用现有客户端提取流程，其提取工作集边界不因按需读取自动消失。

全文件哈希在准备阶段计算；读取时使用固定版本、对象校验元数据和条件读取确认对象身份，只对本次片段计算回执需要的哈希。不能为了读取几 KiB 再下载全文校验。部分读取的校验结果也不能表述为本次重新校验了全文件。

缓存以文本版本和规范参数为键，有界且可丢弃；丢失只影响性能，不影响正确性或权限。首版不建立全量倒排／向量索引，不把正文复制到 SQL 再进行 `LIKE` 全表扫描。若实测显示重复搜索成为主要成本，再独立评估精确搜索索引的存储放大、中文匹配及维护代价。

## 执行、调度与免费层边界

### 泛化现有工具链

将当前偏联网专用的名称、参数／结果 schema、能力检查、任务 journal、供应商定义及公开展示收敛到通用工具层，联网和附件保持各自服务实现。继续使用 AI SDK 的工具定义、参数校验及原生工具消息转换，保留已有供应商私有推理／签名续接规则，不再增加另一套协议解析器。

附件调用先固定本次授权范围和文本版本，再执行只读操作。相同调用 ID 与参数重试返回同一规范结果；DO 重启、扫描重试或编排重放不重复计入结果，也不重新请求模型。

### 内部批次不成为模型轮次

范围读取优先在一个有界任务内完成。搜索按扫描字节、模式规模、输出体积和剩余期限拆成批次；游标记录固定输入、当前位置、跨块匹配状态及已完成结果引用。跨块状态有界，不能把扫描前缀存入游标。

内部扫描批次沿用现有工具任务编排推进，同一已认领调用在等待期间保持 `running`。**只有一个逻辑工具调用完成、失败或返回明确的部分结果后，才启动下一轮模型**，不要求模型为每个存储块反复调用工具。

复用现有 Workflow 根任务，不为每个片段创建独立 Workflow。步骤只传小型状态及引用，正文和大结果不进入步骤返回值。每批结束持久化必要检查点，不逐行／逐命中写 SQL；内部批次、停止和超时必须能从同一任务日志恢复。具体采用受限 Worker 调用还是文件处理 DO 的执行方式，由阶段 A 平台测量选择，并记录依据。

整文件处理不放在普通 HTTP Worker 的一次长 CPU 循环里。停止、删除或根任务超时后不再调度新批次；保留已经可靠保存的结果，返回扫描覆盖范围和未完成原因。不能因为范围读取通常很快，就直接套用联网请求的 15 秒超时与供应商错误分类。

### 预算与测量依据

2026-10-31 核对：普通 Workers Free HTTP 请求 CPU 为 10 ms，isolate 内存为 128 MB；R2 支持范围读取；DO 另有调用、SQL、存储与执行限制，不能将不同执行入口的 CPU 预算混用。依据：[Workers 限制](https://developers.cloudflare.com/workers/platform/limits/#cpu-time)、[DO 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)、[R2 API](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/#ranged-reads)。

每批扫描量、索引步长、缓存大小和读取并发均为调度预算，阶段 A 根据实际 CPU、峰值内存和 R2 操作数确定，不新增每文件总读取次数、累计扫描字节或对话容量配额。流式扫描只限制工作集，完整搜索仍有线性扫描成本，不能据此承诺任意大文件都能在当前工具任务期限内搜完。

测量包含 R2 读取／写入数、DO SQL 行读写、持久化字节、普通 Worker 与 DO 各自 CPU、活跃时长、重启成本和模型工具往返次数。分开记录冷缓存、热缓存、无命中、密集命中及多关键词，并与现有全文输入对照。性能验收绑定代表性负载和实际套餐；本地通过不等于免费层通过。

## 上下文、压缩和后续对话

1. 初始预算按实际内联文本、去重后的可读清单、工具定义、系统提示和选中历史计算。工具定义按本次实际定义估算，不继续用联网专用的固定预留代表新增工具。
2. 每次工具执行前计算剩余返回预算，同时为工具协议封装、已保存的供应商私有续接和后续生成保留已配置的预算。这个返回预算不转换为新的供应商输出上限；未配置的输出预算保持未配置。
3. 工具结果实际编码后再次校验。若有剩余可读空间，返回较短片段和续读位置；协议必要内容也无法容纳时明确结束或要求调整上下文，不静默丢弃当前问题和材料。
4. 首版沿用工具过程的完整续接规则，不在同次生成中任意删减旧 tool call／result 或签名。接近窗口时提供可读的停止原因并保留部分回答。后续如增加同次任务压缩，必须单独验证四协议的调用配对、签名和来源证据，不将 SDK 的通用裁剪函数直接用于私有续接。
5. 后续普通提问继续发送已选择的用户／助手正文和可读文件清单，不自动重放之前所有工具原文；模型需要时重新读取。回执区分上次曾提交与本轮仍携带，避免把历史阅读记录当作当前上下文。
6. 历史压缩只处理真正纳入摘要输入的消息与片段，不为了摘要偷偷加载按需附件全文，也不声称摘要覆盖未读资料。哪些文件仍可重新读取，以本次有效清单为准。用户输入本身过长时仍走现有预算处理，本功能只解决附件的输入方式。

按需读取不能让模型无限记住已读内容，也不能保证抽样足以回答要求通读的问题。工具说明应要求模型如实说明检索／抽样范围；系统证据只声明实际读取和提交，不以模型自述确认完整阅读。

## 输入回执、展示与现有功能

### 三层证据

| 证据       | 记录内容                                         | 不能据此声称                         |
| ---------- | ------------------------------------------------ | ------------------------------------ |
| 可读取     | 本次许可清单、版本、范围、输入方式               | 文件全文已经传给模型                 |
| 工具已产出 | 调用、扫描覆盖、返回范围、片段哈希、规范结果引用 | 结果已经随下一步请求提交             |
| 已尝试提交 | 模型步骤引用、实际携带片段、估算 Token、请求指纹 | 供应商完整接收、模型理解或仍记得全文 |

规范工具结果只持久化一次，后续步骤通过引用描述携带关系；不为每个模型步骤复制相同片段，不把原始扫描过程变成同步事件数据库。仅为扫描而读过但未返回给模型的内容，不能计入已提交范围。覆盖率按指定文本版本的范围并集计算，不能用命中条数或抽样条数推算完整阅读率。

网页在现有思考／工具过程中紧凑展示“读取文件第…行”“搜索文件”，详情列出实际范围、状态及片段；无需新增常驻面板。文件卡片展示自动／全文／按需的实际状态，配置入口放在现有附件详情内。界面词条进入现有 i18n，遵循现有 shadcn/Base UI、可访问性和移动端交互规范。

MCP 的 `everchat_chat` 扩展附件输入方式，`everchat_help` 和能力发现解释读取行为；`everchat_run_context_get` 返回相同证据。沿用 `reuse`／`replace`／`include_both`、分支和幂等规则；新模式必须进入请求指纹。运行中状态包括正在读取／扫描、处理字节和最后进展时间，避免长搜索表现为无进展的模型生成。

复制、备份和恢复包含不可变文本、清单和索引；派生索引可由显式离线操作重建，恢复不能留下看似可读的失效索引。删除按存活版本引用回收对象，正在读取时可取消；删除后旧回执保留允许保留的哈希与来源状态，原文已不可取时如实报告。文件替换和分支切换不得让旧游标读取新内容。

公开分享沿用现有公开范围，不因答案使用过附件就暴露文件清单、全文、私有回执或读取接口。公开工具过程只展示分享策略允许的摘要；可公开的最终回答引用与私人读取位置分别处理。

## 离线迁移与发布

本功能新增清单／索引和输入方式，需要统一版本化存储与备份格式。历史派生文本通过本地运维工具读取备份、生成索引和元数据后，在维护窗口批量应用并校验，记录变更对象和回滚依据。未显式设置输入方式的历史消息使用自动模式，保留已有材料版本与选区语义；新请求按当前预算选择全文或按需输入，不改写历史消息。

不在普通网页请求、生成、工具调用或客户端启动中探测旧结构并自动建索引，不提供“缺索引就下载全文”的兼容回退。历史索引生成属于离线迁移；新上传的正常文本准备属于业务处理，两者明确区分。索引丢失返回准备／维护状态，经显式修复流程处理，不偷偷触发在线回填。

通过 PR 必需检查后再合并；生产先完成离线升级，再部署对应代码并验证已有对话可读、新旧附件能按预期使用。测量和真实供应商冒烟按既有授权及隔离资源规则执行，不因本文已形成计划就视为获准创建云资源或调用真实模型。

## 验收矩阵

- **通用文本**：中文、emoji、组合字符、LF／CRLF、空行、末尾无换行、单行超过单批预算、代码、Markdown、CSV、JSONL 和 HTML 原始文本。相邻续读拼接与原文本逐字节一致，抽样位置可复现且不冒充代表性样本。
- **格式与入口**：HTML／XHTML／SVG／XML、未知扩展名、无扩展名、点文件、大小写后缀、空／通用／不一致 MIME、UTF-8 BOM、非 UTF-8 和伪装文本的二进制文件；网页选择、拖放、MCP 及辅助脚本分类一致。HTML／SVG 预览与下载不执行内容、不发起内含资源请求，CSV 等语法不完整但合法的文本仍可读取。
- **定位与搜索**：首尾、多范围、范围重叠、行页映射、跨批次模式、模式自身重叠、无命中、密集命中、多关键词、完整计数及输出分页。扫描未完成时 `totalMatches=null`，最后一个字符的命中不丢失。
- **内存与资源**：以不同大小、行长和模式规模的合成文件测量；相同片段读取的下载字节与所读片段及索引有关，不随全文线性增长。完整搜索按输入长度增长，并记录读放大和检查点开销。
- **执行恢复**：DO／执行器重启、R2 错误、条件读取失败、重复认领、停止／删除、根任务超时及客户端关闭。内部批次不增加模型请求数，未完成计数／片段状态正确。
- **上下文**：多文件、显式选区、固定材料、替换／并列版本、摘要、分支、重新生成和回答继续；没有全文与按需结果双重注入。长工具交换耗尽预算时留下明确终态与可靠部分回答。
- **供应商与证据**：OpenAI Chat、Responses、Anthropic、Gemini 的工具参数、原生结果、私有签名及流式过程；回执中的清单、返回片段和逐步提交与捕获的实际请求一致。来源删除后不伪造原文。
- **权限与生命周期**：越过本次清单／选区、跨对话／Key、旧版本游标、缓存命中后的撤权、复制与恢复、R2 部分写入清理；公开分享和 SW 缓存不会泄漏私人附件结果。
- **界面与自动化**：Chromium／WebKit 的流式滚动、折叠过程、模式设置、刷新恢复和移动端；MCP 上传三步流程无需增加确认调用，`help`、进度、回执与重试语义一致。

本计划的完成标准是放宽文本格式、三个工具、统一输入方式、可恢复执行和真实回执形成闭环，并有对应平台负载证据；不以模型能回答一个样例或本地测试通过替代资源与上线验收。

## 本次实现参数

普通文本超过 1 MiB 使用增量 UTF-8 验证与索引；索引步长 64 KiB，单次范围预览 8 KiB，扫描批次 256 KiB，单次工具正文工作集最多 48 KiB，并受本次上下文和返回预算进一步缩小。Workflow 每个步骤最多推进 16 个 DO 批次，单个模型工具不因内部批次增加模型轮次。

自动模式优先保留显式全文输入；自动文件超过 8,192 个估算 Token 或不适合剩余预算时使用按需方式。此阈值是输入策略，不是文件容量限制。已知不支持工具的模型保持全文路径，显式按需会返回明确错误。

文件准备计算内容哈希以固定版本；范围读取不重新扫描全文。R2 直传的原始对象可能没有 checksum 元数据，只在它已经通过完整内容校验且保持不可覆盖时允许复用。派生对象仍核对保存时的校验元数据，读取片段单独提供内容哈希。

当前批量参数已通过本地正确性与工作集检查；真实 Cloudflare CPU、冷／热缓存和账户额度对照仍需平台测量，纳入既有[资源排查](sync-worker-resource-investigation-plan.md)。不得将本地耗时当作免费层 CPU 验收。
