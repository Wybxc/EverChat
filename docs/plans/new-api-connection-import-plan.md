# new-api 连接信息导入设计

日期：2026-10-20。状态：设计完成，待实施。

## 目标

用户在 new-api 的「API 密钥」页面选择「复制连接信息」，回到 EverChat 的「设置 → 供应商」粘贴，即可预览并创建供应商，随后获取、勾选模型。减少分别复制地址和密钥的操作，沿用现有协议、模型与自动保存体系。

本次仅设计功能，不修改业务代码。第一阶段支持单个供应商导入；无需数据库迁移、外部插件或 new-api 管理员账号。

## 已核实的数据格式

new-api 官方[连接信息编解码源码](https://github.com/QuantumNous/new-api/blob/main/web/src/lib/channel-connection-info.ts)定义了 JSON 格式：

```json
{
  "_type": "newapi_channel_conn",
  "key": "sk-example-placeholder",
  "url": "https://relay.example.com"
}
```

这是连接参数，不是完整的供应商配置：其中没有名称、模型列表、协议、模型能力或计费价格。官方[API 密钥文档](https://github.com/QuantumNous/new-api-docs-v1/blob/main/content/docs/zh/guide/feature-guide/user/token.mdx)说明用户可从密钥行菜单复制这段信息。

EverChat 独立实现数据识别与映射，复用自身的 JSON／Valibot 校验，不复制 new-api 实现代码或引入其依赖。

## 入口与交互

供应商列表的新增操作旁增加「导入」按钮，打开紧凑弹窗。第一屏仅显示「粘贴连接信息」输入框、可选的「从剪贴板粘贴」按钮和取消操作。也允许在该专用入口直接使用系统粘贴；读取剪贴板失败时仍能手动粘贴。打开设置或切回页面不自动读取剪贴板，不接管聊天输入框的普通粘贴。

识别成功后显示配置预览，原始 JSON 输入框收起但可重新编辑。名称、API 类型、API 基础地址可修改；密钥复用现有 `ApiKeyInput` 的隐藏／显示实现。名称默认取站点主机名，用户可修改，必须非空才能导入。显示必要提示：「确认后将保存到当前空间」。

预览底部提供「导入并获取模型」和「仅导入」。第一项只在用户确认后保存配置并获取模型，不自动发送模型测试或聊天请求。确认前取消不改变供应商列表；确认后的关闭不撤销已提交的保存，保存状态继续由现有设置页呈现。导入后定位新供应商详情，在模型列表中勾选要启用的模型；没有模型时保留现有手动添加入口。

弹窗采用现有 Dialog 和滚动容器，标题、关闭按钮与底部操作保持可达。关闭后将焦点交还导入按钮；成功后聚焦导入供应商的详情或模型列表。移动端不依赖横向并排布局，输入字号遵守项目的 iOS 防自动缩放规范。

## 字段映射与校验

| 输入／情况  | 规则                                                                                                                                      |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `_type`     | 必须精确等于 `newapi_channel_conn`；其他 JSON 显示「不是支持的 new-api 连接信息」。                                                       |
| JSON 根节点 | 必须是对象；拒绝数组、null、字符串、损坏 JSON。首尾空白可忽略，未知字段忽略，不执行其中内容。                                             |
| `key`       | 必须为非空字符串，去除首尾空白，复用现有密钥长度校验；不强制 `sk-` 前缀，也不增删前缀。                                                   |
| `url`       | 必须为非空字符串，复用供应商地址校验：HTTPS，不接受用户名／密码、查询参数、片段及具体调用接口路径。无效时留在预览内修正，不发送探测请求。 |
| 名称        | 默认使用主机名；可编辑且非空。新 UUID 在一次导入尝试中保持稳定，防止重试重复创建。                                                        |
| 协议        | 默认 `openai-chat`，明确是 EverChat 的默认选择，不宣称连接信息已识别协议；可切换到现有其他协议，切换不重置地址、密钥和名称。              |
| 模型        | 连接信息没有模型字段；不猜测模型名称，不自动启用所有模型。复用获取／手动添加、显示名和能力配置流程。                                      |
| 其他设置    | 保留现有供应商、当前默认模型、系统提示词、标题模型和联网服务配置。新供应商导入不擅自切换已有对话模型。                                    |

### 基础地址处理

new-api 复制的是平台地址，而现有 OpenAI 兼容适配器使用 API 基础地址并自行追加 `/models`、`/chat/completions` 等路径。因此预览必须显示最终基础地址，防止漏掉或重复追加 `/v1`。

| 复制的地址                                      | 默认 OpenAI Chat Completions 的预览地址                             |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| `https://relay.example.com` 或末尾 `/`          | `https://relay.example.com/v1`                                      |
| `https://relay.example.com/v1` 或末尾 `/`       | `https://relay.example.com/v1`                                      |
| `https://relay.example.com/newapi`              | `https://relay.example.com/newapi/v1`，保留反向代理前缀，并允许修改 |
| `https://relay.example.com/v1/chat/completions` | 不直接接受，提示填写基础地址并让用户修正                            |

仅在首次识别连接信息时生成上述建议。非根路径的映射属于 new-api 常规路由推定，定制网关需由用户核对；路径大小写和前缀不能随意重写。用户手动编辑地址或切换协议后不再次自动补后缀，不跟随重定向尝试其他站点，也不枚举不同协议发送密钥。

## 重复与更新规则

在确认导入时重新读取当前设置，比较标准化地址、协议及完整密钥；密钥只用于内存比较，不显示在列表或日志中。

| 场景                           | 默认行为                                                                                                                                                                |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 相同地址、协议和密钥已存在     | 显示已有供应商名称，提供「打开已有供应商」，不新增重复项或修改现有配置。                                                                                                |
| 相同地址但密钥或协议不同       | 默认「添加为独立供应商」，名称冲突时补序号，支持同一中转站的不同令牌／分组。                                                                                            |
| 用户明确选择更新某个已有供应商 | 展示目标名称及将修改的字段，只替换确认的地址、协议和密钥；保留模型 ID、名称、启用状态、提示词及人工能力配置。连接发生变化时按现有规则清除来源已失效的目录／测试元数据。 |

首版先支持新增及精确重复识别；更新已有供应商可放到第二阶段，避免在首次交付中混入复杂覆盖操作。

## 保存与模型获取

预览是局部内存草稿，确认前不调用 `SettingsAutosave.update()`，也不写入本地草稿或后端。确认后将完整候选配置合并到当时最新的设置，走现有自动保存与 `flush()`；按钮提交期间禁用重复触发。正常编辑仍遵循自动保存。

现有获取模型接口需要已保存的供应商 ID，因此顺序为「保存供应商 → 确认保存成功 → 获取模型」，不为预览新增临时密钥代理接口。界面将保存结果与模型获取结果分开展示：

- 保存失败：保留草稿和同一 UUID，显示保存错误，允许重试；不请求模型。
- 模型获取成功：沿用现有合并策略，新增模型默认禁用，由用户勾选；不覆盖已存在模型的名称、启用状态或人工配置。
- 模型获取失败：显示「供应商已导入，模型列表获取失败」，保留配置，提供重试及手动添加。复用现有 HTTP 状态、响应正文和诊断详情，不将失败表示为整体导入未完成。
- 空模型列表：展示手动添加入口，不虚构模型。只在用户启用模型后，沿用现有空默认模型的选择规则。
- Access 过期／离线：保留当前页面内的导入状态，按现有重新登录／重试流程处理；不在匿名分享页提供入口。

## 密钥、架构与资源

解析在浏览器本地进行；只有用户确认保存后才提交给 EverChat 受 Access 保护的私有配置接口。获取模型时按现有架构由 Worker 携带密钥请求预览中确认的供应商地址。复用端点校验与禁止重定向规则。

原始连接信息和导入预览不写入 URL、分析事件、错误正文或日志；展示错误只指出出错字段，不回显原始 JSON。导入关闭后清理组件内存，不自动清空用户的系统剪贴板。配置持久化与密钥查看权限保持现有规则，导入不会改变整个应用的密钥存储策略。

无需新的数据库表、DO、Workflow、后台轮询或在线迁移。新增成本为一次现有配置保存，以及用户选择获取模型时的一次目录读取流程；不在导入阶段发起计费生成测试或价格／余额查询。

## 模块落点与实施顺序

1. 在 `src/features/providers` 增加独立连接信息解析与预览映射模块，返回结构化字段错误，校验复用 `shared/providers/settings.ts`；为真实格式及地址规则编写纯函数测试。
2. 新增 `ProviderImportDialog.tsx`，复用现有 Dialog、输入框和 `ApiKeyInput`；从 `ProviderEditor.tsx` 的供应商列表入口打开。文案加入供应商模块的简体中文／English 词条。
3. 将现有供应商模型获取、结果合并和错误呈现提取为可复用操作；接入保存成功后的模型读取，保留既有自动保存行为。
4. 增加新增、重复识别、失败重试与移动端焦点回归，完成使用指南。后续再扩展明确更新已有供应商，不在首版支持任意 JSON／文件批量导入或 URL 携带凭据。

## 验收标准

- 官方 JSON 格式可导入，原始站点地址最终只补一次 `/v1`，代理路径保留；自定义编辑不被自动逻辑重置。
- 错误类型、空字段、数组、无效 URL、HTTP、具体接口路径均在请求前报告；错误不含密钥。
- 确认前取消／关闭和精确重复不会新增配置；连续点击／失败重试不会生成两个供应商。
- 保存与模型获取的成功／失败独立呈现；获取失败后可保留供应商并手动添加模型。
- 模型仍通过多选框启用，已有配置与当前对话模型不受无关修改影响。
- 在粘贴／预览阶段没有网络请求或持久化；未启用 clipboard API 时仍可系统粘贴；iOS PWA 的字号、关闭与焦点路径可用。
- 单元测试、相关浏览器回归、`pnpm typecheck`、`pnpm build` 及格式检查通过。尚未执行这些实施验收，本次仅核实格式并完成设计。
