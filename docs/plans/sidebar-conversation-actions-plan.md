# EverChat 侧边栏对话状态与操作方案

状态：阶段 A 已完成，阶段 B、C 尚待实施。方案日期：2026-10-16，实施更新：2026-10-17。原始代码基线：`267dc54`。

目标：用户在侧边栏即可确认哪些对话正在生成，并对任意对话进行整理与任务操作。沿用现有 shadcn/ui、语义主题和紧凑单行列表。

本篇是[对话体验改进计划](conversation-experience-improvement-plan.md)的侧边栏专项设计；跨功能实施顺序以总计划为准。基础菜单和分组已实施，任务与 AI 标题入口仍按相应阶段接入。

## 1. 实施前基础

- `App.tsx` 的列表行已有标题、置顶标记和本机待发送圆点，尚无行菜单。
- `ConversationActions` 已实现重命名、置顶、归档、复制和删除，以及弹窗、校验与失败反馈；入口在当前对话顶部。
- `ConversationInfo` 只包含标题、时间、置顶和归档等信息，没有生成状态。`useLibraryIndex` 目前每 10 秒刷新列表。
- `useConversation` 只订阅当前对话的快照与 WebSocket；切换对话后无法继续从它判断其他对话的生成进度。
- `useOutbox` 保存本机待发送请求，服务端接受后移除；它不能代表已进入云端的后台生成，也不能代表另一设备发起的任务。
- `App.tsx` 的更新、删除和复制函数依赖 `selected`，需要改为显式传入目标对话 ID，才能安全复用到列表行。

## 2. 首期要增加的功能

### 对话状态提示

状态位固定在标题右侧，独立于置顶标记和菜单按钮，不增加第二行说明。

| 场景                           | 行内提示               | 规则                                                                                                 |
| ------------------------------ | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| 本机请求尚未确认接受           | 待发送                 | 包括离线排队及网络结果未知；不能提前标记为云端生成。                                                 |
| 本机投递明确失败               | 发送失败               | 沿用 outbox 的错误信息；进入对话后可以编辑或重试。                                                   |
| 云端任务已排队                 | 等待生成               | 只依据服务端已确认的任务状态显示。                                                                   |
| 云端任务正在执行               | 小型进度图标与“生成中” | 包括思考、工具调用和自动摘要链路；内部步骤切换不让标记反复消失。                                     |
| 停止请求正在处理               | 停止中                 | 对应任务确认终止后移除，失败保留真实状态并提供重试。                                                 |
| 断线或恢复中，只有旧的活跃状态 | 静态状态图标           | 通过必要的提示和可访问名称表达“生成状态待同步”，不把失联当成已完成，也不无限播放代表实时状态的动画。 |
| 无活跃任务                     | 不显示任务提示         | 不给所有历史对话长期增加“已完成”标签。                                                               |

生成状态属于整个对话，包含未显示分支中的任务。正文中仍沿用既有分支状态反馈。普通点击标题恢复该对话原来的阅读位置；通过菜单的“查看生成位置”才明确跳到生成分支。

### 对话行菜单

每行新增独立的“…”按钮。菜单始终绑定该行 ID，不能依赖当前打开的对话，也不通过先切换到目标对话来间接操作。

| 菜单项             | 显示条件                       | 行为                                                                                     |
| ------------------ | ------------------------------ | ---------------------------------------------------------------------------------------- |
| 置顶／取消置顶     | 所有已保存对话                 | 复用现有置顶排序，状态变化后更新列表。                                                   |
| 重命名             | 所有已保存对话                 | 复用名称弹窗、非空校验和 80 字上限；失败保留输入。                                       |
| 生成／重新生成标题 | 已配置可用标题模型的已保存对话 | 按总计划 F9 发起独立命名任务；保护请求之后的手动改名，失败保留原题。                     |
| 复制链接           | 所有已保存对话                 | 复制目标对话的站内 URL；已知该对话的阅读分支时可包含分支参数。链接仍受现有 Access 控制。 |
| 复制对话           | 所有已保存对话                 | 复用完整对话复制及附件处理；按目标对话的阅读位置处理，不使用当前页面另一对话的分支。     |
| 归档／取消归档     | 所有已保存对话                 | 复用现有归档状态；在归档列表中显示“取消归档”。                                           |
| 查看生成位置       | 存在已确认的活跃任务           | 打开目标对话及任务所在分支，使用已有 SPA URL 与历史导航。                                |
| 停止生成           | 存在可取消的活跃任务           | 使用明确的任务／run ID 请求停止，保留已生成内容；不额外弹确认窗口。                      |
| 删除对话           | 所有已保存对话                 | 复用删除确认，显示被操作对话的标题，并说明会停止其中的生成。                             |

菜单按整理（置顶、重命名、生成标题）、复用（复制链接、复制对话）、任务（查看生成位置、停止）、归档与删除分组，删除独立成组，无可用项的组不显示。命令组内统一图标与对齐宽度，保持单层。正文导出、备份和当前分支操作继续使用现有顶部入口，避免列表菜单过长及分支含义不明确。AI 标题入口随总计划 F9 接入，不阻塞基础菜单交付。

复制对话默认在完成后打开副本；若等待期间用户已经导航到其他位置，只将副本加入列表，不抢占阅读。重命名、置顶、归档及停止非当前对话时，当前 URL、正文、分支和草稿保持不变。删除当前对话后回到新对话；删除其他对话不改变当前页面。

未被服务端确认创建的本地对话行仍可打开和查看“待发送／发送失败”，首期不向它提供依赖云端对话已存在的管理操作。待发送请求的编辑、取消和重试沿用对话内入口。

## 3. 布局、焦点与等待反馈

- 列表行由标题链接、状态位和菜单按钮等同级元素组成，不把按钮嵌入链接。
- 菜单按钮预留固定空间，出现时不推动标题或状态。桌面在悬停、键盘聚焦、当前行或菜单展开时显示；触摸设备始终显示。焦点隐藏时也不能留下一枚看不见的可操作按钮。
- 标题保持截断和完整名称提示；状态不能仅靠颜色区分。按钮与触摸菜单项保持至少 44 CSS px 的命中区域，视觉图标可更小。
- 生成标记与菜单可同时出现；打开菜单不会遮掉生成状态。浅色、深色及减少动态效果设置均需检查。
- 键盘可从标题到菜单，使用 Enter／Space、方向键和 Escape 操作。按钮名称包含目标标题，如“对话名称的更多操作”。
- 重命名和删除共用页面层的弹窗控制器，不为每一行挂载一套弹窗。移动端从侧栏进入弹窗时先协调 Sheet 关闭，再转移焦点，避免两个焦点陷阱冲突。
- 关闭菜单返回原按钮；行因删除或归档离开当前列表时，焦点落到邻近行。移动端侧栏已经关闭时，弹窗关闭后返回侧栏入口，不强制重新展开。
- 请求期间只限制同一目标的冲突操作，保留其他行、导航和复制链接；不冻结整条侧边栏。失败反馈出现在对应菜单或弹窗，保留重试所需的目标和输入。
- 任务状态刷新不修改对话的排序时间，避免每次状态变化都让行移动；置顶、归档等明确整理操作按原规则调整位置。

## 4. 生成状态的数据来源

### 轻量活动索引

由 Conversation DO 维护真实任务状态，并在接受任务、开始执行和结束时向 Library 汇报小型活动记录。Library 列表响应附带活动摘要，不逐个查询所有 Conversation DO，也不为每行维持流式订阅。

建议在 `LibrarySnapshot` 中独立增加活动映射，保持 `ConversationInfo` 的基本元数据职责；运行状态不写入备份或继承到复制出的对话。

活动记录至少包含：对话 ID、单调递增的来源版本、等待／运行／空闲状态、定位所需消息 ID、取消所需任务标识和状态更新时间。来源版本可以使用 Conversation 已持久化的事件序号；不能用客户端时间或 `updatedAt` 代替因果顺序。

首期复用现有约 10 秒的列表刷新、页面恢复时刷新和操作后的主动刷新。当前对话的 WebSocket 状态立即更新该行，本机提交接受结果也补充同一活动缓存。其他对话和其他设备发起的任务允许低频刷新带来的短暂延迟，网络缓慢时不承诺固定秒数。

### 一致性要求

1. Conversation 在保存任务生命周期变化的同一事务中保存待汇报记录，提交后异步投递，失败沿用 DO Alarm 退避重试的模式；不能只用一次性内存通知。
2. Library 仅接受更新版本；结束后保留版本水位，防止迟到的“正在生成”重新覆盖空闲状态。删除标记优先，迟到报告不能恢复已删除行。
3. 客户端合并当前订阅、提交结果和 Library 摘要时也比较版本，较旧的列表结果不能让已结束的当前任务重新转圈。
4. 按整个业务任务判断结束：工具轮次完成不等于回答完成，自动摘要完成但回答仍排队时也不能清除标记。每次任务切换都保留准确的定位和取消目标。
5. 完成、失败、取消、看门狗中断和对象重启后的恢复都需要汇报；正常断网不代表云端任务停止。过期状态只标记待同步，不依据一个 UI 超时猜测完成。
6. 停止操作针对用户看到的任务标识；旧菜单的停止请求不能取消之后的新任务。遇到任务已结束或信息过期时刷新状态，确认前不显示停止成功。
7. 后台对话不读取完整消息或高频 token 数据。活动记录只包含状态与定位信息，变化时才汇报；没有状态变化时不因流式增量增加 Library 写入。

此方案增加有限的生命周期汇报与持久重试记录，实际操作数应在实现后测量；复用现有列表轮询不代表服务端更新完全没有额外成本。

## 6. 验收重点

- 同时生成 A、B，打开 C，A／B 的状态仍可更新；其中一个结束不会影响另一个。
- 打开 A 的旧分支，另一分支生成时整行提示可见；普通打开保留阅读位置，“查看生成位置”明确跳转。
- 本机待发送、服务端排队及实际执行能区分；接受后从 outbox 移除不会让提示短暂消失。
- 慢速停止、失败重试、工具多轮、自动摘要衔接、看门狗中断及 DO 重启均正确转换状态。
- 人为打乱开始／结束／新任务报告顺序，旧版本不能覆盖新任务，也不能恢复被删除的行。
- 从 A 操作 B 的重命名、归档、置顶、删除和停止，A 的正文、草稿、URL、阅读分支与滚动保持不变；复制响应晚到时遵守导航保护。
- 离线时菜单仍可打开、复制链接；依赖云端的操作按真实条件禁用。身份未确认时不展示私密列表，退出后清除活动缓存和迟到回调。
- 桌面、移动端、深浅色、200% 字号及键盘操作正常，标题与状态不挤出菜单，菜单展开期间轮询不换操作目标。
- 验证只在生命周期变化时汇报；测量额外 RPC、SQLite 写入和列表响应大小，确保没有逐 token 写索引或为每行读取快照。

实现时补充状态合并与幂等性单元测试，以及 `tests/e2e/library` 的菜单、后台任务和焦点回归；完成 `pnpm typecheck`、`pnpm test`、相关浏览器回归、生产构建与格式检查后更新本篇状态。
