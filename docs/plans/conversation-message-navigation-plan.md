# EverChat：对话阅读导航方案

日期：2026-10-17（Asia/Shanghai）。状态：已实现并通过本地验收。代码基线：`7812f2b`。

目标：将当前单一的底部跳转入口扩展为「跳到顶部、上一条回答、下一条回答、跳到底部」四个按钮。保持现有紧凑布局、流式跟随、分支阅读和焦点规则，不增加服务端请求或持久化字段。

## 2. 四个按钮的语义

按钮顺序固定为「顶部 → 上一条回答 → 下一条回答 → 底部」，首尾不循环。

| 按钮       | 目标                                                           | 跟随行为                               |
| ---------- | -------------------------------------------------------------- | -------------------------------------- |
| 跳到顶部   | 当前显示路径的消息区最上方，包含第一条提问                     | 暂停底部跟随                           |
| 上一条回答 | 优先返回正在阅读的长回答开头；已在该回答开头时，定位前一个回答 | 暂停底部跟随                           |
| 下一条回答 | 定位阅读参考线之后的第一个回答开头                             | 暂停底部跟随，即使目标是正在生成的回答 |
| 跳到底部   | 当前显示路径的实际末尾，包含最新提问、生成状态或待发送消息     | 恢复现有底部跟随                       |

### 2.1 回答范围

- 只从 `branches.path` 取得助手消息，按当前显示顺序排列，使用消息 ID 作为身份。
- 排队中、生成中、已完成、失败、已停止和手动编辑的普通回答均可定位；不能因状态更新而改变回答顺序。
- 排除已删除消息、历史摘要、用户提问和本地待发送占位。工具活动和思考过程属于所在回答，不另算回答。
- 隐藏分支中的其他版本不进入列表。同一提问重新生成的其他版本继续通过气泡下的版本切换器访问。
- 不切换分支、不改变续聊起点，不修改 `/c/:id?branch=...`、浏览器历史、输入框草稿或模型选择。

### 2.2 如何判断上一条／下一条

以消息视口顶部内缩约 `0.75rem` 的水平线作为阅读参考线，位置比较允许约 2 CSS px 的误差，避免缩放和小数布局造成重复定位。

1. 找到参考线之前最近的回答开头。如果参考线仍处在这条回答的范围内，并且开头已明显超出视口，「上一条」先回到本条开头。
2. 已对齐某条回答开头时，「上一条」跳到前一条，「下一条」跳到后一条。
3. 参考线处在两条回答之间的提问、摘要或留白中时，上一条取其之前最近的回答，下一条取其之后最近的回答。
4. 首个回答之前没有上一条，最后一个回答开头之后没有下一条；使用顶部／底部入口完成剩余阅读定位，不把前后按钮悄悄改成另一种动作。
5. 回答靠近列表末尾、受最大 `scrollTop` 限制而无法顶端对齐时，以已经到达的回答 ID 记录成功定位；无新回答或布局变化时，重复点击不能停留在同一个目标。

例如当前路径为 `提问 A → 回答 A → 提问 B → 回答 B → 提问 C → 回答 C`：

| 阅读位置          | 上一条回答  | 下一条回答  |
| ----------------- | ----------- | ----------- |
| 回答 B 的中段     | 回答 B 开头 | 回答 C 开头 |
| 回答 B 的开头     | 回答 A 开头 | 回答 C 开头 |
| 提问 B 的中段     | 回答 A 开头 | 回答 B 开头 |
| 回答 C 中段或末尾 | 回答 C 开头 | 不可用      |

首期采用即时定位，与现有底部按钮一致，连续点击立即定位相邻目标。不要为顶端对齐添加一整屏尾部空白。

## 3. 布局与可访问性

### 3.1 显示位置

- 用一组四个图标按钮替换原来的底部单按钮，不保留重复入口。
- 桌面在正文右侧有足够留白时竖排；容器较窄时横排，放在输入框上方、消息区域右下角。根据**消息容器宽度**判断，不能只按窗口宽度判断，确保侧栏展开后仍能容纳。
- 工具条锚定在消息滚动区外的同级覆盖层，不随消息内容滚走；输入框保持现有单行功能区。软键盘、搜索条或输入框高度变化后，工具条仍处在实际消息视口内。
- 窄屏工具条下方保留小间距，为最后一条内容提供工具条所需的有限末尾留白；测量是否溢出时排除这块预留空间，避免工具条自行制造溢出和显隐循环。
- 无消息、空白新对话、首次加载且无缓存、内容全部可见无需滚动时隐藏整组。有可阅读缓存时保持可用；后台请求及流式生成不让按钮整组消失。
- 到达顶部或底部时保留四个按钮的位置，只将对应动作设为不可用；避免滑动过程中工具条反复变宽或变高。

### 3.2 外观和操作

- 延用 shadcn/ui `Button`、`Tooltip` 与现有浅／深色语义 Token。整组只保留一个轻边界，不为每个按钮再加边框或分隔线，不新增常驻解释文字。
- 图标建议依次为 `ArrowUpToLine`、`ChevronUp`、`ChevronDown`、`ArrowDownToLine`；图标使用 `min(1rem, 24px)`，触控区域使用 `clamp(44px, 2.75rem, 56px)`。普通字号下四个按钮横排约 176px；200% 字号下不超过 224px，继续保持单行，避免多行工具条占去阅读区域。此处明确覆盖全局按钮的最小尺寸，且不对尺寸做过渡动画。
- 始终可发现，不依赖悬停。悬停和键盘聚焦时提供简短 Tooltip，竖排在左侧显示、横排在上方显示，避免覆盖其他导航按钮。触屏点击不打开 Tooltip，避免气泡遮挡正文；四个按钮均有完整可访问名称。
- 使用命名的按钮组和原生按钮，支持 Tab、Enter、Space。到边界后使用 `aria-disabled` 并拒绝执行，只淡化图标而不淡化焦点环，使连续操作后的焦点仍可停留在当前按钮。
- 点击或键盘操作后焦点保留在按钮，不主动聚焦消息正文或输入框，不弹出软键盘。用单独的 `aria-live="polite"` 状态简短播报「已定位第 3 条回答，共 8 条」；不播报整篇回答或每次手动滚动。
- 前后回答与顶部操作不改变折叠状态，也不滚动思考、代码、公式、表格等内层滚动区；命中范围仍由对话内搜索自己的入口负责。
- 首期不新增全局快捷键，保留 `Mod+J`、`Mod+K` 等现有约定及原生文本编辑、Home／End、PageUp／PageDown 行为。
- 验证浅深色下图标、背景和焦点环；可用图标及焦点指示与相邻背景至少 3:1。尊重减少动态效果偏好。

## 4. 滚动协调与实现边界

### 4.1 单一的阅读意图

新增按钮不应形成第三套独立控制滚动的逻辑。一次显式操作先取消旧定位，再执行当前动作：

| 操作                               | 需要释放的旧状态                       | 后续行为                                   |
| ---------------------------------- | -------------------------------------- | ------------------------------------------ |
| 顶部／前后回答定位                 | 分支操作行锚点、上次尚未完成的回答定位 | 暂停跟随，只校准当前目标                   |
| 底部定位                           | 所有历史阅读锚点与迟到校准             | 恢复跟随，后续流片段继续贴底               |
| 搜索命中定位                       | 分支锚点、回答定位锚点                 | 沿用现有搜索展开与内层定位规则             |
| 气泡版本切换                       | 上次回答定位锚点                       | 沿用分支操作行固定位置                     |
| 用户滚轮、触摸、拖动滚动条或滚动键 | 当前程序定位与布局校准                 | 立即交还用户；手动回到底部仍可恢复跟随     |
| 切换对话、分支、浏览器前进／后退   | 当前对话的定位任务、缓存节点及迟到回调 | 重建当前路径索引，不把旧对话目标带入新页面 |

这里需要给分支锚点增加显式取消入口。当前分支 Hook 的用户输入监听主要在消息视口内，而新按钮位于视口外；仅调用 `pauseFollowing()` 无法释放原锚点，必须一并处理。

### 4.2 锚点与布局变化

- 回答锚定整个消息根节点的模型标题开头，定位只修改主消息视口的 `scrollTop`。不用不受约束的 `scrollIntoView()`，避免连带移动页面或嵌套滚动区。
- 按消息 ID 注册根节点引用，复用 `branches.ids` 和角色／删除状态建立回答序列。流式正文变化只更新高度，不重建全文索引，不扫描或拼接 Markdown。
- 用户导航后，字体、Markdown、图片等造成目标上方高度变化时，可以短暂校准当前目标的位置；用户一旦开始滚动、使用另一导航或切换上下文即释放，不持续把用户拉回锚点。
- 复用已有布局观察和 rAF 合并测量；滚动帧只在顶部／底部状态或当前回答变化时更新 React 状态。首期不增加轮询、逐消息 `ResizeObserver` 或新的滚动动画库。
- 延迟回调携带对话及路径版本，目标被删除、节点卸载或路径改变后立即失效。下一次点击根据新路径重新计算，不复用失效 DOM 坐标。
- 工具条不能截获页面边缘手势，不引入新的全局触摸监听。

### 4.3 建议模块

| 模块                                                | 职责                                                         |
| --------------------------------------------------- | ------------------------------------------------------------ |
| 新增 `src/features/chat/ConversationNavigation.tsx` | 四按钮、布局、可访问名称、边界状态与简短播报                 |
| 新增 `src/features/chat/useMessageNavigation.ts`    | 当前路径回答索引、目标计算、消息引用注册与定位状态           |
| 调整 `useFollowScroll.ts`                           | 共用顶部／底部测量及显式滚动入口，保留流式贴底规则           |
| 调整 `useBranchScrollAnchor.ts`                     | 支持显式释放；与回答定位共享阅读意图，保持既有分支焦点行为   |
| 调整 `MessageView.tsx`、`App.tsx`                   | 注册消息锚点，接入按钮，移除原底部单按钮，协调搜索与分支操作 |

## 5. 实施顺序与验收

1. **先确定定位语义**：实现可独立验证的目标选择函数，覆盖长回答返回本条开头、提问间隙、首尾边界及末尾无法顶端对齐。
2. **统一滚动控制**：补上旧锚点取消、定位任务失效和流式暂停／恢复；先接现有底部行为，保持已有贴底回归。
3. **接四按钮与布局**：替换旧入口，完成消息节点注册、容器宽度适配、边界状态、焦点和播报。
4. **回归与真机检查**：验证相邻功能，再记录桌面与移动设备的实际结果；只执行本方案涉及的验收，不重新加入已取消的侧滑。

| 范围           | 核心验收                                                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 定位语义       | 多轮短回答、跨多屏长回答、提问与摘要间隙、单条回答、无助手回答、末尾无法顶端对齐；连续点击顺序正确且不循环                 |
| 分支和数据变化 | 仅遍历当前路径；重新生成、手动编辑、删除、隐藏分支及远端新版本不误跳；导航前后 URL、草稿和续聊起点不变                     |
| 流式和布局     | 顶部／前后回答定位后持续生成不抢滚动；底部恢复持续贴底；思考折叠、字体／图片迟到、视口变化不让旧锚点反向拖动               |
| 搜索与焦点     | 搜索命中、版本切换和四按钮交替操作不争抢；导航不清空搜索或展开折叠；聚焦按钮可重复操作，输入法与软键盘行为保持正常         |
| 移动和可视范围 | 320／390 CSS px、横屏、侧栏展开／收起、软键盘、200% 字号；工具条不遮挡发送、搜索关闭或最后一条消息，代码与公式仍可横向滚动 |
| 加载与离线     | 空白页隐藏；缓存对话在慢网／离线时可导航；首次加载和对话切换后无旧定位回调                                                 |
| 可访问性       | 按钮名称、Tab／Enter／Space、边界焦点、简短状态播报、浅深色对比度及减少动态效果                                            |

测试选择：目标计算做有边界价值的单元测试；浏览器验证真实几何位置、连续点击和流式行为，不以按钮存在代替定位成功。复用现有流式、分支、搜索与移动布局夹具，避免复制大套测试。实施完成后执行相关浏览器回归、`pnpm test`、`pnpm build`、修改文件的 Prettier 检查及 `git diff --check`。

## 6. 实施记录

- 四个入口已接入主消息视口；消息容器宽度达到 `56rem` 时竖排，否则在消息区右下方横排。
- 回答 ID 与 DOM 节点独立注册，滚动时使用缓存坐标；流片段不重建正文索引。底部无法对齐的短回答以 ID 记录已到达的目标。
- 复用已有 `ResizeObserver`，通过局部布局事件通知分支及回答锚点；显式阅读意图同步使旧定位失效，避免旧锚点抢回滚动。
- 工具条额外尾部留白使用已解析的实际 CSS 长度计算，不直接解析含 `rem`／`calc()` 的自定义属性，避免显隐循环。
- 新增 5 项目标计算单元测试、5 项真实浏览器场景；覆盖长回答、末尾夹限、无助手回答、隐藏／删除版本、搜索、延迟布局、流式暂停／恢复、离线、320px／横屏／200% 字号、键盘焦点与浅深色。

- `pnpm test`：360 项通过，其中新增目标选择测试 5 项。
- Chromium 相邻回归：46 项通过，覆盖聊天、流式、分支、搜索、SPA 导航、阅读布局和输入框；最后调整提示位置后，阅读导航 5 项再次通过。
- WebKit 阅读导航：最终 5 项通过。已修正 Safari 点击按钮默认不聚焦的差异；边界按钮保留焦点，触屏不弹提示气泡；浅深色可用图标和焦点指示对比度均至少 3:1。
- `pnpm build`：完整类型检查及生产构建通过。修改文件 Prettier 检查、`git diff --check` 通过。
- 截图核对：桌面浅深色、320px 窄屏、844px 横屏及 200% 字号。竖排提示不覆盖其他按钮，横排末尾有有限留白，大字号继续保持单行。
