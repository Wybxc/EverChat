# 同步请求与 Cloudflare 免费层资源排查

日期：2026-10-22。状态：待实施，独立于 AI SDK Core 发布。

用户已确认先发布 Core 集成，接受当前记录的资源不确定性，将本排查单列。此决定不表示免费层资源验收通过，也不扩大已结束的隔离测试授权窗口。

## 已知事实

- 最近一次隔离 HTTP 测试完成 476 次同步握手，正文与思考各保存 84,000 字。
- 同步连接 CPU p50 为 2.283 ms、p99 为 15.628 ms、最大样本为 20.809 ms。未报告资源超限，但自适应统计和 tail 均不能证明完整覆盖。
- 空对话和终态同步均有高 CPU 样本；此前空对话尖峰不需要模型流消费就能发生。具体函数尚未定位。
- 鉴权、会话访问检查、中间件和同步路由源码相对发布前 main 未改变；这不是运行时、包体初始化或平台前后对照。
- 本地独立 API isolate 采样出现 JWT、会话查询、路由与 WebSocket 转发。采样点、本地墙钟及 idle／I/O 时间不等于 Cloudflare CPU 或计费用量。
- 准确部署版本和持续流量下，两次 profile 返回 404／10393；DO periodic 延迟查询仍为空。不能记为零消耗，也不能将前期其他窗口的指标填入本次缺项。
- 所有隔离资源与临时凭据已核对清理。生产鉴权和完整性边界没有因此削弱。

证据：[HTTP 补测](../measurements/ai-sdk-core-http-cpu-2026-10-22.json)、[私有补测](../measurements/ai-sdk-core-private-cpu-2026-10-22.json)、[本地采样](../measurements/ai-sdk-core-local-cpu-2026-10-22.json)、[完整记录](../measurements/ai-sdk-core-adoption-2026-10-21.md)。

## 排查顺序

1. 先解决观测可信度：核对部署 UUID、目标、流量和采样时间，查明 10393 与 DO 空数据的条件。优先使用已有证据和只读历史查询；没有新假设或观测手段时，不重复部署相同测试。
2. 建立可归属的同负载基线，分开无状态 Worker 与 Conversation／Library DO，区分空闲、生成中、终态、冷／热状态及历史大小。记录失败和缺失数据，不将缺项补为零。
3. 在身份验证、会话授权、请求构造和转发等候选路径获取平台函数级证据。先证明成本来源，再决定优化；不从本地采样或单请求 wall time 推断平台 CPU 根因。
4. 只实施证据支持的优化，保留 Access 验签与声明验证、复制／导入／删除状态检查、受信会话头清理及流结束完整性。禁止放宽鉴权、无限缓存授权结果或丢弃有效内容。
5. 取得闭合窗口内可归属的 Worker CPU／内存样本，以及 DO 请求、活跃时长、CPU、duration、SQL 读写和存储，核对单位、采样率与覆盖范围，再评估 Workers Free 预算。

新增隔离资源、临时公开入口或访问凭据，须在准备可审查脚本后按具体范围取得授权。每次固定总窗口并预留清理时间，先关闭入口，再删除及核对 Worker／namespace；不重置截止时间或扩大已有授权。

## 完成条件

- 能解释并复现高 CPU 路径，或有充分平台证据排除代码热点并明确外部原因；未定位时保持未完成。
- 优化前后使用同一负载与口径，功能、鉴权、持久化和重连无回归。
- 免费层评估明确常见负载与不适用边界；不因未观察到 exceededCpu 就承诺所有负载符合预算。
- 指标缺项补齐，或确认平台不提供相应指标并记录可核实的替代验证及局限。
- 测试资源和凭据均核对清理，生产部署与数据变动有独立记录。
