# AI SDK Core 与 UI 深度集成计划

日期：2026-10-21。状态：实施中。已固定配套依赖并接入 Core 单轮生成与工具参数解析；UI 消息／Transport 迁移和生产维护切换尚未完成。中间改动只在本地验证，尚未迁移线上数据或部署。

## 目标

让 AI SDK Core 承担通用的模型调用、工具参数解析、输出处理和诊断，让 AI SDK UI 承担前端消息分片、流式状态和 React 订阅。删除已经由 SDK 覆盖的同类实现，降低后续供应商适配和功能开发成本。Robustness 是其中一项验收目标，同时改善消息结构、前后端职责、测试方式和资源使用。

EverChat 继续负责对话分支、上下文选择、持久化、后台任务、幂等、权限和费用账本。SDK 的内存状态不能替代这些能力。继续使用 Cloudflare Workers Free 架构、客户端高频展示与服务端低频持久化，不增加 Redis、Vercel Workflow 或另一套常驻 Agent 服务。

“充分利用”按现有功能的适配程度判断；不为采用更多 API 而新增产品功能。本轮不增加外部 MCP 工具、知识库、临时聊天模式、用户 JSON Schema 输出模式、语音或图像生成。

## 调研时的现状与证据

- 生产依赖包含 Provider V4 适配器、`@ai-sdk/valibot`，没有 `ai` Core 和 `@ai-sdk/react`。普通生成直接调用 `LanguageModelV4.doStream()`，能力探测使用 `doGenerate()`。
- `worker/providers/events.ts` 与 `tool-turn.ts` 处理公开事件、内容聚合、工具 JSON／业务校验和私有续接；部分通用职责与 Core 重复，部分处理供应商协议资料，必须保留。
- `src/features/chat/useConversation.ts` 同时处理分页快照、WebSocket、预览确认、连接状态和 React 更新；`StreamSync` 同时维护 durable 与 preview。它们没有可直接替换成默认 HTTP Transport 的一对一关系。
- 提交经 `useOutbox` 持久化并复用 `requestId`；模型在 DO 中运行，联网调用有自己的持久任务账本与 Workflow。断开网页连接不会自动取消生成。
- 公开消息当前最多一个 reasoning 通道和一个 text 通道，联网步骤通过思考位置重建顺序；这与 SDK 的有序 `UIMessage.parts` 不同。
- [此前 Core 实验](../measurements/ai-sdk-integration-2026-10-20.md)证明 `ai@7.0.145` 的聚合会覆盖 Anthropic 分片签名；Responses 摘要／全文和原生调用身份也需要专门处理。因此不直接把 `responseMessages` 当作完整的私有续接记录。
- 本轮已在隔离安装的同一版本上复核五个本地场景：无效 JSON、Schema 不匹配、工具执行异常、单工具超时均可产生局部 `tool-error`，另一合法调用仍执行，错误进入下一次模型请求；`repairToolCall` 可修复参数。没有调用真实供应商。这仅证明 SDK 通用能力，尚未验证 EverChat 集成后的持久恢复。
- 用户指定对话的具体故障、HTTP 地址策略与搜索结果容错问题见[Robustness 排查](../measurements/provider-tool-robustness-2026-10-21.md)。本计划吸收其修复项，不重复建立一个独立待办。

## Core：统一调用，保留可恢复的执行边界

### 单轮生成

主方案使用公开稳定的 `streamText()`，每个 DO 模型轮次只发起一次实际供应商请求：

1. 显式设置 `maxRetries: 0`；不启用流内恢复重试，`onError` 不请求重试。不把工具失败或流损坏变成整段生成的隐式重发。
2. tools 使用共享 `tool()`／Valibot 定义，首期不提供直接执行联网请求的 `execute`。Core 解析调用并报告无效参数，DO 在完成必要检查与持久认领后执行合法调用。
3. 不在 Core 中开启自动多步推进。DO 保存模型轮次和工具结果后决定下一步；重启不能靠重跑整个 Core 循环来恢复。
4. 用 `wrapLanguageModel` 的公开中间件入口捕获必要的原始 SDK 事件；采用同一条流上的变换，不 tee 一份完整响应。保留 HTTP／wire guard，私有 collector 缩减为原生身份、结束证明、签名、加密资料及续接必需字段。
5. Core 聚合的公开内容与私有资料按稳定块身份／顺序对齐。Anthropic 分片签名必须拼接；Responses 全文优先和摘要去重、加密续接资料必须保留。只缺某个 SDK 字段时增加局部适配，不重新实现整套工具输入解析。
6. 工具只在原生轮次完整结束、调用身份明确、参数与权限通过且任务已认领后执行。SDK 发出完整 tool-call，不单独作为网络流已完整结束的证明。

阶段 0 对比普通 `streamText` 与该版本的低内存入口；选择能通过资料完整性、背压和资源门槛的模式，不依赖未公开的 `_internal` 开关。安装的 Core 还公开导出实验性 `experimental_streamLanguageModelCall`，可以做单轮对照；它不是已选定的生产接口。若采用，必须记录版本约束、替代理由和相同验收结果，不导入 SDK 内部文件。

### 工具容错

- 区分“候选调用”和“可执行调用”。Core 的 invalid call／tool-error 不能被强制断言成合法 `WebToolCall`；身份明确的失败调用保存有界失败信息，并生成与原调用匹配的结果供模型续接。
- 同一轮合法调用继续执行；一个错误不丢弃整个轮次。未知工具不执行；缺少原生 ID、身份歧义、流截断或缺少必要签名时仍停止并保留部分回答。
- 服务端点继续限定 HTTPS；公开来源／Fetch 目标按联网服务能力支持 HTTP／HTTPS，保留凭据、内网和非网页协议边界。URL 不静默改写，约束与工具说明一致。
- 搜索来源逐条处理：标题可合理回退，无效来源单独过滤，保留有效结果与有界警告。根结构错误、凭据泄漏或所有来源不可用明确报告，不能伪装为空搜索。
- 参数约束按所选联网服务生成：对齐 DeepSeek 搜索的 128 个 Unicode 字符和 Fetch 的 8192 字符 URL 能力；区分 Unicode 字符数、JavaScript 字符串长度与 UTF-8 字节预算。严格模式按协议实际能力启用，不把 `strict: true` 当作运行时校验的替代。
- 单工具超时／网页不可用返回局部失败；用户取消、全局期限、存储失败仍停止任务。联网服务认证／余额故障停止继续请求该服务，在剩余资源内让模型收尾。
- `repairToolCall` 先不增加自动的额外模型调用。优先回传字段路径和可修正条件；将来增加修复模型前，先定义请求认领、成本与修复失败行为。不自动补齐未结束的 JSON，也不伪造调用身份。
- 连续重复的同一失败调用用规范化指纹识别无进展；必要时关闭工具，让模型根据已有资料收尾。不重新加入全局固定工具轮数限制。

Core 的 `timeout.toolMs` 适用于由其 `execute` 执行的工具；首期执行仍在 DO／Workflow，因此不能声称只设置这个参数就修好了现有超时。局部失败策略必须在实际执行边界落实。

## UI：采用标准消息流与自定义 Transport

### 消息与内容

定义共享的 `EverChatUIMessage`，使用 `UIMessage<PublicMessageMetadata, EverChatDataParts, EverChatTools>`：

- text、reasoning、工具输入／输出／错误、来源使用 SDK 标准 parts，按实际发生顺序保存与展示。part 身份在刷新、工具轮次和重连中保持稳定。
- 摘要覆盖、附件引用及 PDF 页码选择等应用数据使用类型化 data parts。附件只携带已授权的引用和必要信息，不把 PDF 全文、图片 Base64 或私有存储凭据复制到消息 metadata。
- 模型／供应商显示名、生成用量、计时、上下文估算、中断标记和公开错误进入明确的公开 metadata；分支父子关系、revision、删除状态、runId 和持久游标仍由业务记录维护。
- 公开消息采用一份有序内容。停止同时持久化“UIMessage 全文”和“旧双通道全文”两套内容；私有续接资料单独保存，不从浏览器消息反推。
- 当前依赖“第一个 text／reasoning part”的读取函数改为明确的聚合或按序渲染，避免迁移后漏掉后续块。历史工具位置只在离线转换中用于拆分已有思考；无法还原的信息不能伪造。
- 备份、导出、搜索、复制和分享显式投影公开内容。现有分享 DTO 与内部 SDK 类型隔离；不因为聊天内部迁移就改写所有分享载荷或引入私有聊天运行时。

### 状态所有权

采用三层状态，各有一个所有者：

1. **持久业务状态**：服务端快照／提交确认决定分支图、已保存消息和任务状态；只缓存和导出已确认数据。
2. **活动消息状态**：SDK UI 维护当前运行的有序 parts 与流式更新。预览不能被标成已保存；确认包只推进持久边界，不重复向 SDK 附加相同文字。
3. **组件交互状态**：草稿、选区、附件处理、折叠、编辑、阅读位置和模型选择继续由现有功能模块负责。`useChat` 不管理输入框草稿。

前端使用 `Chat` 实例与 `useChat({ chat })`，配合一个按需存在的会话控制器。控制器管理 conversation／run／分支投影与 Transport 生命周期，切换展示不销毁后台业务任务，也不为每个历史对话常驻一条连接。历史图是持久层模型；SDK messages 只表示当前展示路径，不能成为第二份独立的可变历史图。

不采用每个 token 后 `setMessages(snapshot.messages.map(...))` 的同步方式。增量由 SDK 应用；只有首次加载、分支切换或权威快照替换时重置投影。更新时只替换受影响的消息／parts，避免全历史反复克隆。

### Transport 与同步

实现 `EverChatTransport`，遵循公开 `ChatTransport` 接口：

- `sendMessages` 将操作交给现有 outbox／命令服务，复用同一个 `requestId`。只提交新输入、选中的模型／工具／参数、parentId、revisionOf／retryOf 等业务命令；服务端从持久状态构建历史，不信任客户端上传的整份 messages。
- 服务端接受请求后返回的 userId／assistantId／runId 与 UI 使用同一身份。乐观消息按 requestId 对账；受理超时后只能重查或重投同一请求，不能生成第二个请求 ID。
- `reconnectToStream` 只连接现有 run，不重新提交生成。没有活动 run 时加载终态并返回 null。多设备和 MCP 发起的生成也通过同一活动索引发现并接入。
- 保留 WebSocket 可靠性外壳：epoch、seq、runId、chunkSeq、offset、preview、commit／ack。公开内容载荷改为 SDK `UIMessageChunk`，可靠性控制信息不冒充正文 parts。
- 同一个 UI 消费者只接收去重后的内容一次：已展示的 preview 得到 commit 时只更新确认边界；未见 preview 的客户端从 commit 读取内容。缺口或 epoch 变化回到权威快照，不猜测缺失增量。
- 刷新或丢失预览后，先恢复已保存检查点，再接后续增量；SDK 活动块状态必须能重建。阶段 0 固定并验证重放语义，不能混用全量重放和增量追加，不能靠时间戳去重。必要的块起始信息属于恢复检查点，不持久化整段原始事件日志。
- 一个客户端／会话由同一个连接管理器接收快照与活动流；不要让 useConversation 与 Transport 分别创建两条同用途 WebSocket。重连、心跳和 Access 刷新保留一个所有者。
- 活动 run 与当前可见分支分别标识。用户回看旧分支时，其他分支的新内容只更新对应 run 和侧栏状态，不把当前视图自动切走。

Transport 的 abort 表示取消本地等待／订阅。明确点击停止时，先调用带当前 runId 的服务端取消命令，再结束 SDK 本地流；页面关闭、导航、PWA 挂起、普通网络断开和 `chat.stop()` 本身都不能默认为取消服务端任务。旧 run 的停止请求不能取消后来的 run。

### 服务端批次与检查点

当前版本的 `readUIMessageStream` 会主动消费输入并向输出队列发布消息快照，不能只凭调用这个 API 就宣称保留了端到端背压。服务端采用公开 `AbstractChat` 的单回答状态存储；没有 React 依赖，不提供实际发送模型请求的 Transport，也不配置工具执行回调或自动续接。SDK 负责内容应用，EverChat 只记录恢复所必需的活动块身份。

每次输入最多一个有界批次，等待 SDK 已应用的本地 barrier 后才返回不可变检查点。SDK 内存应用批次上限为 128 KiB，容纳既有 64 KiB 工具参数／结果加上标准 Chunk 外壳；这不是扩大现有 wire 提交批次。barrier 是模块内生成的 transient 数据，不进入消息、网络载荷或数据库。按顺序先异步准备检查点，再在既有 `transactionSync` 中保存；事务失败时丢弃这个解析器，从最后成功提交的检查点重建，不在 SQLite 事务中等待 Promise。预览、确认、容量保护和取消仍由现有执行层负责。

检查点由一份 canonical message 加上活动块的 `{type, id, index}` 描述组成；持久层只额外保存描述，不重复存一份全文。SDK 的 text part 不自带原始流 ID，因此只把已有 messages 作为初始状态不足以恢复后续 `text-delta`。刷新后显式重放已保存的语义 parts，恢复活动 ID，随后追加增量；重放按有界批次进行，不保存原始事件日志。工具参数仍在原生调用完整、身份已验证后才公开，不把部分 JSON 解析状态作为 EverChat 的恢复格式。

该边界已有 7 项本地证明测试：顺序、工具状态更新、历史检查点不被后续增量改写、活动 ID 恢复且前缀不重复、有界批次与禁止重叠、错误拒绝确认、取消等待。生产 buffer、SQL 存储和前端 Transport 尚未切换，不能将此证明当作全链路背压或平台内存验收。

### 前端状态与业务操作

| SDK UI 状态／入口 | EverChat 的对应规则                                                  |
| ----------------- | -------------------------------------------------------------------- |
| submitted         | 正在提交或等待流建立；离线 outbox 与服务端 queued 另有明确状态       |
| streaming         | 正在接收当前消息，不代表每个字都已持久化                             |
| ready             | 本地流结束；业务完成／取消／中断以服务端确认结果为准                 |
| error             | 区分提交失败、订阅中断和生成失败；订阅错误不改写已保存回答为生成失败 |
| sendMessage       | 通过 outbox 幂等提交；附件、草稿和键盘行为仍走现有实现               |
| regenerate        | 创建新回答版本，使用当前输入框模型／联网／思考配置，不覆盖旧回答     |
| 编辑提问／回答    | 保留原位置编辑和分支语义；SDK 的线性截断不删除旧分支后续消息         |
| onData            | 处理工具进度、连接等类型化扩展；持久数据与 transient 进度分开        |
| onFinish          | 完成前端收尾，不作为唯一数据库提交点，也不另外触发一轮完成通知       |

现有按序思考／工具展示、Markdown 流式渲染、长用户消息折叠、生成信息底部字数／Token、模型与供应商标签均保留。滚动交给现有 MessageScroller，SDK 状态更新不增加另一套自动滚动逻辑。

## 扩展复用范围

| 能力                          | 本轮处理                                                                                                                                    |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 标题生成                      | 迁移到统一 Core 调用入口；内部不必流式展示时优先 `generateText`，保留标题清洗、版本竞争、请求账本与中断后不隐式重试                         |
| 历史压缩                      | 复用 Core 单轮生成与诊断；保留分支覆盖、可见摘要消息、后续始终使用有效摘要和失败不替换原文                                                  |
| 能力探测                      | 评估以 `generateText` 替换通用调用；保留有界响应与单次探测请求。确需观察原生协议能力的项目可留明确的底层适配，不能把 SDK 默认值当作探测证据 |
| `convertToModelMessages`      | 仅在服务端选好分支与摘要、验证附件并处理私有续接后使用；data parts 显式映射／过滤，不把 UI 状态自动发送给模型                               |
| `pruneMessages`               | 用于确有既定策略的旧工具内容／空消息清理；不替代 Token 预算或语义摘要，不裁掉当前续接所需签名和工具结果                                     |
| 模型 registry／默认参数中间件 | 统一 providerId＋modelId 解析与公共参数默认值；避免配置表、registry 和 UI 各维护一份模型列表                                                |
| UI 更新节流                   | 利用 SDK React 的订阅节流，减少重绘；不延迟服务端确认或把慢速展示缓冲复制到数据库                                                           |
| `smoothStream`                | 作为体验对照项，不默认增加服务器定时器与在线时长。只有必要时在客户端展示边界采用，验证中文分段、后台节流和中断行为                          |
| `useCompletion`／`useObject`  | 当前没有合适的独立交互入口，不强行采用；将来有流式补全／结构化表单需求时再使用                                                              |
| 遥测与 DevTools               | 使用生命周期回调与模拟测试；生产不默认开启全文、参数或原始响应采集，远程 exporter 另行评估                                                  |

输出预算继续只在上下文管理中配置；本次不新增默认输出上限。现有模型价格、费用计算、余额、通知、PWA、上传与搜索索引不因 SDK 替换而另建实现。

## 验收矩阵

### 协议与 Robustness

- OpenAI Chat、OpenAI Responses／兼容 Responses、Anthropic、Gemini 均覆盖普通文本、思考、工具多轮和用量。
- Anthropic 多片签名／redacted 资料、Gemini thought signature、Responses 加密资料／全文与摘要、DeepSeek reasoning_content 不丢失。
- 无效 JSON／参数、未知工具、同轮部分失败、HTTP 来源、混合有效／无效来源、全部不可用、超时、429、5xx、余额／认证失败具有正确粒度。
- 原生 ID 缺失／重复、签名缺失、SSE／JSON 错误、异常 EOF 和 finish 后事件仍明确失败；不执行未结束的调用。
- 有部分正文的中断回答继续作为正式版本保存并进入后续上下文；局部工具失败不把成功收尾的回答显示成整体失败。
- 默认没有额外模型／工具重试；不同 HTTP 尝试与费用账本一一对应，恢复不重放已执行请求。

### 状态、交互与安全

- 发送、离线后发送、受理响应丢失、重新生成、编辑提问／回答、切换分支、浏览器前后退均保持原有身份与历史。
- 页面刷新、两个客户端同时查看、preview 后重连、commit 先于 preview、重复包、游标缺口、存储失败均与权威快照一致。
- 切到旧分支、新对话、关闭页签、PWA 挂起不取消后台生成；显式停止只作用于指定 run。
- 新建对话焦点、IME、手机换行、桌面发送、上下键历史、快捷键、附件拖放／粘贴和 PDF 范围选择不回归。
- 正文与思考在底部跟随生成，用户上滚后暂停；WebKit 流式结束、导航定位、选区和编辑不抢滚动／焦点。
- 公开 API、WebSocket、导出、分享、前端缓存中不出现密钥、私有签名／加密资料、原始请求或未经批准的 metadata。页面通知不与服务端通知重复。
- 私有路径 Access、MCP Bearer Key、匿名分享各保持既有权限；浏览器不能凭上传的 messages 或 metadata 伪造历史／用量。

### 资源与测试

- 用 SDK 的公开模拟模型／流辅助工具验证通用行为；保留真实 Provider 解析的协议夹具和 DO／Workflow 原生恢复测试，不能全部换成绕过适配器的 mock。
- 执行 `pnpm test`、`pnpm test:operations`、`pnpm build`、`pnpm format:check`、相关 E2E 与 PWA 测试。普通流／工具流沿用现有 `pnpm measure` 工作负载，在同一输入下比较请求数、检查点、SQL 行数、数据库分配、内存、预览延迟和最终内容。
- 不增加逐 token SQL／IndexedDB 写入，不恢复持久化同步事件或完整供应商原始流日志。活动流只保留必要状态，客户端断开后不为 UI 聚合额外积累回放缓冲。
- Worker／DO 的 CPU、活跃时长、包体与启动开销需单独测量。默认检查点频率和无重试场景的实际请求数不增加；其他增长必须解释并证明符合免费层预算。
- 前端按需加载，公开分享入口不引入私有 Chat／Transport 运行时；PWA 必需预缓存不因引入 Core／UI 把全部 SDK 和 Markdown 扩展重新打包进去。
- 本地墙钟、打包尺寸和 SQL 计数不等同 Cloudflare 免费层验收；真实平台证据不足的项保持待验收，不以“SDK 已支持”代替通过。

## 数据迁移与上线

继续遵守[离线运维迁移](../operations/offline-storage-migration.md)。读取历史、WebSocket 连接、客户端启动、分享访问时均不迁移历史数据。

上线前生成离线 dry-run／备份／转换／校验／回滚步骤：覆盖消息有序 parts、工具记录、进行中检查点、备份／导出边界和本地缓存命名空间。新旧格式计数、正文／思考内容、分支关系、工具结果与用量必须核对。现有外部分享保持独立投影，不为了内部类型变化增加在线兼容分支。

维护切换时暂停接受新生成，让进行中的旧协议任务完成或明确停止，刷新备份，运行本地运维迁移，再发布匹配的前后端与 SW。客户端使用全新的缓存命名空间加载权威快照；旧草稿／outbox 若需要转换，提供显式离线导出转换流程，不能在启动时静默丢弃或改写。

普通文本草稿、设置和附件引用格式没有变化时直接沿用；不整库清空浏览器存储。发布前先处理参与设备的待发送队列。协议握手明确声明版本，旧客户端遇到不匹配时停止提交并显示更新入口，不白屏、不自动转换旧载荷，也不保留旧解码器作为兼容路径。

回滚必须与对应数据备份配套，不能将旧代码直接指向新格式数据库。发布前验证 Access 重新登录、长对话、匿名分享、MCP 保存正常对话以及通知定位。计划本身不执行迁移或部署。
