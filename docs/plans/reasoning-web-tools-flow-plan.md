# 思考内容与联网工具按顺序展示

日期：2026-10-18。状态：已完成代码调研，待实施。

## 目标

把搜索、读取网页等联网信息放进「思考过程」，按实际执行顺序穿插在思考文字中。一次回答仍是一条消息，正文保持独立。

```text
思考过程                         可整体折叠
  思考片段 A
  搜索「查询内容」               执行中 → 已完成 · 5 个来源
    来源与摘录                   按需展开
  思考片段 B
  读取网页                       执行中 → 已完成
  思考片段 C

回答正文
```

联网调用刚登记时就在对应位置显示等待状态，执行中与完成后更新同一个位置；后续思考接在它下面。刷新、重新连接、换设备和恢复备份后，顺序一致。只有工具调用、没有供应商思考文字时，也显示实际发生的联网过程。

## 当前原因

| 位置                                    | 当前行为                                                           | 影响                                                 |
| --------------------------------------- | ------------------------------------------------------------------ | ---------------------------------------------------- |
| `src/features/chat/MessageView.tsx`     | 先渲染整段 reasoning 的折叠区，再在外面渲染 `ToolActivity`         | 所有联网信息固定出现在思考内容之后                   |
| `shared/conversation/content.ts`        | `Message.parts` 每个通道只保存一段聚合文字；reasoning 在 text 之前 | 数组顺序不能用于还原工具执行位置                     |
| `shared/web-tools/tasks.ts`             | 工具调用保存 `round`、调用 ID、状态和结果，没有对应的思考位置      | 知道工具属于哪一轮，却不知道应插在哪段文字后面       |
| `worker/conversation/durable-object.ts` | 工具续接切换 `runId`，沿用同一个 `messageId` 并累计思考文字        | 应记录整条消息内的位置，不能使用每轮重新计数的流偏移 |
| `worker/web-tools/task-journal.ts`      | 任务完成后清除私有续接 `turn`                                      | 历史页面不能依赖私有模型响应恢复展示顺序             |

仅把 `ToolActivity` 移进现有折叠区，只能让它出现在思考内容的末尾。实现真正的穿插，需要同时修改公开数据和渲染方式。

## 数据方案：累计文字加少量位置标记

保留现有正文、思考聚合通道和分块存储。在 `PublicToolTask` 中增加每轮工具调用的思考位置，建议字段如下：

```ts
reasoningBreaks?: {
  round: number;
  reasoningEnd: number;
}[];
```

`reasoningEnd` 是该轮工具开始之前，整条消息公开思考文字的累计 UTF-16 长度。前端用同一字符串的 `slice` 切分；不能复用原始 SSE 字节偏移，也不能复用 SQL 中实际按 JSON 转义字节计数的 `reasoningCharacters`。

例如位置为 `[{ round: 0, reasoningEnd: 120 }, { round: 1, reasoningEnd: 260 }]`，展示顺序就是：`reasoning[0:120] → 第 0 轮工具 → reasoning[120:260] → 第 1 轮工具 → reasoning[260:]`。同轮多次调用共用一个位置，以原调用顺序显示；工具结果完成先后不改变位置。

位置只在模型轮次结束、工具调用登记时确定一次。它表示真正开始执行工具的阶段边界，而不是供应商开始流式输出工具参数的时刻。等待、执行、成功、失败和停止仅更新原调用状态。

具体规则：

- 新任务初始化空数组；每个含工具调用的轮次恰好有一个标记。轮次唯一、递增，位置非负且不递减，允许多个轮次位置相同，例如模型连续调用工具但没有输出思考文字。
- 标记取自最终解析并即将持久化的公开思考文字，与该轮调用登记、公开工具状态和生成检查点合并在现有事务边界内提交。
- 重复完成通知保持幂等，已经确定的标记不能被迟到通知改写。因轮次预算等原因登记后未实际执行的调用，也保留所在位置和失败状态。
- 标记存入现有 `message_web_tools.payload`，不复制思考文字、来源正文或工具结果，不增加 SQL 表或列。
- 统一公开工具状态的写入入口。`finish`、`refreshToolMessage`、`scheduleToolModel`、取消和异常结束都复用它，避免重新生成 `publicTask()` 时覆盖已保存的位置。
- 校验器同时检查轮次与调用的对应关系，以及位置不超过已保存思考长度、不会拆开完整的 Unicode 代理对。备份导入执行相同检查。

这属于对话重建所需的语义状态，不是同步事件日志。条目数量受现有模型／工具轮次预算约束，不随 Token 数增长；不保存原始 SSE、工具状态变化历史或私有续接资料。

## 前端展示

新增共享的思考片段组装函数，将 reasoning、位置标记和工具调用转换为有序的渲染块；界面层新增 `ReasoningContent`，替换 `MessageView` 中分别渲染思考与工具的结构。

- 整条消息只有一个「思考过程」折叠入口，沿用现有展开状态。没有思考文字、也没有实际工具调用时，不因启用了联网就出现空面板。
- 思考片段继续使用共享 `MarkdownContent`，保留软换行、代码、公式和流式渲染。以模型轮次为片段边界，不按 Token 或数据库分块切开 Markdown。
- 已完成的片段静态渲染；当前模型仍在输出的末段流式渲染。轮次之间按独立 Markdown 片段解析，未闭合代码／公式沿用 Streamdown 的容错行为，后面的工具卡不会变成代码内容。原始文字不插入额外标记或围栏。
- 将 `ToolActivity` 拆出可复用的轮次／调用展示，移除包裹所有工具的第二个总折叠入口。默认显示紧凑的查询或网页标题、状态及来源数量，来源列表与摘录按需展开。
- 同轮调用按登记顺序显示；使用消息 ID、轮次和调用 ID 作为稳定标识。状态更新、追加思考和切换 `runId` 都不会重置用户已展开的来源或键盘焦点。
- 采用现有语义色和间距 Token，避免每段思考再加边框。桌面次级控件及触屏目标遵循[前端设计规范](../architecture/frontend-design-standard.md)。

工具错误的详细内容在对应位置显示。即使思考区被折叠，消息顶层仍保留必要的失败摘要与定位入口；点击后展开所有相关祖先折叠区，定位并聚焦失败调用。告警不重复播报，`aria-describedby` 保持有效。

## 流式同步、搜索与滚动

高频文本继续沿用当前 preview／checkpoint 路径。位置标记和工具状态通过现有低频消息状态同步，不向公开 SSE 注入工具协议，不新增轮询、Alarm 或 Workflow 步骤。

1. 模型首轮生成思考，前端显示一个增长中的片段。
2. 服务端确认轮次结束，在同一事务内保存公开思考、位置和工具调用；客户端收到该状态后固定前一段，在其后显示调用。
3. 工具执行只更新原卡片；下一轮公开思考追加到最后一个位置之后。
4. 重新连接直接读取当前文字、位置及工具状态，得到同样的顺序；旧 `runId` 的迟到预览继续按现有规则丢弃。

新增同步回归确保边界与文字不会出现不同版本的组合。遇到暂时不完整或不合法的位置时，先请求权威状态恢复，不把位置截到当前文本末尾后当成有效结果，也不把工具插到推测的位置。

思考区继续使用一个限高滚动容器和一个 `useFollowScroll`，不为每个片段建立滚动区。用户位于底部时，新增思考、工具状态及来源展开后的高度变化继续跟随；主动向上阅读、查找命中或定位失败后保持阅读位置。工具状态变化不抢焦点。

会话内搜索目前假定每条消息只有一个 reasoning 渲染根节点，并以 `key.endsWith(':reasoning')` 判断通道，需要同步调整：

- 每段有稳定且唯一的渲染 ID，同时保留消息／通道的逻辑身份；不让多段复用同一个 DOM 搜索 ID。
- 将片段的渲染文本合并为一个逻辑思考字段计数，跨片段命中可映射到多个 DOM Range；工具控件文字不夹入思考正文，不重复计算命中。
- 从全局搜索定位思考时，仍能打开正确消息与片段。全局索引继续读取聚合文字，位置元数据不进入索引或模型上下文。

正文复制和既有文本导出沿用聚合通道。结构化备份、对话复制及恢复必须完整保留位置，且恢复只重建展示，不重新请求模型或联网服务。

## 历史数据与发布

已经完成的历史工具任务只保存聚合思考和工具轮次，缺少可靠的位置；私有续接也已清理，无法精确补回。旧消息将联网信息合并到同一个思考区末尾，保留现有内容。新任务按真实位置穿插；不会平均分割旧思考或通过重新调用供应商来猜测顺序。

位置字段可缺省，属于同一公开工具结构的可选元数据：缺省表示没有顺序记录，存在则执行完整校验。生产运行时不扫描或改写历史消息，也不恢复在线迁移机制。沿用现有表即可，无需全库运维迁移；上线前让正在执行的工具任务完成，避免部署打断调用。若实施时发现必须调整 SQL 结构，另用本地运维工具和维护窗口处理。

## 验收清单

- 单次搜索：思考 A → 搜索 → 思考 B → 回答；读取网页同样生效。
- 多轮：搜索后继续思考，再读取网页；同轮并行调用、空思考轮次和相同位置都不乱序、不重复。
- 四种模型协议：OpenAI Chat、Responses、Anthropic、Gemini 均使用公开的思考位置；DeepSeek Flash 兼容流额外回归。私有签名、加密续接、密钥不进入公开状态、缓存或备份。
- 生命周期：等待、执行、空来源、部分工具失败、终止错误、取消、超时、中断及预算耗尽；已保存文字和位置可读，错误可定位。
- 同步：预览先于确认、重复包、旧轮迟到包、断线重连、工具期间换设备、无客户端后台完成；历史与实时顺序一致。
- 内容：中文、emoji、组合字符、CRLF、软换行、长思考、代码、列表、公式，以及轮次结束时未闭合 Markdown；正文内容不变。
- 交互：顶部／中部阅读不被拉到底部，底部正常跟随；整体折叠和来源展开状态稳定，键盘操作及失败定位可达；会话／全局搜索可定位分段及跨段命中。
- 数据：结构化备份、复制、恢复与分支切换保留顺序；手工编辑新版本不会带入与其思考文字不对应的位置；历史无位置记录仍可读，不触发外部请求。
- 资源：位置只在轮次边界增加，工具结果仍只有现有公开副本；SQL 写入与广播沿用既有事务，不增加逐 Token 持久化或后台调度压力。

实施验证采用现有模拟供应商和 Search／Fetch 测试服务，并执行相关单元、原生 workerd、Chromium／WebKit 回归、类型检查与构建。真实供应商计费验证按当次授权单独记录。
