# PDF 文本输入

阶段 4 第 4 项。聊天框「添加文件」可选择包含文字的 PDF；提取结果带页码，使用现有私有文本预览、文件问答、草稿、离线队列和上下文预算。可以只发送 PDF，不要求视觉模型；PDF 中的图片不进入模型。

## 客户端提取与边界

使用 Mozilla [PDF.js](https://mozilla.github.io/pdf.js/getting_started/) 的 `pdfjs-dist`，在独立浏览器 Worker 中读取本地文件；按页流式读取已有文字，不渲染页面、表单、注释或脚本。中文 CMap 和标准字体资源随应用构建，通过明确名称的资源映射加载；不上传 PDF 到第三方解析服务、不从公共 CDN 加载解析器或字体。PDF 解析模块仅在选择 PDF 时加载。

原文件仍最多 5 MiB，取消 50 页、64,000 码元与 128 KiB 的提取限制。逐页提取全文和页码索引，不静默截断。原文件与 UTF-8 提取文本共同计入每对话 32 MiB、每空间 512 MiB 的附件容量；超出真实存储预算明确拒绝。模块冷加载最多等待 30 秒；提取期间每次读取进展重置 30 秒停滞计时，不再用总时长拒绝持续正常提取的文件。超时或取消释放调用者并终止已创建的 Worker。切换对话、退出登录或取消上传也会终止当前提取。没有可提取文字、需要口令、损坏或不支持的 PDF 保留聊天草稿，不登记文件、不创建模型任务。

只提取 PDF 中已有文字，不处理扫描图像。字体编码、多栏、表格和排版可能影响文字与阅读顺序，不承诺视觉还原；复杂文件可以先重新导出或拆分。原文件仍可私有下载。

## 保存和任务

提取成功后，先保存原 PDF，再用小型 JSON 元数据行加 UTF-8 全文的原生流上传文本、页数／解析器版本及页码索引。普通 Worker 只转发流，DO 负责校验和保存，避免 1 MiB RPC 对象限制。服务端检查已完成原文件、所属对话、原始 SHA-256、提取文本编码、大小、长度及元数据范围；标准 UTF-8 文本保存到私有 R2，DO 只保存解析状态、哈希、长度、版本、页数、页码索引和引用。索引存入已有 PDF 元数据列，受 SQLite 单值字节边界保护；全文不写入 SQL。相同结果幂等复用，已绑定文件 ID 的不同文本或页数拒绝覆盖。

服务端不再运行 PDF 解析器，也不独立证明客户端声明的页数、阅读顺序或提取内容与 PDF 的语义一致。这些是同一登录用户提交的资料。哈希绑定用于固定原文件与提取结果，不能当作解析器执行的证明。

原文件及提取文本可靠保存并通过接受前校验后，才接受聊天任务。之后由 DO 读取固定文本引用，正文以普通文件资料发给四类协议；不依赖客户端继续在线，不把 PDF 二进制、公开 URL 或大块文字写入消息事件和任务上下文。开始模型调用前再次校验解析文本及原文件头元数据。已保存 PDF 可跨设备预览、刷新恢复草稿、离线排队及重新生成。

数量、近似 Tokens、历史／摘要、修改和引用删除规则复用[文本文件输入](documents.md)。每条消息最多 4 个文件，每次上下文最多 8 个；取消上下文 128,000 字符总上限，实际按模型窗口、输出预留及历史／系统提示词预算判断。近似值不能用于计费。5 MiB 源文件、实际存储预算、独立 Worker、停滞超时和取消仍是资源保护，不能保证任意复杂 PDF 的瞬时内存消耗。

## 选择发送范围

草稿中点击 PDF，可选择全文、页码（例如 `1-3, 5`）或在原文中选中片段。界面显示所选内容的近似 Tokens 和所选模型的剩余输入预算；可按容量自动选择能容纳的前几页。首页仍过大时提示选择片段，不截断该页。选择只改变本次发送内容，完整原文仍保留，可以重新选择。

消息引用保存所选范围、选区哈希／Tokens 及原文哈希／统计，不复制全文和页码索引。服务端根据已保存原文重新计算引用，接受任务前和调用模型前再次验证。相同原文件的不同选区分别参与供应商请求和预算；重新生成、修改历史提问保留原选区。草稿刷新、离线排队、独立复制和 ZIP 备份恢复均保留选区，复制与备份同时保留全文和页码索引。

没有页码索引的旧 PDF 仍可选原文片段，不在线补提取或迁移已有数据。

## 故障、删除与后续

解析结果 R2 写入前持久化认领和租约，结果未知时由 Alarm 清理派生对象及 PDF 元数据，保留已完成的原文件。明确重新提交提取结果后可重试保存，不自动调用模型。已被消息或活动任务使用时阻止独立删除；删除最后来源后清理原文件、提取对象和 PDF 元数据。页面关闭前未保存完成的提取不视为已接受，可能需要重新选择文件。

含 PDF 的对话已支持[独立附件复制](attachment-copies.md)和[ZIP 备份恢复](attachment-backups.md)，原文件、全文及选区引用独立保存。文本 JSON 导出要求改用 ZIP；文本导出保留文件名。Office 格式仍待验证托管解析服务。

参考 [PDF.js API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) 的本地数据输入、Worker、`stopAtErrors` 和资源加载参数，以及 [streamTextContent](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib-PDFPageProxy.html) 的按块读取接口。包的当前实现和类型是当前固定版本的运行依据；这些 API 不证明解析结果质量或 Cloudflare 费用。

## 验证

固定 `pdfjs-dist` 为 6.4.299。使用真实 PDF.js 浏览器 Worker、本地 DO／R2、供应商 SDK 与模拟响应验证完整提取、51 页／超过旧字符上限、超过 RPC 对象大小的全文存取、页码及片段选择、模型预算、跨设备预览、刷新草稿、复制和 ZIP 恢复。原有中文 CMap、损坏／空白／加密、不可变哈希绑定、模块／Worker 停滞超时、路由取消及未知写入租约清理回归继续保留。

这些本地测试不调用付费模型、不创建远程桶，也不证明任意 PDF 的提取质量或真实 Cloudflare CPU 与免费账单。
