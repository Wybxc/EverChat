# 图片输入

阶段 4 第 2 项：聊天框选择或粘贴 PNG、JPEG、WebP，预览、移除并发送给视觉模型。图片可以单独作为提问，用户消息修订和重新生成保留对应父链的引用。入口需要私有 R2 绑定；模型的图片能力沿用原生报告、内置目录和手动覆盖。不支持视觉的模型会在浏览器和云端明确拒绝，不会偷偷去掉图片继续回答。

## 上传与草稿

原图最多 5 MiB、2400 万像素。浏览器先检查文件头与尺寸，再完整解码、缩放最长边至最多 1536 像素，并编码为最多 1 MiB 的 WebP（编码不支持时保留浏览器的 PNG 输出）。这会改变原图、尺寸和可能的细节；保留原文件可使用独立的对话文件管理入口。每条消息最多 4 张图片，每次模型上下文最多 8 张、8 MiB，包含当前分支中选入的历史图片。

图片处理完成后先保存到私有 R2；上传进度到 100% 仍需等待持久化确认。新对话首次添加图片会创建云端对话及独立 URL，保留输入文字并将焦点放回聊天框。切换对话或退出登录会取消尚未完成的上传、清理新登记，不将结果放入另一个草稿。失败和取消不发送模型请求。

本地草稿与离线待发送队列仅保存图片元数据，页面刷新、切换对话后可以恢复。图片上传需要联网；已上传图片的消息可以离线排队，联网后沿用同一个请求 ID 发送。私有图片响应不进入 Service Worker 缓存；离线打开未缓存的图片显示不可用，联网后重新读取。移除草稿图片只移除引用，文件仍可从对话文件管理中删除。

## 云端任务与协议

`message_images`、消息 `parts` 和已接受任务上下文保存图片 ID、名称、MIME、大小和 SHA-256；R2 保存文件，浏览器缓存、事件和 SQL 不包含图片二进制或 base64。服务端接受任务前校验所属对话、上传状态、文件完整性、格式、尺寸、模型能力和预算，并固定引用。云端只进行有界读取和文件头／尺寸检查，不完整解码像素；直接调用文件上传 API 上传的坏像素仍可能被供应商拒绝。

执行时服务端重新从 R2 读取、核对校验和，通过 AI SDK 将字节编码进供应商请求，文件地址保持私有：

| 协议 | 原生图片部分 |
|---|---|
| OpenAI Chat Completions／兼容接口 | `image_url` 的 data URL |
| OpenAI Responses | `input_image` 的 data URL |
| Anthropic | `image.source` 的 base64 和 MIME |
| Gemini GenerateContent | `inlineData` 的 MIME 和 base64 |

依据：[OpenAI 图片输入](https://developers.openai.com/api/docs/guides/images-vision)、[Anthropic 视觉输入](https://platform.claude.com/docs/en/build-with-claude/vision)、[Gemini GenerateContent](https://ai.google.dev/api/generate-content)。已接受任务不再依赖浏览器继续在线；图片读取失败时结束任务，保留用户提问，不自动重新调用供应商。

图片每次出现在上下文中按 4,096 Tokens 预留规划额度，并在估算明细中显示。这是应用的保守额度，不是精确 tokenizer 或计费用量；实际成本以模型和供应商报告为准。摘要模型也必须支持视觉；覆盖后的历史摘要不再次携带已压缩图片，未压缩尾部仍保留原引用。

## 删除与后续范围

图片被任一消息或活动任务引用时拒绝单文件删除。删除相关消息会清除图片引用及旧事件，所有来源消息删除后文件可以独立删除；删除整个对话继续由 Library Alarm 清理全部 R2 对象。引用登记的令牌在接受前更新，删除在跨 DO 查询后再次检查，防止并发接受的图片被移除。

含图片的对话已支持[独立附件复制](attachment-copies.md)和[ZIP 备份恢复](attachment-backups.md)，副本拥有新的文件引用与私有 R2 键。文本 JSON 导出要求改用 ZIP；恢复缺少文件的图片备份直接拒绝。Markdown、TXT、HTML 导出保留图片名称占位，不伪造可跨空间读取的链接。

接受和执行各会读取一次选入的私有图片，预览也产生 R2 Class B 读取；图片问答和视觉摘要产生供应商费用。本地回归验证功能，不证明 Workers Free CPU、账户免费余量或实际识图质量。资源边界及私有桶部署见[对话文件](attachments.md)。
