# 界面语言与翻译维护

EverChat 使用 i18next、react-i18next 和原生 Intl。当前支持简体中文、English、跟随系统；入口为「设置 → 通用 → 语言」。语言按本机保存，多标签页同步，不发送到服务器，不改变对话、供应商名称、模型名称、草稿、提示词或 AI 输出。

## 添加界面文案

功能文案放在所属模块的 `locales/en.ts` 和 `locales/zh-CN.ts`；真正共享的操作放在 `src/platform/i18n/locales/*/common.ts`。英文定义资源类型；提交时必须同时提供两种翻译。

```ts
// locales/en.ts
export default {
  removeConfirmation: 'Delete “{{name}}”?',
  resultCount_one: '{{count}} result',
  resultCount_other: '{{count}} results',
} as const;

// locales/zh-CN.ts
export default {
  removeConfirmation: '删除「{{name}}」？',
  resultCount_other: '{{count}} 项结果',
} as const;
```

句子整体翻译，使用有语义的稳定 key。数量传 `count`，遵循各语言的复数类别。用户内容作为参数传入；不要把整句原文、用户名称或数组位置当作翻译 key。

功能的 `locales/index.ts` 在模块加载时调用 `registerTranslations`，同时注册两种语言。组件导入该模块并使用 `useTranslation('namespace', { useSuspense: false })` 和 selector，例如 `t(($) => $.removeConfirmation, { name })`。新增命名空间还要在 `src/platform/i18n/i18next.d.ts` 中增加 type-only 资源声明。不要在公共运行时静态导入所有功能词典；按需功能的两种语言随该功能代码加载，无额外词典请求。

普通函数可以用功能资源入口导出的固定 namespace translator。模块顶层的选项和状态只存 key，显示时翻译；不要永久保存模块初始化时的翻译结果。

## 异步提示与错误

React 状态、自动保存和待发送队列使用 `UiMessage`：通过 `uiMessage(namespace, key, values)` 创建，在 JSX 中调用 `renderUiMessage`。异步函数抛出 `UiError`，catch 使用 `errorMessage`。嵌套提示可以把另一个 `UiMessage` 作为参数传入；多个文件错误可以保留为消息数组。这样错误出现后切换语言也会更新。

后端和共享规则使用 `shared/errors/descriptor.ts` 的 `AppError`、`problem` 和 `issueOf`。API 返回 `issue: { code, params? }`；错误码与 UI key 的关联由受控的 errors 资源维护。`HttpError` 保留原有 HTTP 状态和鉴权／重试 code，语义 issue 单独传递。

新增错误时：

1. 在 `shared/errors/fallbacks.ts` 增加稳定业务码及英文 API 回退；英文 UI 复用这份回退，中文词条在 `src/platform/i18n/locales/zh-CN/errors.ts`。
2. 如需参数，在 descriptor 中显式声明允许的参数名。跨 API／存储边界仅允许经过校验、有界的数字；禁止传 API 密钥、提示词或原始请求。
3. 在错误发生处赋予 issue，重新包装异常时保留 `issueOf(error)`。不要通过原始错误文本或任意上游 code 动态查找翻译。
4. 生成失败的 issue 存在已有生成元数据 JSON 中，工具失败存在已有 outcome JSON 中，备份继续校验这些字段。已保存诊断保持原文；历史记录没有 issue 时显示对应任务的通用摘要，不扫描旧文本、不补写记录。

SQL 结构无需变化。标题等仅有一种失败语义的任务可按已有任务类型／终态显示摘要，保留原始 error 作为诊断。未来若需转换持久化格式，走本地运维迁移，禁止放入请求、DO 构造函数、Alarm、浏览器启动或 SW 激活流程。

## 格式与外部输出

数字、日期、时长使用 `src/platform/i18n/format.ts`。格式语言可以保留系统的区域偏好，例如资源用英文、日期用 en-GB。界面语言不能改变时区、UTC 额度周期、用量统计分桶、精确金额或排序。

导出在开始时固定 locale；CSV 的 ISO 时间和机器可读数字保持原格式。HTML 导出继续转义标题、正文和翻译参数。Markdown 控件通过 Streamdown 的 `translations` 接口配置。

匿名分享只加载公共入口及所需资源，不读取私有会话，不启动通知控制器，不把语言写进分享 URL 或密钥。分享正文、思考、代码、公式保持原文。

启动占位由 Vite 内嵌最小词条。Service Worker 使用独立 i18next 实例和最小 system 词条；私有页面把本机语言镜像到通知 IndexedDB 的独立键。语言切换不更新订阅 revision，不申请权限、不重新订阅。关闭页面后按保存的显式语言或 SW 系统语言决定通知文字。

## 检查

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:e2e tests/e2e/platform/i18n.spec.ts
pnpm test:pwa
```

单元测试检查语义 key、插值、复数、源码硬编码、实例隔离、错误参数和异步提示切换。浏览器回归检查草稿／URL／焦点、多标签页、窄屏、公开分享、流式内容及 PWA 通知。完整回归仍使用 `pnpm check`。

操作系统通知的真实投递与系统辅助技术朗读需要真机验收；自动化的 PushEvent／CDP 测试不代表真实推送网关或屏幕阅读器验收。
