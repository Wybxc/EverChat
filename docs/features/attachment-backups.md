# 含附件的对话备份与恢复

阶段 4 第 5 项的可恢复备份检查点。右上角「对话文件操作」中的「下载备份」生成 `.everchat.zip`；「导入备份」恢复为具有独立 URL、消息 ID、附件 ID 和私有 R2 键的新对话。浏览器 Worker 处理 ZIP 和完整性校验，主页面显示进度并允许取消。

## 存档内容

ZIP 使用 fflate 0.8.3 的未压缩格式，包含版本清单 `manifest.json`、`files/<附件 ID>` 原文件和 `documents/<附件 ID>.txt` 已保存提取文本。包含正文、供应商返回的思考内容、分支与修订关系、会话参数、模型信息、生成报告、历史摘要及提示词预设。捕获时已保存的全部文件都会进入存档，包括尚未用于消息或尚未解析的原文件；未完成上传不进入存档。

API 密钥、流式游标和后台执行状态不进入备份。生成中的回答只保留云端已保存前缀，并标记为未完成；恢复不自动重新调用模型。原文件和已保存的 TXT／CSV／PDF 解析资料独立保存并重映射引用，源对话删除后，恢复结果仍可在第二设备下载、预览和继续问答。

当前版本的无附件 JSON 备份仍可导入，支持 UTF-8 BOM 和 JSON 前导空白；服务端文本 JSON 导出遇到已保存文件会明确要求使用 ZIP，不输出无法恢复的附件引用。原型不提供旧版本迁移。

## 校验与私有访问

导入先在浏览器完整校验，再向服务端提交清单。仅接受完整、未加密、未压缩的当前 EverChat ZIP；拒绝重复／额外路径、缺少文件、隐藏前缀、截断、压缩数据及不匹配的头部。校验每个原文件和提取文本的长度与 SHA-256、UTF-8 文本、元数据和消息关系，禁止借存档读取外部 URL。清单不含可直接访问 R2 的地址。

导出、上传、预览和恢复 API 继续使用应用鉴权与同源写入检查；文件响应禁止缓存。服务端再次验证清单、文件字节和引用，TXT／CSV 按当前解析规则生成资料，PDF 恢复已保存并校验的提取文本，不重新执行客户端 PDF 解析。文件内容不写入 SQL 消息事件、快照或浏览器持久缓存。

## 发布、重试与中断

浏览器在发请求前将存档 SHA-256 绑定到随机恢复 ID。网络中断、响应丢失或等待超时后，重导同一存档沿用 ID；已完成请求直接返回同一对话，不重复写入文件。明确的初始化输入错误或已停止结果会清除标识，下一次主动尝试使用新 ID。切换页面保留当前 URL、草稿和焦点，退出后迟到响应不会重写本地状态。

Library 在 R2 写入前保存恢复登记、目标文件映射、认领和期限。文件、解析结果及消息全部保存后，才在同一 Library 事务更新配置、发布对话并登记搜索索引；发布前不能从公开对话 API、列表或搜索读取暂存内容。恢复配置只在供应商类型和端点相同的情况下保留空间已有密钥，类型／端点变化会清除旧密钥，默认模型选择重置。

文件上传阶段需要客户端继续发送字节。最终恢复一旦被服务端认领，由 DO `waitUntil` 执行，关闭页面后仍能完成；它不能保证实例故障后恢复同一次执行。[DO State](https://developers.cloudflare.com/durable-objects/api/state/) 实例重置后的未知写入、取消、目标删除、超时或错误会明确停止，未发布目标进入持久化删除与 Alarm 清理，不自动重复未知写入。清理失败 30 秒后重试，确认删除前保留容量预留；没有 R2 绑定时保留清理登记，重新绑定后继续，不持续空转。

## 原型资源边界

| 维度            | 限制                                               |
| --------------- | -------------------------------------------------- |
| ZIP 总大小      | 52.125 MiB                                         |
| 清单／文本 JSON | 12 MiB                                             |
| 供应商配置写入  | 12 MiB，经原生流交给 DO 校验                       |
| 原文件          | 每个最多 5 MiB；每对话 64 个／32 MiB               |
| 提取文本        | 每个最多 128 KiB／64,000 个 UTF-16 码元            |
| ZIP 条目        | 最多 129 项                                        |
| 恢复期限        | 上传阶段 10 分钟；认领最终恢复后另有 10 分钟       |
| 恢复登记        | 最多 1,000 项；开始新请求时回收超过 7 天的终态记录 |
| 并发            | 最多 2 项；含文件请求也计算尚未确认清理的清单      |

私有 R2 保存有界清单，每项最多 12 MiB，含文件恢复的未清理清单合计不超过 24 MiB；SQL 只保存登记和文件元数据。无文件恢复无需 R2，也不会被等待重新绑定的终态清理阻塞。原文件沿用每空间 512 个／512 MiB 和 UTC 每日 100 次写入尝试；含文件清单另占一次尝试。开始恢复前检查整批剩余额度，其他并发上传仍可能耗尽额度，届时停止并清理；失败不退还尝试。

大清单、消息、配置及返回快照使用原生 RPC 流，由 DO 解析，普通 Worker 不解析大历史 JSON。恢复事件按约 1 MB 分批写入同一事务。SQLite 单个字符串、BLOB 或行上限为 2 MB；单个供应商配置在保存前保留 1,024 字节余量并校验，不限制整份备份到该大小。供应商设置和会话模型列表也从 DO 返回原生响应，设置写入同样使用有界原生流，恢复后仍可编辑保存大配置。清单、配置和提取文本的单次请求读取另有 90 秒期限。[DO 限制](https://developers.cloudflare.com/durable-objects/platform/limits/)

恢复产生独立的容量占用及 R2／DO 读写操作。本地测试使用原生模拟 DO／R2、实际供应商 SDK 和模拟响应，没有部署、创建远程桶或调用付费模型，不证明真实 Cloudflare CPU 或免费账单。

## 验证

最终 `pnpm check` 通过：206 项单元测试、应用／Worker／工具类型检查、生产构建、完整 196 项浏览器测试及 2 项生产 PWA 测试；新增测试与模拟 Worker 的独立严格 TypeScript 检查、`git diff --check` 通过。

16 项附件备份浏览器场景覆盖混合附件的独立恢复、浏览器 ZIP 与第二设备、缺少资料及完整性拒绝、后台完成与同 ID 重试、并发／额度、R2 写入后重置／清理重试、期限／取消、超过 7.8 MB 的完整历史、超过 5 MB 的配置及恢复后的编辑保存、无消息但有文件的对话，以及未绑定 R2 时的文本恢复与清理休眠。现有备份场景也改为验证实际 ZIP 下载和重新导入。

初轮全量运行的两个失败分别来自测试注入的 DO 重置向 Vite 传播错误遮罩，以及 macOS 睡眠使流式测试超过期限；已在模拟路由处理预期重置，并在最终检查命令期间使用临时 `caffeinate`。最终完整重跑全部通过，没有改变产品超时策略或系统电源设置。
