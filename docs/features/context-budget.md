# 上下文预算与 Token 估算

阶段 3 第 2 项。当前输入包含系统提示词、当前分支的已完成正文（含供应商断流后保留为正式版本的部分回答）、可用历史摘要和本次用户输入；不会把思考通道、其他分支、已删除内容或未保留为正式版本的失败回答放入普通历史上下文。图片按每次出现 4,096 Tokens 的保守规划额度纳入当前输入和历史（不是精确计费值），并限制每次上下文最多 8 张。TXT／Markdown／代码／CSV 及 PDF 的解析内容按近似 Tokens 纳入同一预算，每次上下文最多 8 个，实际内容按模型 Token 预算判断；PDF 可先完整提取，再选择页码或片段；PDF 页码标记同样计入。[工具任务](../architecture/tool-workflow.md)另计 2,048 个工具定义预留 Token、前轮助手续接内容及已保存结果，超出固定预算时不登记下一次模型调用；协议必需的私有思考续接不进入公共历史。

## 会话配置

- `contextBudget`：可发送输入的 Token 预算，包含系统提示词、摘要、历史、本次输入与协议开销；留空按模型窗口。正整数，最大 10,000,000。自定义值不能扩大模型可用窗口。
- `recentMessages`：最多选取的历史消息条数，用户和助手各算一条，本次输入不计；留空只受预算约束，范围 1–1,000。两项同时设置时同时生效。
- 历史按最新的完整用户轮次选取，不裁剪单条正文，不以孤立助手回答开头。条数边界落在一问一答中间时，整个较早轮次省略。例如上限 3 条且每轮为 2 条消息，只选最近 2 条。
- 最近期轮次已装不下时，整个更早前缀也省略，不跳过较新信息去拼接不连续的更早历史。原始消息不删除；发送前显示省略条数，接受任务时固定实际输入及估算，终态「生成信息」仍可查看。
- 历史摘要：始终使用当前分支已完成的有效历史摘要。摘要作为历史资料计入固定预算，其覆盖前缀不再重复发送，最近消息条数限制只作用于未覆盖的原始历史。摘要本身无法装下时阻止发送，不静默丢弃。详见 [历史摘要](history-summaries.md)。
- `autoCompression`：默认关闭；开启会额外调用摘要模型。阈值为输入预算的 50–95%（默认 80%），可选择摘要模型或使用本次聊天模型；以摘要及完整未覆盖父链估算触发，不受原文尾部条数限制提前裁剪。完整摘要先持久化，再计算和保存回答上下文；失败不调用回答模型或自动重试。关闭自动压缩不影响已完成摘要的使用。

配置使用已有会话自动保存、同步、离线草稿、复制和备份机制。编辑消息从原消息父链估算；重新生成使用原提问及其父链；复制到用户提问为止的会话续聊包含末尾用户消息。云端重新解析供应商配置并构建最终上下文，不接受客户端提交的 Token 计数或筛选后的历史作为依据。

## 窗口与输出预留

设窗口为 `W`，估算余量为 `ceil(W × 10%)`。

- 输入与输出共享窗口：可用输入为 `max(0, W − 余量 − 输出预留)`。
- 供应商明确报告独立输入容量：可用输入为 `max(0, W − 余量)`，输出容量独立检查，不重复扣减。
- 已设置请求输出上限时，输出预留使用该值；未设置时使用 `min(模型最大输出, floor(W / 4))`。这只是计划空间，**不会在请求中设置输出上限，也不承诺模型最多输出该数量**。
- 未识别窗口使用已有 32,768 回退、8,192 输出预留，余量 3,277，可用输入 21,299，界面明确提示「窗口未识别」。可在模型设置中覆盖真实窗口。
- 自定义会话预算与可用输入取较小值。系统提示词、本次输入及消息封装已超过预算时，浏览器保留草稿和 URL；云端也在创建消息、任务或调用模型之前拒绝。已接受任务不随后续参数或模型目录编辑改变。

## 有界近似估算

使用同一份无 Node API、无网络依赖的 `shared/conversation/context-budget.ts`，在浏览器和 Workers 中运行，所有计数标为近似值。当前为通用文本估算，**不是精确 tokenizer，不用于计算账单，也不保证上游一定接受请求**。供应商 tokenizer、消息封装和额外内部 Token 可造成误差；10% 余量只是原型的规划策略。

ASCII 字母、数字和空白按每字符约 1/3 Token，ASCII 标点按 1，其他 BMP 字符按 2，代理码元按 1.5（完整补充字符为 3）；按总权重向上取整。超过 256 个 UTF-16 码元的文本，分布采样 16 段、每段 16 个码元，按长度投影。该权重是 EverChat 的偏保守近似策略，不是供应商公布的编码规则。混合文本及特殊词汇仍可能低估，重复文本可能明显高估。

每段文本至多读取 256 个码元，历史受已有 1,000 条和 4 MiB 接受任务边界约束。客户端复用历史对象的弱引用计数缓存，文本变动会失效；只在草稿、模型、分支或参数变化时重算，不做逐 Token 数据库写入或高频计数 API 请求。单条消息额外预估 8 Tokens，请求额外预估 3，系统提示词非空时也计入封装。

当前四类协议与任意兼容端点没有统一可靠的离线精确编码表，因此此次先提供明确标注的通用估算。将来加入模型专属 tokenizer 时须核对实际模型、设计算量边界，保留未知模型的近似回退；不能把某个 OpenAI tokenizer 的结果冒充 Claude、Gemini 或自定义兼容模型的精确计数。

依据：[Gemini Token 定义与 countTokens](https://ai.google.dev/gemini-api/docs/tokens) 说明 Token 可是字符、单词或片段，并提供请求输入计数接口；[Claude Token counting](https://platform.claude.com/docs/en/build-with-claude/token-counting) 说明计数依赖实际模型、封装，计数接口结果也可能与最终消耗略有差异。上述事实支持把本地通用计数标为近似，不证明本原型权重精确。[Chatbox 的估算流程](https://github.com/chatboxai/chatbox/blob/main/docs/token-estimation.md) 使用模型对应 tokenizer，并对长文本计算和近似回退标记设边界；EverChat 当前不引入其桌面持久化队列。

## 此检查点的边界

预算替换原来的 40 条／80,000 字静默截断；小窗口会明确省略历史，大窗口可带入更多原文。手动和可关闭的自动摘要纳入同一预算，提供分支覆盖边界、查看和重新生成；自动压缩失败或仍无法装下原文尾部时明确停止，不循环调用模型。模型生成的摘要可能遗漏信息，保留原始消息不等于保证摘要无损。

## 供应商断流后的回答

普通回答已有非空正文时，供应商提前结束流、流内报错或连接异常，会在保存可解析尾部后将该条回答封存为正式版本（`status: completed`、`generation.interrupted: true`）。后续提问以它为父消息，按照同一上下文预算携带这条正文；思考通道仍不作为普通历史发送。页面保留中断提示与脱敏诊断，刷新、复制、备份和恢复保留此状态。

模型调用的用量与执行结果仍按实际失败记录，不发送「回答已完成」通知，也不把它当作成功回答触发自动标题。只有思考而无正文的失败、摘要失败、主动停止及无法可靠持久化的失败继续沿用原有处理。新增字段保存在既有 JSON 中，不改 SQL、不回填旧记录。
